# views — 只讀聚合與介面快照

本目錄把磁碟上的 Markdown 與工程狀態聚合成上層介面需要的只讀資料，**不寫盤**：

- `projectView.ts`：工程樹（「故事架構」六行、章節列表——**一個章號一行**，細綱與正文是同一行的兩面，每行帶它在哪一卷（章節根下的一級目錄，`quickOpen.ts` 的 `volumeOf` 取第一段）；分卷 `volumes`（2026-10-23）按卷裡最小的章號排、空卷殿後、根下的章是「未分卷」，「新章落這裡」那一卷與 `subdirForNewChapter` 同源；角色/設定是目錄樹；「敘事線」頁籤那一列由 `threads.ts` 算，交進去的是定稿到的最後一章、定稿過的章號與 manifest 裡敘事線判到哪）、細綱浮窗（`buildPlotSummaryView`：沒定稿的標「計劃」，定稿後正文又改過的標過期）與單章流水線檢視；章的說法（「第 12 章《夜訪》」）由這一層給，前端只渲染。
- `threads.ts`：敘事線一覽（敘事線重做第 8 個提交）：工程頁「敘事線」頁籤一條線一行——按主線 → 支線 → 感情線 → 人物線、同種類最近推進的在前（沒推進過的排最後、按計劃開始的章），一行寫「種類 · 狀態 · 最近第 N 章（沒推進過寫計劃區間）· 幾條伏筆沒收」，另給 ⚠（斷了幾章、幾條伏筆逾期、過了計劃收束的第幾章；收束了的線不報）與懸停看的意圖、當前進度；最後是「未歸屬的伏筆 · N 條」（一條都沒有不給）。**純函式**：吃 `projectView.ts` 那一趟 `readThreads()` 讀到的整本、定稿到的最後一章（`current`）與敘事線判到哪（四期的 `ThreadsProgress`：manifest 的水位與定稿過的章號），狀態現算、不落盤（第 18、28 條），文案只在這裡寫一份。**兩個「到哪」**（四期）：定稿到（`current`）與敘事線判到（`through`：水位，不超過定稿到）；⚑ 線的狀態（斷了幾章、伏筆逾期、過了計劃收束章）按敘事線判到算——定稿了還沒判的章上線裡本來就沒有事件；還有這樣的章時給 `lag`（「第 31–60 章還沒判」，工程頁那一句與「從正文補記」按它）。**三期的「敘事線總覽」**（編輯區裡的特殊標籤，章 × 線的時間軸）也從這裡出資料：`buildThreadsOverview(project)` 按需要（`requestThreadsOverview`，不進工程樹）讀一遍敘事線目錄與章節、細綱兩份列表（借快取，不讀一章正文），交給純函式 `buildThreadsMatrix`——列是第 1 章到「計劃或已寫的最後一章」（有細綱或正文的章、任何事件、伏筆計劃埋與收的章、線的計劃區間都算；中間沒檔案的補 `none`、卷名沿用前一章；手誤寫出的遠章號截在 `OVERVIEW_MAX_CHAPTERS` 並說原本到第幾章），帶卷名（`quickOpen.ts` 的 `volumeOf`）與四種定稿狀態；行按種類分組、組裡的先後與一行的說法與工程頁一字不差（同一個 `lineOf` / `compareLines`），每條線下面是它的伏筆，最後是「未歸屬的伏筆」；格子只給有事件的章，偏差（計劃了、那一章定稿了、敘事線也判過了卻沒發生；四期起還沒判的列標 `unjudged`、上面的計劃不算偏差）與伏筆的連線（收了實線、埋了沒收虛線到回收章——伏筆那一行寫的與計劃裡收它的取晚的、逾期延到現在——、還沒埋按計劃淡虛線）都在這裡算好，前端只畫。「定稿到」「敘事線判到」（總覽另畫一條虛豎線）與工程頁同一個口徑。二期加了寫前檢查要的數：`ThreadsView.watch`（`threadWatch`，按現在算，前端批次寫章彈窗拿它算提醒）與讀盤的 `threadReminders(project, nos)`（敘事線目錄 + 敘事線判到第幾章，按第一章 `asOf`；工作臺、對話頁與批次寫章的確認框用它，「還沒記上」的那幾章按判到哪注）。故事時間（2026-10-24；同日重做）：頁籤裡單獨一組「時間線」（`TimelineGroupView`，排在敘事線組前面；那一半的程式碼在 `timeline.ts`）。敘事線總覽的列上只留一句「這一章是哪天」（懸停用），原來的「時間線」一組與月份帶挪去時間線總覽。
- `timeline.ts`：故事時間的兩處介面（2026-10-24，從 `threads.ts` 挪出來）。**工程頁「時間線」組**（`timelineGroupOf`，經 `buildThreadsView` 進 `ProjectTree.threads.timeline`）：標題寫推到第幾章、故事第幾天（現在是哪天、結尾時段），曆法與起點給組標題的懸停（同日去掉了組裡那一行），沒填起點有建議、起點認不出的各成一條 ⚠（`start: true`），對賬一條一行（`timelineIssues` 加上推不出、認不出、還沒推，帶章號的點了在總覽裡展開那一章），章按月分段（沒起點按卷、卷也沒有每 20 章）一章一行（那一天不帶年份、比上一章、依據 / 你定的 / 正文寫明，改時間要的現值、是不是機器寫的）。**時間線總覽**（`buildTimelineMatrix`，編輯區裡的特殊標籤，按需要：讀盤那一半是 `threads.ts` 的 `buildTimelineOverview`，和敘事線總覽共用讀章節那一段）：按故事日子從早到晚一個日子一項（往回跳的章排到它那一天），同一天的幾章按章號、回憶的章掛在閱讀順序上前一章那一天裡；卡片帶時段、比上一章、依據、結尾是第幾天（前端算「N 天后」），這一章在各條線上**實際**發生的事（線按種類與目錄裡的先後，前 8 條各一色、不迴圈），沒有事件時給細綱梗概，詳情給全稱、歷時、正文寫明的日子、季節、細綱的時間地點；時間線寫到的最後一章之後還沒推的章不上軸。都從時間線現算（`computeTimeline`），不調模型、不落盤。設計見 [docs/design/plans/2026-10-24-timeline-page.md](../../../docs/design/plans/2026-10-24-timeline-page.md)。
- `pipeline.ts`：讀取大綱、配置、細綱與章節，**一個章號一行**（正文按章號認，細綱**按路徑配對**：正文映象的那一份，還沒有正文的按號認計劃，規則在 `NovelProject.plotFor`），彙總每一章的流水線狀態與新鮮度鏈；給全書狀態機取數（`buildBookFacts`，主按鈕、工程頁、agent 三處共用）；算正文的落點（`chapterTargetOf`：已有正文就是它，否則落在細綱所在的子目錄，連細綱都沒有就跟上一章同一個子目錄）；
- `workbench.ts`：讀取當前創作目標，構造「當前產物」浮窗的內容（單條設定目標攤一句話、各節與暗設；還只有一句話的不攤空節，提示 `/展开`；正文目標上還沒寫的這一章細綱點名、卻還只有一句話的設定給一句 `notice`——寫前提醒，完善設定三期，`thinLoreFor`，零呼叫、不攔，與上游變過的 `warning` 分開；「設定」一節空著、已經寫了字的章不讀設定區；敘事線的三類提醒——伏筆逾期、計劃埋了卻沒埋、線斷了，敘事線二期（第三類是復跑之後加的），`threads.ts` 的 `threadReminders`——同一個口徑，還沒寫的章才提，與它並在同一句 `notice` 裡）；
- `cast.ts`：從各章**定稿過的**細綱（有 `sourceHash`）反向聚合出場人物索引（第 14 條）。沒定稿的細綱裡寫的是計劃出場，不算。
- `quickOpen.ts`：「轉到…」（獨立版 Ctrl+P）要的索引——章節（一個章號一條：章號、標題、卷目錄、正文 / 細綱路徑、字數）、角色卡（名字與別名）、設定、架構幾件與大綱 / 文風 / 敘事線 / 全文大綱（有檔案的；稱呼與 `editorLabel.ts` 共用 `SETTING_DOC_LABEL` / `FIXED_DOC_LABEL`）、草稿。按需要（`requestQuickOpen`），不進工程樹；章節與細綱借 `listChapters()` / `listPlots()` 的快取，不為它多讀一章（讀了哪些盤寫在檔案頭上）。
- `nameIndex.ts`：內建編輯器「名詞補全」（獨立版 Alt+/ 與邊打邊彈）的名詞表——角色卡（名字、別名與名字裡括號內外各一截，一個字的不要；一句話取「身份」第一句，沒寫取標籤）、設定條目（標題、關鍵詞、分類即目錄、`loreBrief`）、設定名錄裡出現過還沒建條目的名字（`lore.ts` 的 `unknown`：建議分類、最近一章的說明）。**不調模型**。按需要（`requestNameIndex`），前端帶著手上那份的指紋（`have`）來，對得上只回指紋（`nameIndexSig`，controller 比）。讀盤：卡與條目按「路徑 · 大小 · 修改時間」的簽名記在記憶體裡（按工程例項），沒變一份都不讀，變了才整份重讀（與 `listCharacters` / `listLore` 同一個解析）；未建條目借 `listPlots()` / `listChapters()` 的快取、關掉名錄的「待整合」那一步（`buildLoreIndex(…, { pending: false })`）。
- `bookFind.ts`：全書查詢（獨立版「編輯 → 全書查詢替換…」，`bookFind` 訊息，**只讀**）：按範圍（正文、細綱、草稿、角色卡、設定條目、其他創作檔案，`model/bookFindScope.ts`）列檔案——正文與細綱借 `listChapters()` / `listPlots()` 的快取、按章號，草稿 / 角色卡 / 設定只列不讀——再逐份讀一次、匹配（口徑 `model/bookFind.ts` 的 `fileHits`：`textFind` 去掉護住的字），給出按檔案分組的結果：稱呼（`editorLabel.ts` 的短標記 + 麵包屑最後一段）、讀到時的 hash（替換時的樂觀鎖）、一共幾處、每一處的行列與那一行上下文，預覽時帶換成什麼。列滿 `BOOK_FIND_LIMIT`（1000）處就停、說停在哪一份上；在兩份檔案之間看一眼叫停；超過 2 MB 的跳過並列出來。不建索引、不快取內容（讀了哪些盤寫在檔案頭上）。替換在 `features/bookReplace.ts`。
- `chapterIndex.ts`：內建編輯器的章節索引（`chapterIndex` 訊息：章節條與上一章 / 下一章要的那幾個欄位）。與工程樹章節那一行**同一個函式投影**（`projectView.ts` 在它上面再加定稿、草稿、⟳），資料是 controller 構建 `ViewState` 時本來就跑的那一趟流水線索引，不多讀盤；controller 只在內容變了時推。
- `checkTerms.ts`：內建編輯器「寫作體檢」的詞表（`checkTerms` 訊息）：禁用詞（`readBannedTerms`——`style.md` 的「禁用詞表」、小說配置「全域要求」、`config.md` 的型別 / 子型別交給 `model/manuscriptCheck.ts` 的 `bannedTerms`；**寫正文的 `generation/generate.ts` 的 `planWriting` 也調它**，兩邊同一個函式、同一份輸入）+ 自定義敏感詞表（`.novelwarden/sensitive.txt`，`model/sensitiveWords.ts` 解析，壞行帶行號）。讀 `style.md` 與 `sensitive.txt` 各一次，`config.md` 由呼叫方給（controller 構建 `ViewState` 那一趟已經讀過）；讀不到當沒有、絕不拋。controller 每次 `pushState` 都調、內容變了才推（`controller/check.ts`）。
- `editorLabel.ts`：內建編輯器怎麼稱呼一份檔案（標籤上的型別短標記與名字、工具欄麵包屑），按 `kindOfPath` 與章節 / 細綱的檔名規則算，純函式、零 I/O、絕不拋（輸入是前端傳上來的路徑）。標題取檔名裡的那一段，不讀 H1。固定檔案的中文稱呼（`FIXED_DOC_LABEL`）與「轉到…」的索引共用。
- `lore.ts`：設定名錄（2026-10-18）。同一個路子：從定稿過的細綱**「設定」一節**聚合出已建條目（出現章、水位之後待整合的新事實——「設定」一節冒號後那句與提到它的連續性事實，工程頁的 `＋N`；認「提到」按最長匹配，2026-10-25：落在別人更長的名字裡——別的條目、名錄裡記著還沒建條目的——不算，「幻池秘境」的事不掛到上位概念「秘境」名下）、**未建條目**（出現過、沒有條目的名字，按出現章數排，分類取多數票）、**還沒記過設定的定稿章**（「設定」一節標題不在的，補記用）。認條目先標題後關鍵詞，人名不算。工程頁重新整理時由 `projectView.ts` 把已讀的細綱、條目、角色卡傳進來，同一次重新整理裡一個檔案只讀一次；裝配器的 `lore` 層也用它算尾巴。只要出現章與未建條目的呼叫方（名詞補全的 `nameIndex.ts`）傳 `{ pending: false }`，跳過「待整合」那一步——它要拿每一章的連續性事實去對每一條條目，幾百章 × 幾百條時是這裡最貴的一段。**待完善**（`thin`，完善設定 2026-10-19，傳 `{ thin: true }` 才算，只有工程樹要）：名錄裡唯一往前看的一塊——沒定稿、也還沒寫正文（沒有章節檔案或 0 字）的細綱「設定」一節點名的設定裡，還沒有條目的、條目還只有一句話的（`loreThin`：空的、新建設定的佔位、三節全是「（未交代）」）；每個名字給分類（有條目取所在目錄，沒有取「設定」一節多數票）、條目路徑、哪一種、要用到的章，按最早那一章升序。複用已經讀進來的細綱、章節與條目，不多讀盤。`projectView.ts` 把它放進工程樹的 `loreThin`（一行的說明「第 12 章起要用 · 只有一句話」由這一層給）。條目裡有作者的字的（三節全是「（未交代）」卻沒蓋過機器的章、明面空著只寫了暗設，`loreMaterial.ts` 的 `loreBatchExpandable` 不認的）標 `authored`：「全部展開」跳過它（三期）。寫前提醒要的「這幾章要用的」是 `thinLoreFor(project, nos)`：就是待完善裡要用到這幾章的那幾條，口徑一字不差，章號只留這幾章的。
- `loreMaterial.ts`：一條設定的原料（完善設定，2026-10-19；從 `features/lore.ts` 挪過來，行為不變）：定稿細綱裡關於它的全部記錄（`recordsAbout`，建條目、整合、展開共用）、整合 / 展開寫完水位記到第幾章（`integrationWatermark`：第一處沒定稿或定稿後正文又改過的章之前）、給模型的記錄封頂 `MATERIAL_TOKENS`；展開要的兩樣原料 `expansionMaterial`——沒定稿的細綱裡用到它的地方（「設定」一節點名它的那一行，按名錄同一張表認；梗概、關鍵事件裡提到它的句子，帶章號）與定稿過的記錄；`loreEntryAt` 認路徑上的那一條條目，檔案還不在時按路徑拼一條空的；條目正文是不是機器寫的（`loreOwnedByMachine`，三期從 `features/lore.ts` 挪過來）與批次展開會不會寫它（`loreBatchExpandable`：還只有一句話，而且空的、佔位的、機器寫的才寫；三節全是「（未交代）」沒蓋章的、寫過暗設的都算作者的）。純讀盤、不調模型；裝配器（context/ 不依賴 features/）、名錄、落盤與 `features/lore.ts` 共用。

新鮮度鏈：這一章細綱的梗概（就是情節大綱裡第 N 章那一條——大綱是各章梗概的彙總）→（`upstreamHash`）同一份細綱的其餘幾節 →
（`writtenFrom`，記在細綱上，定稿時重新整理）`chapters/…/N-标题` →（`sourceHash`，定稿時記）同一份
細綱（`summaries/` 下與正文同樣的相對路徑），全靠比對 hash，零模型呼叫。細綱內容與 `writtenFrom` 對不上，正文掛 ⟳
（包括定稿之後又改細綱）；`sourceHash` 與正文對不上，這一章回到待定稿。

`chapters/` 是正文的**唯一真相**：`deriveStage` 先看這一章有沒有字，有字就不再退回
「寫細綱」。所以只有 `chapters/`、一份細綱都沒有的老工程，每一章是「待定稿」或
「已完成」，不會被倒回去要求補細綱；它們缺的是架構，全書狀態機會先推那一格。

`pipeline.ts` 是 I/O 聚合器；[`../model/pipeline.ts`](../model/pipeline.ts) 仍是零 I/O、零 import
的純領域模型和狀態機。不要把後者遷入 `views/`，也不要在 `views/pipeline.ts` 裡複製狀態判斷。

## 一行同時代表一章的兩面

`buildPipelineIndex` 返回的是 `Map<章號, PlotPipeline>`：細綱（`summaries/` 下，遞迴）與成品（`chapters/`）
各掃一遍，一個章號一條。兩邊都可能缺席——只有細綱是「還沒寫完的章」，只有成品是
「老工程裡已經寫好的章」，都有是正常情況。行按章號建，但細綱與正文**按路徑配對**：有正文的章
只認正文映象的那份細綱（作者在外面給正文改了名，舊細綱不冒認，這一章就是還沒有細綱）；同號的正文
有兩份時認路徑排序第一份並記 warn。

## 讀盤只讀一次

工程樹、流水線狀態、出場索引要的是**同一批檔案**，而 `buildProjectTree` 由檔案監聽觸發
（兩個殼各去抖 250ms）——**作者每存一次盤就跑一次**。三處各讀各的，一次重新整理就把每一章的
細綱讀好幾遍。

所以這裡的規矩是：**同一次重新整理裡，一個檔案只讀一次**。批次入口
（`buildPipelineIndex`）負責把大綱、配置、manifest 與細綱、章節兩份列表讀出來，經 `context`
引數與返回值往下攤（出場索引 `buildCastIndex(project, plots)` 直接吃它的細綱列表）；
單章入口不傳就自己讀，行為不變。兩份列表本身則由 `NovelProject.listPlots()` /
`listChapters()` 各自快取（同構，含在途 promise 與世代號）。新增取數方時接著攤這一份，
不要再開一條讀盤路徑——`tests/integration/views/projectTreeReads.test.js` 會把重複讀盤的
檔名打出來。
