# media — 前端資源

面板的全部前端程式碼，兩個形態共用。外掛形態由 [../src/shells/vscode/webviewHtml.ts](../src/shells/vscode/webviewHtml.ts) 生成 HTML 載入（側邊欄 / 編輯器標籤頁），獨立形態由 [../src/shells/standalone/page.ts](../src/shells/standalone/page.ts) 載入。兩份頁面的 pane 結構來自同一處：[../src/shells/shared/panes.ts](../src/shells/shared/panes.ts)。

## 倉庫裡只有原始碼，產物在 `dist/media/`

`media/` 下入庫的只有 `src/`（TypeScript 與 CSS 片段）、`icon.svg` 與本檔案。`view.js` / `editor.js` / `explorer.js` / `bridge.js` / `view.css` / `standalone.css` 由 [`../scripts/build-media.js`](../scripts/build-media.js) 生成到 **`dist/media/`**——和 `dist/extension.js` 同一個去處，整個 `dist/` 都不入庫。

```
npm run media          # 構建一次（→ dist/media/）
npm run compile        # 連同擴充套件主體一起構建（F5 除錯前跑這個）
npm run watch          # 監聽重建
npm run typecheck      # 含 media/tsconfig.json，前端與協議對不上會報錯
```

`embed-media.js`、`standalone`、`dist` 都會先跑一次構建，所以克隆下來直接 `npm run standalone` 不會撞上「找不到 view.js」。**沒跑過構建就按 F5，webview 會 404 一片白**——兩個宿主的 `localResourceRoots` 裡現在有 `dist/media/`，那兒空著就什麼都載入不到。

產物是 IIFE 格式的 classic script，不是 ES module：webview 的 CSP 用 nonce 放行指令碼，而 nonce 不傳遞給 `import` 進來的模組——原生模組要麼得開 `strict-dynamic`，要麼就打包，這裡選打包。順帶 jsdom 的 `window.eval` 也只吃得下 classic script。

獨立版的 `/media/*` 是**路由名不是路徑**：位元組全部來自 `embed-media.js` 內嵌進 `mediaAssets.ts` 的表，URL 不必跟著產物目錄改。

## 型別是真的會被檢查的

`src/protocol.ts` 用 `import type` 直接從 [../src/core/protocol/](../src/core/protocol/index.ts) 轉出 `InMessage` / `OutMessage` 等全部型別（只有型別跨過這條邊界，一行執行時程式碼都不會被打包進來）。**改協議後端加了欄位、改了名字，前端對不上會直接編譯不過**——這以前只是一句「記得同時改 view.js」的註釋約定。

## 關鍵約定

- **前端無狀態**：一切資料來自 `ViewState` / `ProjectTree` 全量推送，前端只保留 UI 狀態（草稿、展開/摺疊、正在編輯的回覆）。webview 銷燬重建後一條 `ready` 就能完整恢復。
- **輸入框旁那三個下拉框各歸各的真相**（`view/composer.ts` + `view/state.ts`）：**模型**是全域設定（`ViewState.model`，選一下等於把它提到預設模型列表首位），**思考深度**與**當前章**是**會話的屬性**（`SerializedSession.thinking` / `.target`）。所以思考深度的 change 只 `postMessage({type:'setThinking'})`、不改本地狀態——值由回來的那條 `session` 訊息回填（`syncThinkingSelect`）。五個檔位的說法直接打包後端那份零 import 的 `model/thinking.ts`，介面上寫的和跑起來的必然一致。
- **進度與日誌各有一條推送路徑**：長任務用 `tasks`（**全量替換**，列表最多兩三項，增量協議不值得），日誌用 `log`（增量一條）+ `logs`（全量，切到日誌頁或清空後）+ `logHistory`（**只有點「載入更早」才發**，那是唯一會查工程庫的路徑，預設進日誌頁零開銷）。兩者都在 `resendFullState` 裡補推，重新整理頁面時正在跑的任務不會憑空消失。
  - **任務條在頁頭**（W8，四期）：`#taskList` 由 `shells/shared/panes.ts` 的 `taskBar()` 給出，外掛放在標籤欄下、獨立版放在側欄頂上——所有頁籤都看得見，從對話頁點的定稿、批次不會跑起來就沒了影。`pausable` 的任務多一顆「寫完這一章就停」（發 `stopAfterItem`），點過換成一句說明。任務說完那一句時後端推 `taskDone`，`view/toast.ts` 出一條帶按鈕的提示（「開啟第 3 章」發 `openChapter`；批次寫完即審稿是「開啟審稿報告」，發 `openSession`，五期補遺 §4），多留一會兒。
  - **計時由前端自己走**（`view/tasks.ts`）：後端只在有進度時才推快照，一次模型呼叫能安靜一分鐘，那期間計時停住會讓人以為卡死。收到快照時記下 `Date.now() - elapsedMs` 當基線，之後每秒**只改計時文字**——重建 DOM 會打斷「停止」按鈕上的點選。
  - **日誌增量不重畫整表**（`view/logs.ts`）：長任務每秒好幾條，重畫會讓滾動位置亂跳。只在原本就貼著底時才跟著滾，使用者翻上去看東西時不該被拽回來。
  - **對話頁流式輸出同樣只在貼著底才跟滾**（`view/messages.ts` 的 `scrollToBottom`）：每來一段 delta / 思考 / 工具行都會調它，翻上去看前面的氣泡時不該被拽回底部。切會話與主動傳送仍強制貼底。`.messages` 關掉了瀏覽器預設的 `overflow-anchor`，避免末氣泡變高時視口自己挪。
- **工程頁分五個頁籤**（`view/project/tabs.ts`，2026-10-20）：概覽（定稿進度橫幅、「故事架構」「文風與摘要」）/ 章節 / 角色（連同「出場人物 · 未建卡」）/ 設定（連同「待完善」「出現過 · 未建條目」）/ 敘事線（敘事線重做第 8 個提交，排在設定後面）。五頁的內容**每次都全畫**，各自裝進 `#projectBody` 裡一塊 `.project-panel[data-project-panel]`，切頁籤只換哪一塊露出來（`hidden`）——不重畫、不往後端要資料，分組的右鍵選單與三隻浮窗掛在 `#projectBody` 上的事件委託都不必知道有頁籤；按 `#projectBody .group` 找分組的老程式碼與測試照舊找得到。當前頁籤只在前端、重推樹不換頁（`buildPanel` 按當前頁籤建塊）；五頁共用 `#projectBody` 這一個滾動容器（它不隨重畫換掉，重推樹時滾動位置才留得住），各頁滾到哪由 `tabs.ts` 記，切走時記、切回來放回去。頁籤條 `#projectTabs` 在 `panes.ts` 裡，上面除了五個頁籤只有「重新整理」——從前那五顆按鈕（補齊架構、拆細綱、批次寫章、＋ 角色卡、＋ 設定）在分組右鍵裡都有，拿掉了；作品名與「N 章 · M 萬字」那一塊也拿掉了（字數在「章節」組標題上）。每頁的主分組（章節 / 角色 / 設定 / 敘事線）`buildGroup` 時傳 `panel`：分組下面的空白處右鍵也給這一組的選單（`.project-panel` 撐滿可見高度）。「故事架構」裡點已填的角色圖譜 / 設定清單切到對應頁籤（`rows.ts` 的 `revealGroup`）。
- **「敘事線」頁籤**（`view/project/threads.ts`）：兩組。「時間線」組在上（故事時間，2026-10-24 重做；同日時間線總覽改過點法）：曆法與起點在組標題的懸停裡（`buildGroup` 的 `tip`），改走右鍵（組標題、空白處「改曆法與起點…」；沒填起點有建議、起點認不出的各成一條 ⚠，右鍵「填為起點」）；對賬一條一行（`.timeline-issue`），章按月分段（段頭 `.row-timeline-segment` 點了摺疊，最後一段預設展開、其餘收起，摺疊記在 `treeState.ts` 的 `timelineFolds`），一章一行（`.row-time-chapter.time-<state>`；右鍵改時間、重推這一章、從這一章起重推、開啟這一章）。**點一章、點帶章號的 ⚠ 開啟時間線總覽、展開那一章**（`nf-timeline-command`，不開啟正文）；外掛形態沒有時間線總覽（`nf-timeline-query` 沒人回答），點了開啟時間線檔案。標題旁「補推時間」「重推」（補推、重推有一樣在跑時都不給）「總覽」（開啟時間線總覽，外掛形態不給）。「敘事線」組：一條線一行，最後一行「未歸屬的伏筆 · N 條」；一行的說法、排序與 ⚠（斷了幾章、伏筆逾期、過了計劃收束章）都由後端給（`core/views/threads.ts`，`ProjectTree.threads`），前端只渲染、只在每一句前加 ⚠。點一行開啟那條線的檔案，右鍵「開啟」（沒有刪除改名：一條線就是一份 Markdown，作者直接改），進行中的線另有「標為收束…」「標為放棄…」、計劃中的只有放棄（發 `closeThread` / `abandonThread`，後端先問）。失敗的 ❗ 掛在對應的行上（當前進度作者改過的黃 ❗ 在那條線的檔案上）；排線失敗掛在敘事線目錄上，沒有對應的行，放在組標題旁、「從大綱排出 / 從大綱補充」前面——組標題只管摺疊，這兩樣走 `buildGroup` 的 `head`（與「設定」組的篩選框同一個位置）。從前「文風與摘要」組裡那一行計數刪了。**「總覽」也在標題旁**（敘事線重做三期）、組標題右鍵「開啟敘事線總覽」、一行右鍵「在總覽裡看」：經 `nf-threads-command` 開啟編輯區裡的「敘事線總覽」標籤（見下面「敘事線總覽」）。**能力探測**：先 `queryThreadsOverview()`（`nf-threads-query`），只有 editor.js 回答——外掛形態沒有內建編輯器，三樣都不畫；一條線、一條未歸屬的伏筆都沒有時也不給。**敘事線落後於定稿時**（四期，`ProjectTree.threads.lag`）：頁裡最上面一句「⚠ 第 31–60 章還沒判」（與角色組「稱呼衝突」同一個樣子），標題旁多一個「從正文補記」、組標題與空白處右鍵多「從已寫正文補記敘事線」，發 `backfillThreads`（後端先彈確認框）；補記在跑時（任務名與 `features/threadsBackfill.ts` 的 `BACKFILL_TASK` 一字不差）不給按鈕。故事時間（2026-10-24）：各條線前面一行「時間線」（◷，說法後端給，`ThreadsView.timeline`），點名字開啟 `threads/时间线.md`（還沒有這份檔案時不開）；有敘事線判過卻還沒推的章時標題旁與右鍵給「補推時間」（`backfillTimeline`，補推在跑時不給，任務名與 features/timelineBackfill.ts 一字不差），補推失敗的紅 ❗ 掛在這一行。
- **工程頁的樹是扁平渲染的**（`view/project/rows.ts`）：`renderNodes` 遞迴遍歷 `ProjectNode`，但產出的是**扁平的行陣列**，層級靠 `paddingLeft` 縮排表達而非巢狀 DOM。摺疊狀態存在 `project/treeState.ts` 的 `openFolders`（relPath 集合）與 `openGroups` 裡，「章節」頁籤的卷反過來記折起的（`foldedVolumes`：卷預設展開，`buildVolumeRows`）；切換摺疊只用最近一次收到的樹重畫（`rerenderProject`），不往後端要資料。資料夾預設摺疊，頂層分組預設展開。**「故事架構」那一組複用章節行的元件**（同樣的 `.row-plot` / `.row-label`），所以按 `.row-plot` 取節點時要排掉 `.row-architecture`，否則「章節有幾行」之類的判斷會連架構五行一起數。空分組的「下一步：……」與說明行（`view/project/nextSteps.ts`）**不是** `.row`：它們不是樹上的一項，沒有右鍵選單，也不該被「這一組有幾行」數進去。
- **設定名錄**（`view/project/rows.ts` 的 `buildLoreRow` / `buildLoreUnfiledRows`，篩選框在 `view/project/loreFilter.ts`）：設定行右邊多一格出現章（`ProjectTree.loreByEntry[relPath].detail`，「第 3–57 章 · 12 章」，後端從定稿過的細綱「設定」一節算好，前端不自己算），**另起一格、不截斷**，不像角色行那樣並進副標題——一句話副標題常有二三十字，並進去出現章永遠被省略號吃掉；被擠掉的是一句話，`detailTip` 看得全。水位之後還有新內容的掛「＋N」，樣子同角色卡（`.cast-pending`），tooltip 分水位是不是 0 兩種說法。「設定」組後面緊跟「出現過 · 未建條目」（`loreUnfiled`，有才畫）：一行是 名字〔分類〕· 出現章，右鍵「新建這條設定」發 `projectAction newLore`，帶 `name`（後端不再彈框問標題）與建議分類的目錄 `dir`（沒分類就是設定根目錄，目錄還沒有時後端建）；**點名字不做事**——建出來的是一份空條目，不放在手一滑就點到的地方。一次先畫 30 個，點過「顯示全部 N 個」記在 `treeState.loreView.showAllUnfiled`，重推樹不縮回。
  - **待完善**（完善設定，2026-10-19，`buildLoreThinRows`）：「設定」組與「出現過 · 未建條目」之間一組「待完善 · N 個」（`loreThin`，有才畫、預設展開）——往前看的一組（接下來幾章要用、卻還沒有條目或條目還只有一句話），排在往回記的那一組前面。一行是 名字〔分類〕· 後端給的說明（「第 12 章起要用 · 只有一句話」）；有條目的點名字開啟，還沒有條目的點名字不做事、整行壓暗（同未建條目）。右鍵「展開…（預計 1 次呼叫）」發 `expandLore`：有條目帶 `relPath`，沒有帶 `name` 與 `category`（後端先問一句要求、彈確認框挑這一次的模型，再按分類建空條目、在對話頁發一輪生成）。**每一條設定行**的右鍵也有這一項（`buildLoreRow`，有沒有待整合都在，跟在「整合這一條」後面）。篩選框按名字 / 分類也篩這一組。組標題右鍵「全部展開（K 條，預計 K 次呼叫，最多 2K 次）」（三期）發 `projectAction: 'expandLoreAll'`：K 不算作者寫過的（`LoreThinEntry.authored`，後端 `loreBatchExpandable` 算好），次數用 core 的 `loreExpandCalls`，與後端確認框同源；全是作者寫過的就沒有這一項。
  - **篩選框是純前端的**：掛在「設定」組標題欄上、摺疊開關旁邊而不是裡面（`buildGroup` 的 `head`；開關是一顆 `<button>`，放進去的話點框、按空格回車都會把組折起來）。篩選串記在 `loreView.filter`，不發後端，重推樹照樣留著。已建條目按標題 / 一句話 / `loreByEntry[].keywords` 匹配，未建條目按名字 / 分類，不分大小寫的子串；篩選時有匹配的資料夾一律展開、沒匹配的整個不畫（`renderNodes` 的 `match`；`openFolders` 不動，清掉篩選就回到原來的開合），已建條目一個都沒匹配上時說「沒有匹配的設定」，未建條目一個都沒有就整組不畫；Esc 與 × 清空，開始篩時組折著就展開。
  - **打一個字整頁重畫一次，焦點得自己放回去**：`renderProject` 重建前記下篩選框的焦點與游標、建完放回新的那個框——檔案監視隨時會推樹，不放回的話旁邊儲存一章就把正在打字的人踢出去。**輸入法組字期間不重畫**：中途的 `input` 不篩，這期間推來的樹只記下不畫（`loreFilterComposing()`），`compositionend` 那一下按最新的樹一起畫——組字中途換掉輸入框，打了一半的拼音就沒了。
- **細綱浮窗按需取、事件委託**（`view/project/summaryTip.ts`）：滑鼠停在**章節行**上約半秒後彈出這一章的細綱（七節，空著的節不畫）。沒定稿的細綱是計劃，頭上標「計劃」；定稿之後正文又改過的標「已過期」。還沒有細綱的章浮窗會照實說，有正文的再提一句可以右鍵「定稿」照正文整理一份。細綱正文**不在** `ProjectTree` 裡（那棵樹每次檔案變動都全量重推，塞進去等於每儲存一次就推幾百 KB），懸停時發 `requestSummary{plotRelPath}` 單章去要。**快取只在收到 `project` 訊息時清**——那說明磁碟變過；摺疊資料夾走 `rerenderProject()` 不經那條分支，快取留著。監聽用事件委託掛在 `#projectBody` 上（行每次重渲染都換掉，逐行 `addEventListener` 會堆積），浮窗與右鍵選單同樣是掛在 `body` 上的 `position: fixed`。
  - **浮窗是可以進去的**：細綱有七個小節、可能上千字，一瞥看不完。滑鼠移上去就一直留著，能滾動、能選中複製，移開才收。所以**不能**給它 `pointer-events: none`，收起也**必須有寬限期**（`CLOSE_DELAY_MS`）——從行挪到浮窗要跨過一道縫，那一兩幀滑鼠既不在行上也不在浮窗上，立刻收會讓浮窗永遠夠不著。
  - **收起要分清是誰在滾**：頁面滾動會讓 fixed 的浮窗和目標行脫節，得收；但**浮窗自己內部的滾動不算**，一滾就收等於那個捲軸形同虛設。捕獲階段的 `scroll` 監聽裡用 `hoverTip.box.contains(e.target)` 區分。Esc 與右鍵仍然立刻收（右鍵選單也是 fixed，會疊在一起）。
  - **定位必須夾進視口**：`place()` 橫向左對齊目標行、右邊溢位往左收；縱向優先放下方，放不下翻上方，**兩邊都放不下時選空間大的一側並壓行內 `max-height`**——只翻轉不壓高度的話，一份長細綱在矮視窗裡會有一截永遠夠不到。量高度前要先清掉上一次的 `maxHeight`，否則會一直沿用之前那個更矮的值；內容後到達（`applySummary`）把浮窗撐高後要重新走一次定位。
- **三隻浮窗，各有取捨**（`view/project/` 下的 `summaryTip` / `detailTip` / `errorTip`）：定位（`view/tip.ts` 的 `placeTip`）與事件委託是同一套（掛 `body`、`position: fixed`、委託在 `#projectBody` 上），區別只在**要不要讓滑鼠進去**。`detailTip` 只復讀一行被截斷的副標題，`pointer-events: none` 收起不留寬限；`summaryTip` 與 `errorTip` 的內容是多行、要能滾動與選中複製，所以必須留寬限期。`errorTip` 還有一點不同：**資料不必向後端單取**——失敗記錄隨 `ProjectTree.failures` 一起推來了（一條几十字，且只有出錯的目標才有），直接讀 `treeState.lastTree` 即可。
- **失敗標記是「解析失敗只有日誌、使用者看不見」的介面出口**（`view/project/rows.ts` 的 `failureMark`）：出錯的行在檔名之前插一個感嘆號，紅色 = 整體失敗、目標一字未改，黃色 = 部分完成、下次會重來；同一目標混著兩種時**按最嚴重的算**。感嘆號還帶原生 `title` 兜底（浮窗要等 300ms）。舊後端推來的樹沒有 `failures` 欄位，`lastTree?.failures?.[relPath]` 的可選鏈是有意的，別把它簡化掉。
- **一套選單引擎、兩個入口**（`view/menu.ts`）：`buildMenuElement(items, className)` 由 `{ label, run, danger, disabled }`（`{ sep: true }` 是分隔線）建出選單 DOM。氣泡右上角的 ⋯ 用 `.msg-menu` 絕對定位貼在 `.msg-head` 裡；右鍵用 `.ctx-menu` 掛到 `body` 上 `position: fixed` 跟著游標走（工程頁有內部滾動，掛在容器裡會被裁掉），貼邊時翻轉。同時只有一個選單，點別處 / Esc / 滾動都收起。
- **創作頁只推薦一個動作，其餘走 `/`**（`view/pipeline.ts` + `view/commands.ts`）：主按鈕來自後端狀態機算出的 `next`，**點了就跑**，輸入框可留空——「寫第 N 章細綱」本來就不需要作者再說什麼。**傳送時用 `next.target` 與 `next.range`，不用會話當下的 target**：全書層的下一步常常落在另一份產物上（會話停在大綱，下一步是給第 1 章拆細綱），從前只覆蓋 stage 與 capability，按鈕上寫著一件事、落盤時寫到了另一處。其餘命令收在 `/` 面板裡——**只有會寫檔案的**（生成，細綱層多一條 `/落定细纲`；目標是一條設定時生成叫 `/展开这条设定`，`/展开` 就挑得中，`commandsFor` 收 `store.session.target` 分得出來；每一層末尾都有一條 `/落定设定`，它帶著自己的 `stage` 與 `target`（設定目錄），挑中後 chip 記著它們、傳送時用它們而不是會話那一層，回到哪由後端管；`/续写大纲` 同理，目標是情節大綱、區間由後端算，工程頁「情節大綱」行與「章節」組右鍵的「續寫大綱（第 a–b 章）」掛的也是這一枚 chip）；討論不是命令，打字就是。挑中變成輸入框裡的一枚待執行 chip，用完即清。命令表來自 core 的 `commandsFor`（零 import 的純函式，前端直接打包），**前端不自己維護一份**——否則介面上會出現後端不認的命令，點了什麼都不發生。停在一章上時流水線條是「大綱 / 細綱 / 正文」三格：大綱那一格（2026-10-24）報這一章排進大綱沒有（`PlotPipelineView.outline`，沒排進掛 ⚠、懸停說排到第幾章），從不高亮，點了回到全書那一層；輸入框旁目標下拉的第一項「全書（架構 · 大綱）」與下面的章之間隔一條選不中的分隔線——從前停在一章上，回全書只有那一項、看著又像列表裡的又一章，作者找不到續寫大綱。
  - **`/` 就是輸入框裡的一個普通字元**，面板只是浮在它上方的候選列表（掛在 `#composerInput` 上，`bottom: 100%`）。從前 `/` 由 keydown 攔下來**不落進輸入框**，過濾串自己攢在模組變數裡——那等於在輸入框旁邊又造了一個隱形的輸入框：游標在哪、退格退的是誰全靠猜，**輸入法打的中文一個都收不到**（composition 期間不發可列印鍵的 keydown）。現在過濾串由 `slashQuery()` 從輸入框的值算出來，面板的開合掛在 `input` 事件上（不是 keydown），中文/退格/貼上/Ctrl+A 全都自動對。鍵盤只接管 ↑↓ / Enter·Tab / Esc，可列印字元一律放行。
  - **判據是「整個輸入框只有一個 `/词`」**（`/^\/(\S*)$/`）：`/` 在中文正文裡是普通字元（日期、比值、網址），`子时 3/4 刻` 與 `/ 这是一句话` 都不該彈面板。這條判據同時管著「要不要開面板」與「挑中後要不要把那幾個字從輸入框裡抹掉」，所以只寫一次。
  - **Esc 關過要記一筆**（`dismissed`）：輸入框裡那個 `/` 還在（那是使用者的字，不替他刪），而面板是由輸入框的值驅動的——不記的話下一次按鍵又把它彈出來。刪掉 `/` 或往後打出別的形狀時這一筆自動清掉。
- **寫正文時氣泡頂上一條進度（W7）**（`view/index.ts` 的 `showWriteProgress`）：收 `writeProgress` 就地更新「正在寫 / 續寫第 k 輪 · 已寫 x / 目標 y 字」與一條進度條，到了目標的八成換色，沒有目標字數時來回掃；續寫丟棄一輪時收 `streamReset`，把正文塊退回那一份。收尾的 `turnDone` 整條重建氣泡，進度條隨之消失——那時落盤卡片與氣泡上的 `.artifact-length`（`describeWriteLength`，與後端同一句）已經寫著最後的字數，重演過的另掛一枚紅色 `.artifact-replay`。
- **命令類訊息的氣泡不能是空的**（`view/messages.ts` 的 `fillUserBody`）：命令（寫細綱、寫正文）一律不要求輸入，作者一個字都不必打，於是 user 輪的 `content` 是空串。氣泡裡畫一枚 `/写细纲` 標籤（資料來自 `SerializedTurn.command`，後端記的是**按階段具體化過的標籤**），有補充要求就跟在下面。**命令名不寫進 `content`**——那句話會被當成作者的要求裝進 prompt，與舊介面逼他手打一句「請生成細綱」是同一個毛病。assistant 那一支**刻意保持成純文字節點**：流式增量走 `body.textContent += delta`，裡面有子元素的話第一片增量就會把它們沖掉。
- **有段的那一輪按發生順序畫**（外部 agent 經 MCP 留下的氣泡：角色名「外部 Agent」旁一枚 `.msg-tag` MCP）（`view/messages.ts` 的 `buildSegments`，實時那條路在 `view/index.ts`）：畫的是 `SerializedTurn.segments`——一段文字一塊 `.msg-body[data-seg=text]`，一次呼叫一條 `.tool-row`，**相鄰的呼叫並進同一個 `.tools` 串**（連著五次 list/read 仍然是一串流水賬，散成五塊反而更亂），文字與 generate 卡打斷它。實時那條路就地追加、絕不重建氣泡：`delta` 接在**末尾那塊**文字上（末尾不是文字就新開一塊，那就是交替本身），`toolCall` 接在**末尾那一串**上（中間說過一句話就另起一串），插入位置一律取 `segmentAnchor()`（上下文明細 / 行內動作之前）。**有段的那一輪不給就地編輯**：`editTurn` 換的是整輪內容，多塊之間沒法對映；單步創作那條路（一塊正文）照舊可改完再採納。一輪剛開始那塊空正文是給「它在想」留的位（推理模型常常先想幾十秒），第一段是工具呼叫時由 `dropEmptyText()` 就地撤掉。
- **`generate` 產出的正文自成一張卡**（`view/messages.ts` 的 `buildGenCard`）：它走的是 `toolDelta` 而不是 `delta`（後端按 callId 貼的標籤），流進 `.gen[data-call=…] .gen-body`，**只在卡內滾**——那幾千字正在往下漲，讓它把訊息流一路往下頂的話，作者連上面剛說的那句話都看不成了。預設展開、限高 260px：`read` 回來的是它查資料的過程，而這是**產物本身**，作者接著就要判斷「這份要不要落盤」。頭兩行（在做什麼 / 結論如何）長在 `<summary>` 裡，所以收起來之後還在，摺疊只藏正文。`toolResult` 到了要**把卡裡當下那份正文帶過去**——它是一段段攢起來的，那條訊息里根本沒有它（落盤的結論隨後還會重推一次同樣的 `toolResult`，那時同樣不能抹掉）。
- **審稿報告卡（五期 W10，`view/review.ts`）**：有 `turn.review` 的那一輪畫報告卡，不畫那段可就地編輯的正文（報告不落盤，改它的文字沒有意義；「複製」取 `turn.content` 裡那一份給人讀的文字）。目標核對在前，嚴重 / 建議分組，通過、丟掉的意見、說明摺疊；點引文發 `revealQuote`。預設勾選來自後端（`review.picks`：嚴重、建議、未完成勾上，待核實不勾），勾選狀態按 turnId 記在前端——氣泡隨 `turnDone` 整體重建時不丟。底部「按勾選的 n 條修稿」寫呼叫次數（`REVISE_CALLS`），0 條或 `busy` 時禁用，點了發 `reviseChapter`。修稿那一輪的使用者氣泡在 `/按审稿修稿` 下面列出勾了哪幾條（`turn.revise.items`）。**編輯模式**（五期補遺 §3）：底部「編輯問題」把問題那幾組換成一張可改的表（分類、嚴重度、說明、引文），「新增問題」加一條作者補充的（引文可以空著）；作者加的能刪、模型給的不能刪；編輯中的表按 turnId 記在前端，重建不丟；「儲存」發 `editReview`（整張表，新加的不帶 id），後端校驗引文、接著編號再推回；編輯期間修稿按鈕收起。推回之後沒見過的新條目按後端的預設勾上，作者加的標「作者補充」、改過的標「已改」，沒有引文的不畫引文那一行。
- **覆蓋審閱的合併檢視（五期 W11，僅獨立版，`view/merge.ts`）**：收 `prompt kind: 'merge'` 畫進 `#mergeModal`（骨架在 `shells/shared/panes.ts` 的 `mergeModal()`，只有獨立版的頁面放它——外掛用 VS Code 自己的 diff 編輯器；頁面上沒有這一塊時當取消回話，不讓後端死等）。按段對齊用 core 的 `paragraphDiff.ts`，相同的段一行帶過、連著超過 3 段折起來，每一處改動原文 / 新版兩欄 + 一格可以手改的結果（預設是新版）+「採用新版 / 保留原文」，頂上「已處理 k / n 處」與「全部採用新版 / 全部保留原文」。**手改過的那一格誰都不動**（上游 ThreeWayMerge 點採用會沖掉手改的內容）：逐格按鈕禁用、整體按鈕跳過它，要重來先點「撤銷手改」。一處都沒動過（或全部採用新版、沒手改）時回 `{"verdict":"apply"}`，原樣用新版、不經段拼接；否則回 `{"verdict":"apply","merged":…}`。只讀模式（`mergeable: false`）只有兩欄與「採納 / 放棄」。**兩欄叫什麼由訊息說**：帶 `sides`（內建編輯器衝突時的「磁碟上的 / 編輯器裡的」、歷史版本的「快照 / 編輯器裡的」）時兩欄、逐處與整體按鈕、狀態一律換成「用……」的說法，`applyLabel` 換掉「寫入合併結果」（那兩處不寫盤，是「放回編輯器」）；不帶就是從前那一套，一字不改。樣式在 `css/standalone/merge.css`。
- **要動磁碟之前那一句問固定在輸入框上方**（`view/gate.ts`）：`gate` 到了就往 `#gateDock`（`.composer` 的第一格，緊貼輸入框上沿）掛一張卡片——要做什麼、動的是哪個檔案、這一次的引數（摺疊著），加上按鈕；點下去發回 `gateResult`。**兩種問法共用這一張卡**：agent 動手前的閘門，以及**產物落盤前那一句**（後者從前是氣泡末尾那顆「採納寫入」——一顆可以永遠不點的按鈕；它的拒絕那顆寫「不採納」而不是「跳過」，答完那一行也補在正文**下面**，靠 `msg.callId` 在不在判斷）。**不復用 `providerModal` 那個遮罩層**：作者要判斷的上下文（它前幾步讀了什麼、正要寫哪個檔案）就在被遮罩蓋住的訊息流裡，而且模態框期間連翻一眼那個檔案都做不到。**也不再掛在氣泡上**：那樣它會跟著內容滾——agent 隨後還在說話、還在調工具，幾行之後卡片就滾出視野了，而迴圈正卡在它上面等回答，介面看起來像「卡住不動」。**只有兩顆按鈕**——叫停整輪是輸入框旁邊那顆「停止」，不在這張卡上（擺進閘門只會被誤當成「跳過」，而兩者的後果差著一整輪）。按鈕上的字全部來自訊息（前端不寫死），同意貼最右（離「傳送」最近的那一側就是「繼續」），拒絕挨著它壓成次級按鈕。訊息帶 `danger` 時（正文開頭重演了上一章結尾）整張卡標紅、多一塊紅色說明；帶 `confirm` 時「同意」要點兩下——第一下只把字換成 `confirm`，第二下才發（按鈕文案兩段式，不疊彈窗）。帶 `remember` 時（一致性預檢，五期補遺 §2）按鈕行上面多一格理由輸入框與第三顆按鈕「記為刻意安排，照寫」，填了理由才能點，點了發 `gateResult { verdict: 'proceed', remember }`。答完卡片就撤（後端回話之前不撤的話，兩顆都點得著，而只有第一下算數），訊息流裡補一行 `.gate-note` 當記錄——緊跟著的工具條只說「未執行」，「因為我按了跳過」只有那一行講得出。那一行不進 `SerializedTurn`：這一輪結束時氣泡按會話重建，它自然消失，決定本身已經記在工具條上了。
- **工作區卡是一隻懸停浮窗**（`view/workbench.ts`）：流水線條上留一個一行高的入口（`#workbench`，只寫「當前產物 · 正文」這樣的層名 `WorkbenchView.layer`——章名已在麵包屑上，完整標題 `title` 在浮窗頭上；也不掛 ▤，那是標題欄「顯示 / 隱藏編輯器」的圖示），懸停浮出這一層的產物，**點一下釘住**（照著細綱寫正文時滑鼠要回輸入框），Esc / 再點一次 / 點別處收起。從前它是訊息流頂部一張 `position: sticky` 的卡片——滾不出視野，代價是永遠佔著訊息流最上面那一塊，而且**既關不掉也藏不起來**（只能摺疊成一條標題欄，那條標題欄還在），側邊欄只有三百來畫素寬，一份細綱能吃掉半屏對話。改成浮窗之後 `renderSession` 不必再把卡片節點放回 `#messages` 了。
  - **寫前提醒**（完善設定三期）：`WorkbenchView.notice`（正文目標上「本章要用的 天機閣 還只有一句話」）在浮窗裡是淡色的 `.wbt-notice`、入口上是淡色的 `◌`（`.wbt-entry-mark.is-notice`），與上游變過的 `⟳`（`warning`）分開——只是提個醒、零呼叫、不攔；兩樣都有時入口仍是 ⟳。
  - **類名用 `wbt-` 而不是 `wb-`**：`wb-` 是**獨立版工作臺外殼**的名稱空間（`css/standalone/workbench.css` 的 `.wb-title` 是那條 38px 高的標題欄、`.wb-side` 是側欄）。改造前這張卡的標題也叫 `.wb-title`，於是在獨立版裡被標題欄那條規則套上了 38px 高度與標題欄底色。
  - **不監聽 scroll**，這是它與另外三隻浮窗唯一的不同：那三隻的目標是工程頁裡會滾動的行，頁面一滾就得收；這個入口長在不滾的流水線條上（`.pipeline` 是 `flex: 0 0 auto`），訊息流滾動時它一動不動。照抄那條會讓「滾上去看前一輪對話，同時對著這一段的細綱」變得不可能——而那正是釘住要解決的情形。
- **四隻浮窗共用一份定位**（`view/tip.ts` 的 `placeTip`）：掛 `body`、`position: fixed`、橫向左對齊目標（右溢位往左收）、縱向優先下方（放不下翻上方、兩邊都不夠就壓 `max-height`）。從前這套幾何在 `summaryTip` / `detailTip` / `errorTip` 裡各抄了一遍。`minHeight: 0` 關掉壓高度那一步，只有 `detailTip` 用它——那隻浮窗只有一行、`pointer-events: none`、滾不動，壓出來的 `max-height` 等於把字截掉。
- **右鍵選單靠 WeakMap 登記**：構建某一行時用 `onContextMenu(row, () => items)` 把「這行右鍵給什麼」記在元素上（那一刻上下文最全，不用右鍵時反查最近那棵樹；行被重渲染丟棄後自動回收）。全域 `contextmenu` 監聽從 `e.target` 向上找第一個登記過的祖先，找不到就用兜底的「重新整理」。**重新整理複用已有的 `projectAction: 'refresh'`**——後端那個分支只是 `pushState()`，會按當前頁籤推資料，天然適用於所有頁面，無需新增協議。
- **右鍵一律接管**：全域監聽裡無條件 `preventDefault()`，輸入框 / 文字域 / 內建編輯器裡也一樣，所以**原生的複製/貼上/剪下選單不會出現**。這是有意的取捨（選單風格統一），代價是這幾處的編輯項要自己實現（編輯器正文區與檔案頁已經做了，見 `editor/clipboard.ts` 與 `explorer/rows.ts`；輸入框裡目前只有「重新整理」）。外掛形態另需 [../src/shells/vscode/webviewHtml.ts](../src/shells/vscode/webviewHtml.ts) 的 `<body data-vscode-context='{"preventDefaultContextMenuItems": true}'>`：VS Code 給 webview 右鍵選單加的複製/貼上項由宿主渲染，JS 的 `preventDefault` 壓不住，不加會同時冒出兩層選單。**監聽掛在 `window` 的捕獲階段**，並額外接管副鍵的 `auxclick`：冒泡階段的監聽會被中途任何一處 `stopPropagation()` 擋掉，而觸控板雙指點選在部分瀏覽器/驅動上只發 `auxclick`、不發 `contextmenu`——兩種漏法的現象都是「彈出原生右鍵選單」。同一次點選的尾巴（落點沒動、300ms 內）只擋不彈，免得一下點選彈兩遍。`pointerdown` / `mousedown` 的預設行為**不碰**：按規範取消它們攔不住 `contextmenu`，卻會把 `mousedown` 一起吃掉，於是文字域裡右鍵不再挪游標，選單裡的「貼上」會貼到上一次游標的位置去。觸控長按的原生 callout 走的不是 `contextmenu`，在 CSS 裡用 `-webkit-touch-callout: none` 關（`css/view/base.css`）。
- **DOM 結構只有一份**：工程頁頁籤條等結構在 [../src/shells/shared/panes.ts](../src/shells/shared/panes.ts)，兩個殼都從那裡取，**加按鈕只改那一處**。（從前兩個殼各存一份，這條規矩是「要同時改兩處」；現在前提沒了。）兩處例外：一是工作臺外殼與編輯器容器只在獨立版的 `page.ts` 裡——那是佈局，本該按宿主分叉；二是草稿那塊編輯區的 DOM 由 `editor/paneElements.ts` 的 `createPaneElements()` 克隆主區結構現造，`page.ts` 裡只有容器 `#wbEditors` 與分隔條 `#wbDraftResizer`。編輯區裡由指令碼現造的幾樣（章節條 `chapterBar.ts`、查詢替換條 `find.ts`、高亮映象層 `highlight.ts`、狀態列上「自動儲存」那一枚 `saving.ts`、標籤條裡的 `.ed-tabs-list` 與「▾」`.ed-tabs-more`（`tabStrip.ts`，模板裡只有空的 `.ed-tabs`）、工具欄麵包屑的各段（`breadcrumb.ts`，填進 `.ed-path`））**兩邊模板裡都沒有**，各自只有一個生成函式，兩塊編輯區共用；編輯器的頁內對話方塊（`dialog.ts`）掛在 `body` 上、現造現拆。
- **宿主差異用能力探測，不判斷環境**：只有 VS Code 有原生設定介面，所以「在 VS Code 設定中開啟」這顆按鈕**在獨立版的頁面里根本不存在**（`settingsPane({ nativeSettings })`），前端用 `maybeById` 取不到就跳過。別改回「渲染出來再 hidden 掉」或「看 state 裡的某個環境位」——那條路走過，介面文案會跟著腐爛（見 [../src/shells/README.md](../src/shells/README.md)）。
- **CSP**：webview 的 CSP 只允許本地資源與 nonce 指令碼，不引任何 CDN / 外部指令碼。獨立版同樣不引外部資源。
- **兩形態隔離**：`standalone.css` 與 `editor.js` / `explorer.js` **只**由獨立版載入，外掛的 `webviewHtml.ts` 裡沒有它們，也沒有 `#wbEditor` / `#filesBody` 容器。給獨立版加樣式請只改 `src/css/standalone/`（必要時用 `.workbench` 字首覆蓋 view 的規則），不要為獨立版去動 `src/css/view/`。
- **能力探測而非環境判斷**：`view/store.ts` 裡用 `document.getElementById('wbEditor')` 判斷有沒有內建編輯器，據此決定「開啟檔案」發 `openEditor` 還是 `openFile`；`editor/index.ts` 與 `explorer/index.ts` 各自開頭探測自己那塊容器（`#wbEditor` / `#filesBody`），不在就直接 return（連 `acquireVsCodeApi()` 都不調——webview 裡那個函式只允許調一次）。外掛裡沒有這些容器，行為不變。
- **跨檔案只經三樣東西**（全在 `src/globals.ts`）：`window.__nfToast`（view 出，editor / explorer 用）、`window.__nfContextMenu` / `window.__nfShowMenu`（view 出的右鍵選單登記函式，與「在某處彈一個選單」——編輯器標籤條的「▾」用，同一個選單引擎、同時只有一個）、幾個自定義事件——`nf-editor-active`（editor → explorer，高亮當前檔案）、`nf-files-moved`（explorer → editor，改名後搬標籤）、`nf-reveal-in-files`（editor → explorer + view：麵包屑目錄段、標籤右鍵「在檔案頁中定位」；資源管理器展開到它、標出那一行 `.fx-revealed`，view 切到「檔案」頁），以及標題欄與編輯器之間的 `nf-editor-query` / `nf-editor-command`（儲存、撤銷那一組，外加「檔案 → 自動儲存」：`query` 裡的 `autoSave`、`command` 的 `toggleAutoSave`）與 `nf-paragraph-query` / `nf-paragraph-command`（「編輯」選單段落那一組）、`nf-versions-query` / `nf-versions-command`（「檔案 → 歷史版本…」）、`nf-quickopen-query` / `nf-quickopen-command`（「檔案 → 轉到…」）、`nf-bookfind-query` / `nf-bookfind-command`（「編輯 → 全書查詢替換…」）、`nf-view-query` / `nf-view-command`（「檢視」選單；`query` 裡的 `look` / `focus` 兩個欄位歸外觀與專注那兩組）、`nf-stats-query` / `nf-stats-command`（「檢視 → 統計」）、`nf-check-query` / `nf-check-command`（「檢視 → 體檢」）、`nf-names-query` / `nf-names-command`（「檢視 → 補全」）、`nf-shortcuts-query` / `nf-shortcuts-command`（「幫助 → 快捷鍵一覽」），以及對話頁「加入選區」問內建編輯器選區的 `nf-selection-query`（獨立版宿主取不到網頁裡的選區，前端問到了就隨 `addSelection.selection` 帶上去；沒選中、在 Markdown 預覽裡、或者是外掛形態沒人回答時不帶，交給宿主——外掛讀 VS Code 選區，獨立版彈貼上框），工程頁「敘事線」頁籤開啟編輯區「敘事線總覽」的 `nf-threads-query` / `nf-threads-command`（`query` 沒人回答就是外掛形態，「總覽」與「在總覽裡看」不畫；`command` 帶 `focus` 就定位到那一行），時間線總覽的 `nf-timeline-query` / `nf-timeline-command`（同樣的探測；`command` 帶 `chapter` 就展開那一章），以及存檔點彈窗退回時問內建編輯器哪幾份沒儲存的 `nf-dirty-query`（外掛形態沒人回答，是空的）。**`editor/shortcuts.ts` 不是第四樣**：它是一張純資料表（零 DOM、零模組狀態），view.js 打包一份只為在選單上寫鍵，兩個產物之間不經它傳任何東西。別讓 explorer 直接讀 editor 的 `panes`——那會把編輯器的內部狀態變成兩個檔案之間的契約，而資源管理器在外掛形態里根本不存在。右鍵選單尤其**不能各起一套**：全域 `contextmenu` 監聽在 view 裡，另起一個會兩層選單一起彈。
- **不拼 HTML 字串渲染使用者內容**：一律 `createElement` + `textContent`（`src/dom.ts` 的 `el()` 就是幹這個的），正文裡寫 `<script>` 也只是普通文字。
- **一排控制元件共用一套尺寸，主按鈕靠顏色跳出來**（`css/view/buttons.css` 的 `--nf-ctl-height` / `--nf-ctl-padding-x` / `--nf-ctl-radius`）：`.primary` / `.secondary` / `.danger` / `.chip-btn` / `.composer-tool` 與 composer、日誌頁工具欄裡的下拉框、數字框同高。從前主次按鈕是 `5px 12px` + 13px 字號，在一排 0.8em 的小控制元件中間粗一號——「寫第 N 章」「儲存」「傳送」於是成了三塊各佔一角的色斑。要改高度只動那三個變數。
  - **尺寸掛在變體類上，不掛在裸 `button` 上**：頁面上大半的 `button` 不是「一排控制元件裡的一顆」——選單項、頁籤、標籤頁的關閉叉、chip 上的 ×、命令面板的每一項、流水線條上的那幾層，各有各的高度。`min-height` 寫在裸 `button` 上會把它們全拽到 24px（`min-height` 壓得過它們自己的 `height`，而它們都沒宣告 min-height 來擋）。裸 `button` 只留字型、游標、圓角這類人人都要的。
  - **`forms.css` 的 `width: 100%` 要在工具欄裡收回來**：那條規則是給設定頁那種「一列一個欄位」定的；工具欄一行擺好幾顆控制元件，不寫 `width: auto` 的話下拉框會獨佔一整行，把後面的按鈕擠到第二行（日誌頁曾是這樣）。
- **預覽與等寬字型是兩件事**：章節可以是 `.txt` / 無副檔名，那時沒有 Markdown 可預覽（隱藏「預覽」按鈕），但它仍是正文，該用正文字型；只有 `.json` / `.yml` 這類結構化檔案才加 `.mono`。
- **兩處 `countWords` 口徑不同，別合併**：`editor/words.ts` 的與 core 一致（中文按字、英文按詞），狀態列上的字數要與工程頁上後端算的對得上（寫法是一趟迴圈、不造中間陣列，結果與 core 的正則寫法逐字對拍，見 `tests/unit/editor/writingStats.test.js`）；`view/format.ts` 的統計模型回覆長度（去空白後的字元數），是另一件事。

## 內建編輯器的行為約束

對應「不靜默覆蓋」這條產品承諾（見 [../AGENTS.md](../AGENTS.md)）：

- 儲存帶**內容 hash 樂觀鎖**。磁碟上的 hash 與編輯器基線不一致（作者在別處改過、或外掛寫入過）時儲存被拒，前端彈衝突條，由使用者在「對比合併…」「用磁碟版本覆蓋編輯器」和「用編輯器內容強制儲存」之間選。
- 只有使用者明確點了「強制儲存」（頁內對話方塊裡再確認一次），才會發不帶 `baseHash` 的 `saveFile`。
- **「對比合併…」不寫盤**（`editor/conflictMerge.ts` + `replace.ts`）：發 `mergeWithDisk`（帶編輯器裡的這一份與 requestId），後端讀磁碟上此刻的那一份開合併檢視（左磁碟、右編輯器），採納後回 `editorReplace` 帶 `base`。前端**先 `Pane.rebase`**（樂觀鎖基線換成磁碟那份、收起衝突條）**再 `applyEdit`** 換內容——順序反過來的話，換內容那一刻的髒標記是對著舊基線算的。結果是一步撤銷、仍是未儲存，作者照常 `Ctrl+S`，不必強制儲存。`rebase` 與衝突條上「用磁碟版本覆蓋」同一套收尾：`diskSeen` 裡見過的磁碟新版作廢（`knownDiskHash` 回到新基線，之後磁碟再變——哪怕變回撞衝突時見過的那一份——核對時照樣報）、`file.gone` 清掉、自動儲存的閘放開（`saving.unblockAutoSave`：基線換了本來也會讓閘失效，但磁碟那份正好變回撞衝突時的基線時 hash 一樣，閘會一直關著），之後照常停筆就存。磁碟上已經沒有這一份（`gone`）時衝突條也亮著，那時沒有磁碟版本可合併，按鈕藏起來（與「用磁碟版本覆蓋」同一個判法）。放棄 / 關掉合併檢視後端什麼都不回，什麼都不變。按鈕由模組在每塊編輯區第一次重畫時插進衝突條（說明文字之後），`page.ts` / `createPaneElements` 裡沒有它；衝突條的顯隱與說明文字仍歸 `pane.ts`。
- **`editorReplace` 只認本頁發的 requestId**（`replace.ts` 的 `newRequestId` / `claimRequest`）：回覆是廣播，同一個工程開著兩個視窗時，另一個視窗裡那份不該被換掉。
- **「版本」只換編輯區，從不寫盤**（側欄 `editor/versions.ts`、對比標籤 `editor/versionDiff.ts`；快照由閘道器存，見 `src/core/workspace/README.md`）：用回一處、恢復整份都經 `applyEdit`（一步撤銷、成為未儲存、基線不變），放回之前先發一條不說話的 `saveVersion { quiet: true }`（排在之後任何一次 `saveFile` 前面）。對比標籤是 `transient` 的特殊標籤，不進重新整理恢復；比的口徑（按行、忽略空行與首尾空白、逐字標）只在 `versionDiffCore.ts`。能不能用看 `unavailableReason`，**前端不拿路徑猜**，後端也會再判一次（`versions.unavailable`）。
- 重新整理頁面後恢復未儲存草稿時，同樣比對 hash：磁碟變過就丟棄草稿並提示，不拿舊草稿蓋新內容。
- 關閉有未儲存修改的標籤頁會先問「儲存 / 不儲存 / 取消」（頁內對話方塊）；帶未儲存內容離開頁面問的是瀏覽器原生那一句（`beforeunload`，頁面改不了）。

**不丟稿**（`safety.ts` 裝配的那幾個模組；`pane.ts` 只認 `saving` / `closing` / `dialog` 的幾個函式）：

- **磁碟上的改動同步到已開的標籤**（`diskSync.ts`）：每收到一條 `state` / `init` 去抖 400ms、視窗拿回焦點 / 頁面重新可見時，把兩塊編輯區裡**所有開著的檔案**的 `{ path, hash }` 發給後端（`checkEditorFiles`）。`hash` 取 `Pane.knownDiskHash`：標成已刪除的給空串（磁碟上又出現了後端就會回話），見過一份還沒載入的磁碟新版就給那一份的（`pane.ts` 的 `diskSeen`；衝突條因為接著打字收起了，同一個新版也不再報第二次），否則是儲存基線；正在儲存的那幾份不帶。後端回 `editorDiskChanged`（磁碟上的新版）或 `editorDiskGone`，經 `paneOwning` 交給那一塊：
  - **沒改過的標籤**就地換成新內容（`Pane.applyDiskChange`：走 `replaceAll`，記一步撤銷，與「再次開啟時磁碟有新版」同一處理），**不切標籤、不搶焦點**，游標與滾動夾進新長度；是當前正看著的就在狀態列說一句「磁碟上有新版本，已載入」，幾秒後退回儲存狀態。不彈 toast。
  - **改過的標籤**一個字不動，掛衝突條（`reopen` 那句文案），標籤上掛一個 `.ed-tab-flag`「!」（`.ed-tab.conflict`），彈一條 toast（同一個新版只彈一次）；不切標籤；這一份的自動儲存停下。磁碟上的正好就是編輯器裡那一份時認下來，不算衝突。
  - **不復用 `editorOpen`**：那條把標籤切成當前的、搶焦點，只留給「開啟」這件事（生成落盤後 `openFile` → `editorOpen` 那條路不變）。
- **磁碟上沒了**（`editorDiskGone` → `Pane.markGone`）：`OpenFile.gone`，標籤 `.ed-tab.gone`（名字劃掉 + 紅色「!」），衝突條那一格說「磁碟上已經沒有這個檔案（被刪或改名）」、藏起「用磁碟版本覆蓋編輯器」（沒有磁碟版本），打字不讓它收起。按儲存（含衝突條上的強制儲存）先問「要不要在原路徑重建」，答應了才發 `saveFile { recreate: true }`（仍帶基線）；**絕不靜默在原路徑重建**——閘道器對「帶了基線、檔案卻不在」是當新建處理的，後端編輯器這條路因此收緊成回 `editorDiskGone`、什麼都不寫（`files/fileEditing.ts` 的 `FileGoneError`）。自動儲存跳過它。
- **自己儲存之後不誤報**：`editorSaved` 先到（基線換成新 hash）、`state` 後到（WebSocket 保證順序），之後核對帶的就是新 hash；自己那次儲存還在路上時收到的 `editorDiskChanged` 不認（多半讀到的就是自己剛寫下去的那份，回執會說清楚）。
- **別的視窗存了同一份**：回執是廣播的。這邊沒有儲存在路上時收到的 `editorSaved` / `editorConflict` 當成「磁碟上變了」處理（`applyDiskChange`），**不把基線悄悄換成別人的那一份**——從前那樣做，下一次儲存就把別人的改動蓋掉了。
- **編輯器裡不用 `window.confirm`**（`dialog.ts`）：關標籤的三選一、「還原」與「用編輯器內容強制儲存」的確認、「要不要在原路徑重建」都是頁內對話方塊，外觀複用 `css/view/modal.css`（`.modal-overlay` / `.modal` / `.modal-foot`，按鈕 `.primary` / `.secondary` / `.danger`），DOM 現造現拆。焦點進對話方塊、預設落在主按鈕上；`Enter` 按焦點所在的那顆、`Esc` 取消、`Tab` 不出對話方塊；開著時 `Ctrl` / `Cmd` 組合鍵不往下傳；同一時刻只開一個，後來的排隊。
- **關標籤**（`closing.ts`）：一份有修改時「儲存」（主按鈕）/「不儲存」/「取消」；幾份一起關（關閉其它 / 左側 / 右側）合成一個對話方塊問一次，列出是哪幾份——「全部儲存」/「全部不儲存」/「取消」。「儲存」**等這一份的回執**才關，撞上衝突、磁碟上沒了、出錯就不關（衝突條留著），等回執的工夫裡又改了的也不關。Ctrl+W、「檔案 → 關閉編輯器」、標籤上的叉與中鍵都走這一條（`Pane.closeFile`）；問過之後真正關掉用 `Pane.discard`。
- **儲存本身**（`saving.ts`）：所有儲存（Ctrl+S、工具欄、全部儲存、關標籤時的儲存、自動儲存）都經 `requestSave`。**同一份同一時刻只有一個儲存在路上**，回執回來之前又要存只記一筆，回執是「存成了」而還有沒存上的修改再存一次；撞上衝突、出錯就不接著存。狀態列那一格：「● 未儲存」→「儲存中…」→「已儲存 14:32」（本次會話裡最後一次存成的時刻），發出去 10 秒沒回音說「還沒收到迴音，連上後會自動發出」（斷線時訊息在 bridge 的 outbox 裡等重連）。**存成了不彈 toast**，衝突、出錯照樣彈。回執由 pane 認領之後調 `settleSave`；落到已經不開著的檔案上的，`saving.ts` 自己兜底結掉；換工程時清空。
- **自動儲存**（`autosave.ts`，預設關）：標題欄「檔案 → 自動儲存」（緊跟「全部儲存」，開著打 ✓），開著時狀態列掛一枚 `.ed-autosave`。停筆 2 秒（組字中途不算，上屏重新計時）、切走一個標籤、視窗失去焦點 / 頁面藏起來時儲存，一律帶 `baseHash`。閘在 `saving.autoSaveAllowed`：撞過沖突（或核對磁碟時發現改過的標籤在磁碟上變了）的那一份記下當時的基線，基線沒動之前不碰它（那一枚寫「自動儲存已暫停」），絕不強制儲存；磁碟上沒了的不碰；點了「還原」、磁碟版還沒回來的不碰（`holdSave`）；有對話方塊開著不碰。

編輯區裡的幾條硬規矩（`editor/api.ts` 檔案頭同一份，後來的功能模組——回車自動縮排、成對標點、一鍵排版、查詢替換——都照這幾條寫）：

- **程式改寫只走 `Pane.applyEdit(start, end, text, selection?, opts?)`**，不許直接寫 `textarea.value`（`setRangeText`、`execCommand('insertText')` 也不行）。它換掉一段文字、落選區、記**一步**撤銷，同時更新 `file.draft`、髒標記、狀態列、標籤圓點與 localStorage 草稿，清掉過期的衝突條，再發一條 `onEditorChange`。位置按 `area.value` 的下標算（與 `selectionStart` 同一套），`selection` 按新文字算、預設是游標落在插入文字末尾；`opts.join` 把這一處並進剛記下的那一步（成對標點的後半個隨前半個一起退）。繞過它的改動不進撤銷記錄——下一次 Ctrl+Z 核對不上，整份歷史作廢。右鍵「剪下 / 貼上」、Tab 縮排、「還原」「用磁碟版本覆蓋編輯器」、磁碟新版就地換進沒改過的標籤都已經走它。
- **撤銷 / 重做是編輯器自己記的**（`editor/history.ts`），不用瀏覽器原生的：一塊區的所有標籤共用一個 textarea，切標籤整份換 `value`，原生記錄隨之作廢，而它在各瀏覽器 / 桌面 WebView 裡跨元素、跨程式改寫的行為又沒法統一實測。每個開啟的檔案一份（掛在 `OpenFile.history` 上），記差異不記快照、上限 500 步；切標籤不丟，關標籤丟棄，重新整理不恢復。使用者的輸入在 `input` 裡拿 `file.draft` 與 textarea 當前值求差異；連續打字 / 刪除在 1 秒內且位置相鄰時併成一步，換行斷開；貼上、拖放、程式改寫各自一步。Ctrl/Cmd+Z、Ctrl+Y、Ctrl/Cmd+Shift+Z 在編輯區的 keydown 裡攔下，`beforeinput` 的 `historyUndo` / `historyRedo` 也攔下；標題欄「編輯 → 撤銷 / 重做」在焦點落在編輯區時經 `nf-editor-command`（`undo` / `redo`）交給編輯器（`nf-editor-query` 的 `areaFocused` 告訴標題欄焦點在不在），焦點在別的輸入框時照舊 `execCommand`。標題欄的選單按鈕按下時不奪焦點（`menubar.ts` 的 `keepFocus`），否則 Chromium 裡一點選單焦點就離開了輸入框，編輯那幾項永遠置灰。
- **輸入法保護**：編輯區裡所有 keydown 處理先過 `isImeComposing(e)`（`e.isComposing || e.keyCode === 229`），組字時的 Tab、回車、Ctrl 組合鍵一律放行給輸入法；全域的 Ctrl+S / F / W 同樣。組字期間的 `input` 只重新整理顯示、不記撤銷，`compositionend` 之後整段記一步。用 `addKeyHandler` 掛的處理函式不會收到組字中途的按鍵。
- **正文與否由後端說**：`editorOpen` / `editorSaved` 帶 `kind`（`kindOfPath` 算的），`chapter` / `draft` 是正文（`isProse`），其餘不是；沒給（沒開啟工程）當非正文。與 `draftPath` 同一條原則，前端不拿路徑或副檔名猜。Tab 的縮排單位就看它：正文兩個全形空格，其餘兩個半形空格（`indentUnit`）。
- **Tab 不吞字**：有選區時給碰到的每一行行首加一級（空行跳過），選中的字一個不刪、選區跟著平移；Shift+Tab 每行最多去一級（認兩個全形、單個全形、兩個半形、一個半形、`\t`）。規則在 `editor/indent.ts`。
- **高亮映象層是共用設施**（`editor/highlight.ts`，樣式在 `css/standalone/highlight.css`）：textarea 自己畫不了高亮，於是在每塊編輯區的 textarea 背後疊一層映象 div（`.ed-mirror`，第一次用到時現造在 `.ed-stage` 裡），文字排得與 textarea 一模一樣但顏色透明，只有 `<mark>` 的底色看得見。
  - **為什麼 textarea 背景透明**：映象在下、textarea 在上（`.ed-area` 是 `position: relative; z-index: 1; background: transparent`，`.ed-stage` 用 `isolation: isolate` 把這層疊關係關在格子裡，底色由 `.wb-editor` 給），底色才透得上來；游標、選區、輸入法、點選、右鍵仍然全是 textarea 的，映象 `pointer-events: none`、`aria-hidden`。
  - **排得一模一樣**靠兩樣：一是**排版引數是一組 CSS 變數**（`css/standalone/look.css`：`--nf-ed-font-family` / `--nf-ed-font-size` / `--nf-ed-line-height` / `--nf-ed-measure` 由 `look.ts` 按偏好寫在 `<html>` 上，`--nf-ed-pad-x` / `--nf-ed-pad-y` / `--nf-ed-pad-bottom` / `--nf-ed-gutter` 是 CSS 自己的），`.ed-area` 與 `.ed-mirror-content`（還有 `.ed-preview`）**寫在同一條規則裡讀它們**——要改正文的字號、字型、行距、內邊距，改變數或那一條規則，**不許**給 textarea 或映象層單寫一份、也不許在 JS 裡往元素上寫 `style.fontSize`；二是每次渲染時仍從 textarea 的**計算樣式**抄（字型、字號、行高、字距、內邊距、`white-space` / 斷行規則、`tab-size`……，`.mono` 檔案換了字型也跟得上），寬度取 textarea 的內容區（扣掉豎捲軸，用 `getBoundingClientRect` 的小數寬度），滾動用 `transform` 跟著平移。外觀一變（`look.ts`）各塊映象層當場重抄一遍（`relayoutMirror`：字號變了而 textarea 尺寸沒變時 `ResizeObserver` 不會叫）。CSS 裡**不許**給 `<mark>` 加內邊距、邊框、字重——任何一樣都會讓兩層排得不一樣。
  - **版心居中按容器寬算**：`.ed-stage` 是 `container-type: inline-size`，左右內邊距是 `max(--nf-ed-pad-x, (100cqi - --nf-ed-measure - --nf-ed-gutter) / 2)`。用 `cqi` 而不是百分比：textarea 與映象層落在同一個容器裡，算出來一樣；百分比按包含塊算，映象層的包含塊比 textarea 窄一條捲軸，兩邊會差半條。整段包在 `@supports (width: 1cqi)` 裡，不認容器單位的舊瀏覽器照舊鋪滿（不至於把內邊距算成 0）。
  - **介面按命名圖層**：`setHighlights(pane, layer, ranges)` / `clearHighlights(pane, layer)`，`ranges` 是 `{ start, end, cls }`（`area.value` 的下標，`cls` 是那一段 `<mark>` 的 class，顏色寫在 `highlight.css`）；幾層疊在同一段字上時那一段帶上幾層的 class。查詢用 `find` 這一層，段落聚焦用 `focus` 這一層（`<mark>` 不畫底色、用實色畫字，見下面「外觀與專注」），寫作體檢用 `check` 這一層（只畫下劃線，敏感詞另加淡底色，見下面「寫作體檢」），名詞高亮用 `names` 這一層（角色 / 設定淡底色、未建條目虛下劃線，見下面「名詞高亮」）；再要新的就另起圖層名，**別另起一層映象**（各抄一遍排版，對不齊的地方會翻倍）。三層疊在同一段字上時各管一樣：`find` 管底色、`focus` 管字色、`check` 管下劃線（`check.css` 的選擇器套 `:where()` 降一級，敏感詞的淡底色永遠蓋不過查詢的底色）。
  - **什麼時候重畫**：`setHighlights` / `clearHighlights` 當場畫；換了檔案所有圖層清空（範圍是給上一個檔案算的）；內容變了各層先按這一處改動平移（壓在改動上的丟掉）、下一幀重畫——呼叫方自己下一幀重算再 `setHighlights` 的話那一幀只畫一次；切預覽當場藏；尺寸變了只重擺位置（`ResizeObserver`，沒有就不管）。超過 `HIGHLIGHT_LIMIT`（30 萬字元）不畫，要不要告訴人由呼叫方定（`tooLargeToHighlight`，查詢條會說一句）。
  - **按行分塊，只換變了的那幾塊**：映象裡一行（按 `\n` 切，行尾的 `\n` 留在這一行裡）一個 `<div>`，每塊記著「這一行的字 + 落在這一行的那幾段」（跨行的高亮切成幾截）；重畫時與上一次逐塊比，頭尾對得上的塊原樣留著，只換中間那一截——打一個字只重建、重排一行。從前整份 `replaceChildren`，三萬字的章節、幾百上千處標記時每敲一下要 20~30ms，分塊之後不到 2ms（headless Chromium 實測，與整份一個 div 的排法逐個標記比過位置，差 0px）。排版不變的理由：`pre-wrap` 裡塊尾那個 `\n` 不多出一行（與 textarea 一樣），空行是隻有一個 `\n` 的塊，以 `\n` 結尾時末尾空行單獨一塊放零寬空格；`text-indent` 只留給第一塊（`highlight.css`）。抄樣式、擺位置也只在值變了時才寫（寫同樣的值可能讓瀏覽器把這一層標髒、整份重排）。
  - **滑鼠底下是哪一段**：`rangeAtPoint(pane, layer, x, y)`。映象 `pointer-events: none`，滑鼠事件全在 textarea 上，而瀏覽器按座標取字（`caretPositionFromPoint`）在 textarea 上靠不住（Chromium 時有時無，WebKit 沒有），所以反過來量映象：按縱向二分找到那一塊，再在塊裡量那幾個 `<mark>`（`getClientRects`，折行的每一截都量）。只認畫著的圖層；名詞浮窗用它。
  - **順帶的精確定位**：`scrollToOffset(pane, offset, { onlyIfHidden })` 在一份看不見的映象（`.ed-mirror-probe`）裡排出這個字之前的文字與它所在那一行、把這個字包進標記量 `offsetTop`，把它滾到視口偏上三分之一。審稿引文定位（`Pane.reveal`）與查詢跳轉（`onlyIfHidden`：已經看得見就不滾）都用它；打字機滾動用同一個量法（`measureOffset`）把游標那一行滾到中間，名詞補全的候選框也用它（多量一個 `left`）貼著游標擺。從前按字元位置佔全文的比例估，段落長短不一時能差出好幾屏。量不了（太大、textarea 藏著）時退回按比例估。
- **查詢替換條**（`editor/find.ts`，純函式在零 DOM 的 `editor/findCore.ts`）：每塊編輯區一條，只作用於這一塊的當前檔案。
  - **結構約定**：DOM 只由 `find.ts` 的 `buildFindDom()` 生成，兩塊編輯區都在第一次用到時現造、插在 `.ed-stage` 前面；`page.ts` 與 `createPaneElements()` 裡都沒有它（`tests/dom/standalone/find.test.js` 守著：渲染出來的頁面模板裡不許出現 `ed-find`）。從前查詢條兩邊各寫一份、靠人對齊，加了替換行與兩顆開關之後再抄兩份只會越抄越歪。節點沒有 id（兩塊各一條），按 class 取：第一行 `.ed-find-toggle` / `.ed-find-input` / `.ed-find-case` / `.ed-find-regex` / `.ed-find-count` / `.ed-find-prev` / `.ed-find-next` / `.ed-find-close`，第二行 `.ed-replace-row` 裡的 `.ed-replace-input` / `.ed-replace-one` / `.ed-replace-all`，底下一行提示 `.ed-find-note`。
  - **改寫只走 `applyEdit`**：替換一處一步撤銷；全部替換由 `findCore.replaceAllIn` 算出「第一處到最後一處那一段」的新文字，一次 `applyEdit`、只記一步。
  - **匹配口徑只有一份**：`findCore` 裡找匹配、展開 `$1`、全部替換那一半原樣轉自 core 的 `model/textFind.ts`（零 import，經 `protocol.ts` 打包）——後端的全書查詢替換在磁碟上找的用的是同一份，同一個查詢串、同兩顆開關在一份檔案裡與在全書裡找到的是同一批（`tests/unit/editor/findCore.test.js` 釘著兩邊是同一個函式）。
  - **借給全書查詢定位**：`revealFindMatch(pane, query, opts, offset)`——這一塊的查詢條換成那邊的查詢串與兩顆開關，選中離 `offset` 最近的那一處（與查詢框裡打字之後選中一處同一個 `select`）、焦點進編輯區。
  - **不奪焦點**：打字時從游標往後找、選中匹配，但焦點留在查詢框（人還在打字）；textarea 沒焦點時原生選區看不見，當前那一處靠高亮層的另一種顏色（`ed-hl-find-current`）標出來。`Esc` 關掉時焦點才回編輯區。
  - **快捷鍵**由 `installFind()` 掛在 document 上：`Ctrl+F` / `Ctrl+H` / `F3` 給焦點所在的那一塊（焦點在頁面上、按鈕上時給當前那一塊；**帶 Shift 的不接**——`Ctrl+Shift+F` / `Ctrl+Shift+H` 是全書查詢替換）；焦點在編輯區之外的輸入框 / 文字框（對話輸入框之類）時**不攔**，留給瀏覽器；那一塊沒開檔案也不攔。編輯區裡的 `Esc` 收起查詢條。標題欄「編輯 → 查詢 / 替換」經 `nf-editor-command`（`find` / `replace`）。
- **對「使用者剛輸入了什麼」做反應，只認 `onEditorChange` 裡帶 `change` 的那一下，不認 keydown**（`editor/pairs.ts`）：中文標點幾乎都是輸入法打出來的，keydown 裡看不到那個字，有的輸入法還走一遍組字、`compositionend` 才上屏。`typing` 與 `composition` 兩種來源都帶 `change`（被替換掉的選區也在 `change.removed` 裡），成對符號就靠它包選區、補右半邊；補的那一下 `join: true`，與那次輸入算一步撤銷。在監聽裡調 `applyEdit` 會再發一條 `edit`，自己記一個標誌跳過它。
- **按鍵歸誰按功能分模組掛 `addKeyHandler`**（鍵本身一律先登記在 `shortcuts.ts`，見下面「快捷鍵」）：回車 / Shift+Enter 在 `enter.ts`，`Alt+↑↓`、`Shift+Alt+↑↓`、`Ctrl/Cmd+Shift+K`、`Ctrl/Cmd+Enter` 在 `lines.ts`；彼此不重疊，掛的順序無所謂。沒得可做（到頂、全是空行）也返回 true 接下這一下——這幾個組合鍵瀏覽器的預設動作在編輯區裡沒有用。**例外是名詞補全**（`names.ts`）：`Alt+/` 歸它，候選框開著時 `↑↓` / `Enter` / `Tab` / `Esc` 也先歸它（邊打邊彈時回車不接，放給 `enter.ts`），所以 `installNames` 在 `installParagraphTools` 之前裝。
- **分段格式是工程的設定，前端只讀**（`editor/paragraphState.ts`）：從 `init` / `state`（`ViewState.paragraphStyle`，哪個頁籤都推）與 `project`（工程樹，只在「工程」頁籤開著時推）裡取，預設 `blank`。切換是標題欄「編輯 → 段落格式」發 `setParagraphStyle`，後端只改 `config.md` frontmatter 的這一個鍵再 `pushState`，新值隨下一條 `state` 回來——前端不先改本地的值。回車插什麼、一鍵排版排成什麼樣都打包 core 的 `model/paragraphFormat.ts`，與後端同一份。
- **編輯器偏好按瀏覽器記**：localStorage `novelforge.editor.prefs`（不按工程分鍵，那是作者的手感，不是這本書的設定），一個物件：成對符號自動補全（預設開）、自動儲存（預設關，只認明明白白的 `true`）、單擊開啟為臨時標籤（預設開，只認明明白白的 `false`），外加外觀四項（`fontFamily` / `fontSize` / `lineHeight` / `measure`）、專注三項（`focusMode` / `typewriter` / `paragraphFocus`，只認明明白白的 `true`；全屏不記），以及碼字統計的 `stats` 子物件（`{ goal, session, today }`）、寫作體檢的 `check` 子物件（`{ highlight, status }`，兩個都預設開、只認明明白白的 `false`）、名詞補全的邊打邊彈（`nameAutoPopup`，只認明明白白的 `true`，關掉就刪掉這一項）、名詞高亮（`nameHighlight`，預設開、只認明明白白的 `false`，開啟就刪掉這一項）。前三項歸 `paragraphState.ts`，其餘各歸各的模組（`look.ts` / `focus.ts` / `stats.ts` / `check.ts` / `names.ts` / `nameMarks.ts`）。**往這個鍵裡寫的模組一律讀出整份、合上自己那幾項再整份寫回**（`paragraphState` 的 `storedPrefs` / `setStoredPrefs`；localStorage 讀得到時每次都以它為準，讀不了、寫不進時以記憶體裡那一份為準），誰也不沖掉誰；讀回來的壞值各自逐項回落預設（外觀與專注在 `lookCore.ts`，越界的夾進上下限；寫壞了不是 JSON 的整份當沒記過）。寫不進去時只在記憶體裡生效。主題不在這裡：照舊是 `novelforge.theme`。
- **只對正文出現的工具欄按鈕由功能模組自己插**（「排版」，`editor/layout.ts`）：在每塊編輯區第一次 `render` 時插到「預覽」後面、之後跟著當前檔案顯隱，`page.ts` 與 `createPaneElements` 裡沒有它——兩塊編輯區走同一條路，`pane.ts` 不必知道它。
- **快捷鍵先登記、再處理**（`editor/shortcuts.ts`，見下面「快捷鍵」）：新增或改一個快捷鍵，先在那張表裡寫上鍵、做什麼、分組、生效範圍；選單上的 `kbd`、快捷鍵一覽、按鈕提示裡寫的鍵都從表取，不寫字面量。處理按鍵的地方照舊各管各的，`tests/dom/standalone/shortcuts.test.js` 兩頭守著表與處理對得齊。
- **預覽按標籤記，切換隻走 `Pane.setPreviewing`**（見下面「Markdown 預覽」）：`activate` 只切標籤、不再順手切回編輯——要「先切回編輯」的模組調 `setPreviewing(false)`。

## 敘事線總覽（編輯區裡的特殊標籤）

`editor/threadsOverview.ts`，樣式在 `css/standalone/threads.css`，後端的矩陣在 `core/views/threads.ts` 的 `buildThreadsOverview`（訊息在 `core/protocol/threadsOverview.ts`），`tests/dom/standalone/threadsOverview.test.js` 釘整條鏈路。設計見 [../docs/design/plans/2026-10-20-narrative-threads.md](../docs/design/plans/2026-10-20-narrative-threads.md)「八」。**不調模型**（第 4 條）、不寫盤。

- **只在獨立版**：在 editor.js 裡，探測不到 `#wbEditor` 就整個不裝；工程頁的入口先問 `nf-threads-query`，沒人回答（外掛形態）就不畫（設計稿 ⚑11：外掛先不做，以後要做再開一個 webview panel）。
- **是一個特殊標籤**（上面「標籤」那一條）：預設開在主區，已經開在某一塊就切過去；`nf-threads-command` 帶 `focus`（一條線、或「未歸屬的伏筆」那份檔案的路徑）就標出那一行（`.tov-focus`，換了資料重畫也標著）、資料到了滾過去一次。覆蓋層 `.tov` 掛在那一塊的 `.ed-stage` 裡（`position: absolute; inset: 0; z-index: 3`，壓過正文區），第一次用到時現造，頁面模板裡沒有它。
- **資料按需要**（同「轉到…」）：顯示出來時發 `requestThreadsOverview { requestId }`，回 `threadsOverview`，認 requestId（`replace.ts` 的 `newRequestId` / `claimRequest`，回覆是廣播）。顯示著收到 `state` / `init`（磁碟上變過）停 600ms 再要一次（連著幾條只要一次）；藏著時只記一筆過期，下次顯示再要；點「總覽」總是再要一次。不進 `ProjectTree` / `ViewState`。換工程作廢。
- **畫法**：一切說法與判斷（偏差、連線、逾期、狀態、一行的說法）都是後端算好的，前端只畫。`.tov-scroll` 是唯一的滾動容器：表頭 `.tov-header` sticky top、左列 `.tov-name` sticky left、左上角兩樣都 sticky，橫著豎著都能滾。一列 24px（`CELL`，CSS 經 `--tov-cell` 拿同一個數）、左列 220px。**格子是稀疏的**：一行只給有事件的章造 `.tov-cell`（絕對定位），列的分隔線是 `.tov-track` 的背景——幾千章的書一行也只有幾個節點。左列壓在格子上面，所以它的底色必須不透明（收束了的行壓暗字、不壓整格；定位到的那一行的選中色疊在編輯區底色上），不然橫著滾時底下的記號會透上來。
  - 列頭：章號（`.tov-col-<state>`：已定稿 / 寫了沒定稿 / 只有細綱 / 都沒有，底下一道顏色；定稿了、敘事線還沒判的另加 `.tov-col-unjudged`——那道綠換成虛的、字壓暗，四期），分卷的書上面一行卷名（相鄰同卷的併成一格）；「定稿到第 N 章」是網格里一條絕對定位的豎線 `.tov-now`，敘事線落後於定稿時另一條虛的 `.tov-judged` 標「敘事線判到第 M 章」（一章都沒判過不畫，表頭那一行說「敘事線還沒判過」）。
  - 線的格子借流水線條的 `pstage-mark`：`.tov-mark-plan` ○、`.tov-mark-actual` ●、`.tov-mark-both` ◉（實心外加一圈 `box-shadow`）、`.tov-mark-dev` 紅圈；計劃區間 `.tov-band` 一條淡底。
  - 伏筆一行：埋 `.tov-fmark-plant`（`pstage-mark`，實際的實心、計劃的空心）、收 `.tov-fmark-resolve`（轉 45° 的方塊，計劃的空心）、棄 `.tov-fmark-drop` ✕，一格里實際的先畫（棄 → 收 → 埋），沒有實際的畫計劃的；連線 `.tov-span-done / -open / -planned`（實線 / 虛線 / 淡點線，逾期 `.tov-overdue` 標紅），沒收的在回收章那一格一道豎線 `.tov-due`。
- **互動**：`.tov-scroll` 上的事件委託。懸停 `.tov-cell` 彈 `.tov-tip`（`position: fixed`、`pointer-events: none`，掛在覆蓋層裡）：第幾章、哪一行、計劃與實際的事件、證據、偏差說一句；移開、滾動就收。點 `.tov-cell` / 列頭 `.tov-col` 發 `openChapter`（有正文給正文路徑，只有細綱給細綱路徑——同工程頁點章節行：正文進主區、細綱並排；都沒有就 toast、不發）；點線名、伏筆名、「未歸屬的伏筆」（`.tov-link`）發 `openEditor`，開在總覽所在的這一塊（正常標籤）。窄屏開啟時 `revealEditor()`。使用者內容一律 `textContent`。
  - **手指**（2026-10-24，見[觸屏與窄屏](#觸屏與窄屏手機android-殼)）：點格子 / 列頭**只彈浮窗看這一格**、不開啟那一章（作者定的點選語義：點一項顯示它本身，不跳正文），列頭浮窗裡「點選開啟」換成「長按開啟這一章」，點別處收；相容滑鼠事件不當懸停。右鍵 / 長按格子與列頭給「開啟第 N 章」（只有細綱的「開啟第 N 章的細綱」，都沒有置灰）與「重新整理」，空白處只有「重新整理」——滑鼠右鍵也有這一份。窄屏（≤600px）左列收到 128px（`currentNameWidth()`，量一次、寬度變了下次重畫跟上）。
- **故事時間**（2026-10-24）：列頭與格子的懸停帶上「這一章是哪天」（`ThreadsOverviewChapter.time`，一句話）。同日「時間線總覽」：原來主線組前面的「時間線」一組、「故事時間」一行與表頭的月份帶都挪去了[時間線總覽](#時間線總覽編輯區裡的另一個特殊標籤)，這裡只管線與伏筆。

## 時間線總覽（編輯區裡的另一個特殊標籤）

`editor/timelineOverview.ts`，樣式在 `css/standalone/timeline.css`，後端在 `core/views/timeline.ts` 的 `buildTimelineMatrix`（讀盤那一半是 `core/views/threads.ts` 的 `buildTimelineOverview`，訊息在 `core/protocol/timelineOverview.ts`），`tests/dom/standalone/timelineOverview.test.js` 釘整條鏈路與工程頁的入口。設計見 [../docs/design/plans/2026-10-24-timeline-page.md](../docs/design/plans/2026-10-24-timeline-page.md)。**不調模型**。

- **只在獨立版、同敘事線總覽的做法**：探測 `nf-timeline-query`、開啟 `nf-timeline-command`（帶 `chapter` 就展開、選中那一張，資料到了滾過去一次；那一張被篩選藏起來時放開篩選）；資料按需要（`requestTimelineOverview` → `timelineOverview`，認 requestId；顯示著收到 `state` / `init` 停 600ms 再要一次）。覆蓋層 `.tlp` 掛在那一塊的 `.ed-stage` 上。
- **畫法**：`.tlp-scroll` 是唯一的滾動容器。月份變了插一行 `.tlp-month`（sticky top，帶季節）；一個日子一行 `.tlp-day`（grid：左列日子 `.tlp-when`、中間豎軸 `.tlp-rail` 一個點、右邊卡片 `.tlp-cards`）；相鄰兩個日子之間空了 2 天以上插一行 `.tlp-gap`「N 天后」（照上一行卡片裡最晚的 `end` 算；前端算，篩選之後照留下的重算）。卡片 `.tlp-card.tlp-<state>`：狀態點、章號章名、時段與比上一章、依據，事件（線名小標籤 `.tlp-chip.tlp-c<n>`，色塊 `--tlp-c0`…`--tlp-c7` 是一套校驗過色盲區分度的分類色、不迴圈，第 9 條線起與「未歸屬的伏筆」一樣 `.tlp-cx` 灰；名字照正文的顏色寫）收著時最多 3 條，沒有事件給梗概；對賬報了的 `.has-issue` 左邊一道紅、紅字一條一行；回憶 `.tlp-flashback` 虛線框、縮排。

## 快捷鍵（`editor/shortcuts.ts`）

快捷鍵的唯一一張表：每一條寫著鍵（`Mod+Shift+F` 這樣，`Mod` 是 Windows / Linux 的 Ctrl、Mac 的 ⌘）、做什麼、分組、生效範圍、補充說明（瀏覽器攔不住的寫在這裡）、選單上哪一項寫著它（`menu`）。純資料加幾個純函式、零 DOM、沒有模組狀態（`tests/unit/editor/shortcuts.test.js` 釘著：不撞鍵、每條寫全、按平臺寫、按法怎麼認、篩選）。

- **生效範圍四檔**：`global` 哪裡都行（焦點在對話輸入框裡也認：儲存、轉到、全書查詢、專注、快捷鍵一覽……）；`workbench` 編輯區裡或頁面上——焦點在對話輸入框這類別的輸入框裡時不攔，留給瀏覽器（查詢、F3、上一章 / 下一章、預覽；該給哪一塊用 `api.ts` 的 `paneForShortcut`）；`editor` 游標在正文裡（`addKeyHandler`，組字中途收不到）；`context` 某個面板開著時或某個頁面上（必須寫 `where`：查詢框裡的回車、補全框裡的方向鍵、檔案頁樹上的 Ctrl+C……）。前三檔會同時收到同一下按鍵，三檔之間一種按法只許歸一條；`context` 在同一個 `where` 裡不許重。
- **新增快捷鍵**：先在表裡加一條（選單上也寫著它就填 `menu`），再去處理按鍵的模組裡認它——能用 `matchesShortcut(e, id)` 就用它：它不許多按修飾鍵（`Ctrl+Shift+S` 不是 `Ctrl+S`，`Ctrl+Alt+S` 也不是——AltGr 在一些鍵盤上就是 Ctrl+Alt），表與處理才對得齊。挑鍵之前先看錶裡有沒有撞的、瀏覽器攔不攔得住：Chrome 的 `Ctrl+W` / `Ctrl+N` / `Ctrl+T` / `Ctrl+Tab` / `Ctrl+PageUp` / `Ctrl+PageDown` 頁面攔不住，不拿來做新的快捷鍵（已有的 `Ctrl+W` 關標籤、`Ctrl+N` 新建檔案照舊處理——桌面版攔得到——表裡寫明瞭，⚑）。
- **寫出來的鍵都從表取**：選單（`view/menubar.ts` 與「檢視」各組的 `kbd`）、快捷鍵一覽、按鈕與提示裡的鍵（儲存、預覽、查詢條的「展開替換」、上一章 / 下一章、外觀面板的 −+、「轉到…」底下那一行）用 `shortcutLabel(id)`：Windows / Linux 寫 `Ctrl+Shift+F`，Mac 寫 `⇧⌘F`（`isMacPlatform` 看 `navigator`）。view.js 打包這張表只為寫鍵（上面「跨檔案只經三樣東西」那條說的）。
- **兩頭守著**（`tests/dom/standalone/shortcuts.test.js`）：表裡每一條照它的生效範圍擺好場面（正文裡 / 頁面上 / 對話輸入框裡 / `where` 說的那個面板）按一下，得被接走（`defaultPrevented`），瀏覽器自己的那幾樣（`native`：剪下、複製、貼上、全選）反過來不許被接走——`where` 是新的、測試裡沒有擺場面的辦法，就算沒測到；反過來在正文裡、頁面上、對話輸入框裡把幾百種按法（字母、數字、標點、F1–F12、方向鍵這些 × 修飾鍵組合）挨個按一遍，被接走的每一下都得是那一檔認的某一條。選單上寫著鍵的每一項都得在表裡（`menu`），字也一樣。README「內建編輯器 → 快捷鍵一覽」那張表由 `tests/unit/editor/shortcutsReadme.test.js` 逐格對著這張表核。

## 快捷鍵一覽（Ctrl+/）

`editor/shortcutsPanel.ts` 是面板，標題欄「幫助」裡那一項在 `view/shortcutsMenu.ts`，樣式在 `css/standalone/keys.css`。

- **只在獨立版**：它在 editor.js 裡，探測不到 `#wbEditor` 就整個不裝；外掛形態沒有內建編輯器、也沒有標題欄。
- **寫法照 `dialog.ts`**：DOM 現造現拆、頁面模板裡沒有它，外觀是 `modal.css` 那一套。它是模態的（外面那一層是 `.modal-overlay`，`Ctrl+P` 之類開著時不開），但不是一問一答：不算 `isDialogOpen()`（不攔自動儲存），開著時別的快捷鍵照常；別的 `.modal-overlay`（服務商彈窗、表單、頁內對話方塊）開著時它不開。
- **鍵 `Ctrl+/`**（⚑；Google 文件也是這個鍵）：document 的冒泡階段，哪裡都認（對話輸入框裡也開），組字中途不算。開著時面板在捕獲階段接走 `Esc` 與 `Ctrl+/`、關掉、焦點還回開啟之前的地方；點外面那一層（`mousedown` 落在遮罩本身）、× 也關；`Tab` 不出面板（`focusin` 拉回篩選框）。
- **內容**：按分組（`SHORTCUT_GROUPS` 的順序）列出整張表，一行三格：鍵（幾種按法各一個 `<kbd>`）、做什麼（補充說明在下面一行小字）、在哪兒管用。篩選框按說明、在哪兒、補充說明、分組與兩種平臺的按鍵寫法篩（`filterShortcuts`，空白隔開的幾段都得有），組字中途不篩。

## Markdown 預覽

`editor/pane.ts` 的 `setPreviewing`；切塊與換算是零 DOM 的 `editor/previewCore.ts`（`tests/unit/editor/previewCore.test.js`），量位置在 `editor/previewSync.ts`，渲染在 `editor/preview.ts`。

- **按標籤記**（方案 D3）：預覽還是編輯記在每份檔案的 `OpenFile.markdownPreview` 上，`Pane.isPreviewing()` 說的是當前這一份。`setPreviewing(on)` 是唯一的切換入口：工具欄「預覽 / 編輯」、`Ctrl+Shift+V`、要「先切回編輯」的模組（查詢條、體檢面板、`replace.ts` 放回內容、全書查詢點一處、點引文 `reveal`）。**`activate` 只切標籤、不改預覽**——從前它順手切回編輯，好幾處模組靠這一下退出預覽，現在都改調 `setPreviewing(false)`，新寫的模組也照這樣。切走時預覽滾到哪記在 `previewScrollTop`，切回來放回去；從另一塊搬過來（`CarriedDraft.markdownPreview`）、改名搬家、重新整理恢復（快照裡的 `markdownPreview`，⚑ 只記在前端、不隨開啟請求發出去）都照舊。只對 `.md` / `.markdown` 有意義（`canPreview`）。
- **滾動對應**：`renderPreview` 按 `previewBlocks` 切塊，每一塊（frontmatter、標題、段落、程式碼塊、分隔線、引用、每一個列表項——不掛在 `<ul>` / `<ol>` 上，各塊互不重疊）記 `data-line` / `data-line-end`（原始檔第幾行到第幾行，從 0 數，`\r\n` 先歸一，與 textarea 的行一致）。編輯 → 預覽：`areaTopLine` 二分找編輯區視口頂上那一行，借高亮映象層的 `measureOffset` 量行頂（只量 log₂(行數) 次，**不另起測量 DOM**），位置帶小數——中文一段就是一行、能折成好幾屏，滾到一段中間預覽裡也在那一段中間；`scrollPreviewToLine` 在對應那一塊裡按比例擺（兩塊之間的空行在上一塊的底與下一塊的頂之間擺）。預覽 → 編輯反過來（`previewTopLine` → `areaScrollForLine`）。切回編輯時游標不在視口裡就挪到視口頂上那一行的行首（⚑），在的話不動；先落游標、再滾，免得落選區時瀏覽器把視口拽回游標。量不了（30 萬字以上、沒有排版）按滾過的比例估。
- **重畫不彈回頂上**：`showPreview` 重畫之前記下預覽的 `scrollTop`、畫完放回——儲存回執、磁碟上的新版進來都會重畫預覽。
- **鍵 `Ctrl+Shift+V`**（⚑，與 VS Code「開啟預覽」同一個鍵）：`index.ts` 的全域 keydown，`paneForShortcut` 認是哪一塊（焦點在對話輸入框裡不攔）；那一份不是 Markdown 時也不攔，瀏覽器照常「貼上為純文字」。預覽是 `tabIndex = -1`：切過去焦點進它（方向鍵與翻頁鍵滾的是它，再按一下也認得出是這一塊），`:focus` 不畫框。

## 碼字統計

`editor/stats.ts` 裝配，口徑在零 DOM 的 `editor/writingStats.ts`（`tests/unit/editor/writingStats.test.js` 釘著），「今日碼字」的存法在 `editor/statsDaily.ts`，面板在 `editor/statsPanel.ts`，「檢視 → 統計」在 `view/statsMenu.ts`。`pane.ts` 只在 `updateStatus` 裡調一句 `renderWordStatus`，別的都是模組自己掛的（`onEditorChange`、章節索引、`storage` 事件）。

- **狀態列字數那一格**（每塊編輯區一格，`#edStatusWords` 與草稿區那一格；class、子節點、點選都由 `stats.ts` 第一次畫時掛上，`page.ts` / `createPaneElements` 裡仍是一個空 `<span>`）：「全文 N 字」；有選區「選中 N 字 / 全文 M 字」；當前標籤是某一章的**正文**（`chapterAt` 認出是 `chapter` 那一面）且章節索引裡這一章有 `targetWords` 時換成「3,120 / 4,000 字，還差 880」（超了「超出 120」，正好「正好寫夠」）＋一條細進度條，到八成（第 21 條「寫夠了」的線）加 `enough` 換色。目標只認章節索引的 `targetWords`：後端 `views/pipeline.ts` 的 `plot?.targetWords ?? config.wordsPerChapter`，與寫正文時判寫夠沒有（`controller/chat.ts` 的 `targetWordsOf`、`generation/generate.ts`）同一個式子。細綱、草稿、角色卡，沒寫目標、索引裡還沒有這一章，都不顯示目標。「· 本次 +356 字」「· 今日 1,820 字」兩項按偏好顯示（預設關）。字元數在 `title` 裡。按下滑鼠 `preventDefault`（不奪編輯區焦點），點選 / 回車 / 空格開面板。
- **字數與後端同一個數法**：章節（`kind === 'chapter'` 且是 `.md` / `.markdown`）不算開頭那行 `# 標題`（`headingWords`，與 core `stripH1` 同一條正則、單測對拍）——後端數章節字數是 `countWords(stripH1(body))`，狀態列、章節條、工程頁三處說的才是同一個數。
- **碼字口徑**（「本次」「今日」同一套）：作者親手打進去的淨字數。算 `typing`、帶 `change` 的 `composition`（輸入法上屏那一下）與 `completion`（名詞補全裡挑了一個名字補上的那幾個字，⚑ 與輸入法挑候選詞同理——`Pane.applyEdit` 帶 `opts.source: 'completion'`），刪掉的倒扣；**不算** `input`（貼上、剪下、拖放）與一切 `program`（回車與 Tab 補的空白、成對符號的半邊、段落快捷鍵、一鍵排版、半形轉全形、替換 / 全部替換、對比合併、歷史版本恢復、還原、用磁碟版本覆蓋、磁碟同步、右鍵貼上），組字中途也不算。**撤銷 / 重做跟著那一步走**（⚑）：`EditHistory.topId` 給每一步一個編號，`StepLedger` 記每一步計入過幾個字，撤銷那一步就減回去、重做再加上；撤銷貼上、排版不動碼字數。重新開始計時換一批新賬本，之前打的字撤銷了也不倒扣這一次。一處改動算幾個字用 `wordDelta`：中文逐字，英文兩頭擴到詞邊界再比，等於前後各數一遍全文再相減，但只看改動那一段。
- **時長**：`typing` / `composition`（組字中途也算）是心跳；兩下之間不超過 2 分鐘（⚑ `IDLE_MS`）那段記進去，更長的整段不算；記在後一下落筆的檔案上，各檔案加起來就是總時長。速度 = 淨字數 ÷ 時長，寫夠 1 分鐘（`MIN_SPEED_MS`）且淨字數為正才報。
- **本次**：從載入頁面起，「重新開始計時」（面板裡與「檢視」裡）、換工程（`nf-workspace-reset`）重來；按檔案分別記（`nf-files-moved` 時明細跟著改名）。只在記憶體裡，重新整理從 0 起。
- **今日**：localStorage `novelforge.editor.stats.daily@<工程>`（`projectStorageKey`；網址上沒有 `?project=` 時只在記憶體裡），`{ v: 1, days: { 'YYYY-MM-DD': { words, ms } } }`，按落筆那一刻的本地日期記、留 30 天，壞值當沒有（`parseDaily`）。**不進工程目錄、不進 SQLite**：工程裡放的是作品（第 17 條：內容的唯一真相是 Markdown），碼字習慣是這個瀏覽器上這個人的，丟了無所謂。**多視窗**：每個視窗只往「待寫」裡記自己的增量，至多 2 秒（以及 `pagehide` / 藏起來 / 換工程時）現讀、相加、寫回，絕不寫自己的總數；別的視窗寫了，這邊收 `storage` 事件丟掉快取重畫。顯示的是「上次讀到的 + 自己還沒寫進去的」。讀寫拋過就只在記憶體裡算，面板上照實說。
- **大章節不卡**：`countWords` 一趟迴圈；每份檔案快取「數過的是哪一份文字」，帶 `change` 的改動核對快取正是改動之前那一份就只數改動那一段（`wordDelta`）；撤銷 / 重做、組字中途這類沒有 `change` 的，兩萬字以內當場重數、更長的至多 300ms 重數一次（其間顯示上一次的數）；選中字數只數選中的那段並按（文字、起止）記住；本次 / 今日只看改動那一段。`pane.ts` 的 `updateStatus` 在 `edit` 事件之前調到——那一刻快取還沒跟上，長文字先顯示舊數，緊跟著的 `edit` 監聽補上再重畫。
- **面板**（`statsPanel.ts`）：掛在 `body` 上 `position: fixed`、貼著那一格往上彈，不是遮罩；點外面（捕獲階段 `mousedown`）、`Esc`、再點那一格收起；同一時刻一個；開著時打字、章節索引更新、別的視窗記了今日碼字都重畫。使用者內容一律 `textContent`。

## 寫作體檢

`editor/check.ts` 裝配，口徑在零 DOM 的 `editor/checkCore.ts`（`tests/unit/editor/checkCore.test.js` 釘著），面板在 `editor/checkPanel.ts`，「檢視 → 體檢」在 `view/checkMenu.ts`，樣式在 `css/standalone/check.css`。**不調模型**（第 4 條），只是按詞表在正文裡找字；不替作者改字（替換是作者點的那一下，走 `applyEdit`）。`pane.ts`、`page.ts`、`createPaneElements` 一行都沒改：那一格、圖層、鉤子都是模組自己掛的。

- **只看正文**：`isProse`（後端給的 `kind`，前端不拿路徑猜）。細綱、角色卡、敏感詞表本身（`kind: 'sensitive'`）、沒給 `kind` 的都不查，那一格藏起來。
- **詞從哪來、口徑在哪**：禁用詞與敏感詞表由後端算好推來（`checkTerms` 訊息，`core/protocol/check.ts`；`controller/check.ts` 每次 `pushState` 現算、內容變了才推、只給有 `openInEditor` 的宿主推）。禁用詞**與生成鏈同一個函式、同一份輸入**：後端 `views/checkTerms.ts` 的 `readBannedTerms`，`generation/generate.ts` 的 `planWriting` 也調它。找位置的函式在 core 的 `model/manuscriptCheck.ts`（`locateTerms` / `latinAcronymRanges`，零 import，前端經 `protocol.ts` 打包；生成鏈的 `countBanned` / `countSimiles` / `latinAcronyms` 都建在它們上面），比喻詞表與上限（`SIMILE_WORDS` / `SIMILE_LIMIT`）也是那一份。
- **四類**：敏感詞（`foldCase`：英文不分大小寫、全形當半形）、禁用詞（區分大小寫，與 `countBanned` 一樣）、比喻詞（全章超過上限才算、才畫，算超出的那幾個）、英文縮寫。同一段字可以同時落在幾類裡，各算各的；同一個詞每一處都算。狀態列「體檢 N」的 N 是四類加起來（⚑ 比喻詞按超出的個數算），沒有問題寫「體檢 ✓」（⚑）。
- **`check` 圖層**：`<mark class="ed-hl ed-hl-chk-<類>">`。只用 `text-decoration`（不佔排版；顏色明寫，映象裡的字是透明的）：敏感詞實線 + 淡底色、禁用詞紅波浪、比喻詞黃波浪、縮寫藍點線，顏色是 `check.css` 裡三套主題各一份的 `--nf-chk-*`。`dom/standalone/check.test.js` 釘著：這幾條規則不許出現內邊距、外邊距、邊框、字重、字色，選擇器必須是 `:where(.ed-mirror) mark.ed-hl-chk-*`。
- **什麼時候重查**（「幾萬字的章節每敲一下也不卡」，這一套在 `editor/liveLayer.ts`，名詞高亮共用）：每份檔案快取「查過的是哪一份文字、哪一版詞表」。兩萬字以內改了字在**微任務**裡重查（`highlight.ts` 的同步訂閱先平移各層，之後才落新的一份，兩次繪製之間只畫一次）；更長的至多 300ms 一次（尾隨，`LIVE_RECHECK_MS`），其間已經畫著的由 `highlight.ts` 跟著改動平移。模組自己記著「映象層上此刻畫著的那幾段」（照 `highlight.ts` 同一條平移規則，`checkCore.shiftRanges`），重查結果一模一樣就不再 `setHighlights`。撤銷 / 重做、組字中途、上屏這些改動對不上「上一份文字」的，按前後文字差（`diffChange`）挪過去並標髒、微任務裡重畫一次。**組字中途不重查**（`compositionstart` / `compositionend` 掛在 textarea 上；pane 自己的 `compositionend` 先跑、上屏那一下的 `edit` 先發）：拼音字母不當英文敏感詞、計數不跟著拼音跳，上屏之後再查。
- **狀態列那一格**（`.ed-check`，插在 `.ed-status` 的 `.spacer` 前面、緊跟字數那一格，兩塊編輯區各一格、第一次 `render` 時現造）：樣子、`aria-expanded`、按下滑鼠不奪焦點、回車 / 空格開啟都照碼字統計那一格；專注模式裡狀態列淡掉時照樣點得開（`focus.css` 認 `aria-expanded`）。
- **面板**（`checkPanel.ts`）：開合照碼字統計面板——掛 `body`、`position: fixed`、貼著那一格往上彈、點外面（捕獲階段 `mousedown`）/ `Esc`（捕獲階段吞掉，專注模式不跟著退）/ 再點一下收起，同一時刻一個；面板上的按鈕按下滑鼠不奪焦點。按類列詞與次數，點一個詞：先 `freshEntry`（節流中就當場重查，位置是此刻的），預覽裡先切回編輯，選中下一處（選區正好是第 k 處就去 k+1，到底繞回，`nextOccurrence`），焦點進 textarea（`preventScroll`）、`scrollToOffset(…, { onlyIfHidden })`，那一行寫「k/N」。有替換詞的敏感詞多「替換本處」（選區正好是某一處才換，換完選中下一處；不是就這一下只選中——與查詢替換的「替換」同一個規矩）與「全部替換」（`checkCore.replaceAllEdit` 算第一處到最後一處那一段，一次 `applyEdit`、一步撤銷——與查詢替換的全部替換同一條路，位置用體檢找出來的那幾處，高亮在哪就換哪）。使用者內容一律 `textContent`。
- **「編輯敏感詞表…」**（面板底下、「檢視 → 體檢」裡）：發 `editSensitiveWords`，後端沒有就經閘道器新建模板（`mode: 'create'`）再 `openInEditor`；儲存走編輯器那條路（樂觀鎖、存歷史版本）。沒開啟工程（`body.no-workspace`）時選單項置灰、面板裡點了只說一句。
- 換工程（`nf-workspace-reset`）：詞表作廢、面板收起，等新工程的 `checkTerms`。

## 兩塊編輯區

- `createPane(id, refs, post)`（`editor/pane.ts`）是工廠，兩塊編輯區是它的兩個例項，各自持有 `files` / `conflicts` / `activePath`（預覽還是編輯按檔案記在 `OpenFile.markdownPreview` 上，見下面「Markdown 預覽」）。主區綁頁面上固定 id 的節點，第二塊（`pane: 'draft'`）在首次收到 `editorOpen{pane:'draft'}` 時惰性建立——它放草稿，也放點開一章時並排開啟的那份細綱（W6）。
- **章節工作臺（W6）**：工程頁點章節行名發 `openChapter`，後端按宿主能力開——正文進主區，細綱經 `openBeside` 進第二塊（VS Code 殼落在 `ViewColumn.Beside`，前端什麼都不用做）。主區頂上的**章節條**（`editor/chapterBar.ts`）在任一塊正開著某一章的正文或細綱時出現：這一章在哪一步、寫了多少，「寫這一章 / 接著寫 / 重寫 / 審稿 / 定稿」按狀態亮滅（提示裡寫呼叫次數），另一份沒開著時給「並排看細綱 / 正文」。按鈕發 `chapterAction`，後端當成對這一章按下主按鈕（審稿是正文層的 `review`，只出報告）。資料取**章節索引**（`chapterIndex` 訊息，`editor/chapterIndex.ts`）與 `nf-editor-active`。從前只取工程樹，而工程樹只在「工程」頁籤開著時才推——作者待在對話頁時條上的字數、狀態是舊的，從沒開啟過工程頁時乾脆沒有資料。章節索引哪個頁籤都推（隨 `init` 一次，之後 `pushState` 裡與 `ViewState` 同一趟流水線索引算出、內容變了才推）。條在主區裡，當前檔案卻可能在右側：條上的 `pointerdown` / `focusin` 不往上冒，免得主區把「當前這一塊」搶過去、條一重畫點選就落空。
- **上一章 / 下一章**（`editor/chapterNav.ts`，章節條兩頭的按鈕與 Alt+PageUp / Alt+PageDown ⚑）：順序按章節索引（章號，第 8 條）；正文跟正文、細綱跟細綱；沒改過就在原位置換掉（`openEditor` 帶 `replace`，收到時 `pane.ts` 的 `slotFor` 再看一眼那一份還是不是沒改過），改過就另開；相鄰那一章已經開著就直接切過去；另一塊開著配對檔案時同樣換成相鄰那一章的配對檔案，**那一份的 `editorOpen` 不認下「當前這一塊」**（`takeQuietOpen`：兩份請求在後端是併發處理的，回來的先後不定）；相鄰那一章沒有這一面時 toast 照實說，不發請求。
- **點引文定位（五期 W10）**：後端推 `editorReveal { path, quote }`（緊跟在那一份的 `editorOpen` 之後），擁有那份檔案的那一塊 `Pane.reveal` 選中那一句，用高亮映象層量出它的位置、滾到視口偏上三分之一（`highlight.ts` 的 `scrollToOffset`）。定位用 core 的 `locateQuote`（`model/review.ts`，與後端校驗引文同一個歸一化：去空白與標點），按編輯區裡**當下**的文字找——有沒儲存的修改時照樣認得出。
- **一個路徑同一時刻只屬於一塊**。`editorSaved` / `editorConflict` / `editorError` / `editorDiskChanged` / `editorDiskGone` 都只帶 `path`，靠這條不變數才認得出該送給誰（`paneOwning`）。因此收到 `editorOpen` 時會先讓另一塊 `closeSilently` 掉同路徑，未儲存內容與撤銷歷史一併搬過來（`CarriedDraft`；歷史只在接上之後的內容與搬走時一字不差才接，改名搬家 `nf-files-moved` 同理）——不是關閉，是搬家。破壞這條會導致從錯的那塊儲存時用錯 `baseHash`，觸發假衝突。標籤右鍵「移到另一側」走同一套（`Pane.moveOut` 交出去、`upsertFile(view, carried)` 接上），只是**不經後端**：交出來的 `view` 就是搬走時的基線，`carried.local` 讓接手的那一塊連衝突條、見過的磁碟新版、「磁碟上沒了」與游標一起接上（經後端重讀來的那一份可能已經不是它們說的那一份，所以 `editorOpen` 那條路不接這幾樣）。

**標籤**（`pane.ts` 的 `renderTabs` / `upsertFile`，`tabLabels.ts` / `tabStrip.ts` / `tabMenu.ts`）：

- **稱呼由後端算**（`EditorFileView.label`：型別短標記、去掉副檔名的名字、麵包屑，`src/core/views/editorLabel.ts`），與 `kind`、`draftPath` 同一條原則；固定檔案的中文稱呼（情節大綱、文風指南、敘事線、全文大綱）與「轉到…」的索引共用 `FIXED_DOC_LABEL` 一張表。麵包屑的章節那一段優先取章節索引裡的標題（`breadcrumb.ts`）：`editorLabel` 不讀盤、只看得到檔名，而有正文的章改了標題檔名不動（第 7 條），那時章節條、「轉到…」說的都是新標題；標籤上仍寫檔名；**同名區分在前端**——開著哪幾份只有前端知道。兩塊編輯區放在一起比，所以一塊的標籤開了 / 關了要讓另一塊重畫標籤（`store.refreshOtherTabs`）。沒給 `label` 時標籤寫檔名、工具欄寫原始路徑。
- **臨時標籤**（`OpenFile.preview`）：開啟請求帶 `preview`（工程頁 / 檔案頁單擊；第二下點選 `e.detail >= 2` 不帶——第一下開啟後那一行可能已經重畫，不指望 `dblclick` 落在同一個元素上），後端原樣帶回 `editorOpen`（`EditorOpenIntent`）。**傳送方總是帶，開關在編輯器這邊判**（`previewTabsEnabled`），view / explorer 不必讀編輯器的偏好。不變數：**每塊最多一個**（新來的臨時標籤佔舊的那個的位置，`slotFor`）；**有未儲存修改的永遠不是臨時的**（`afterContentChange` 裡一變髒就轉正）——所以換掉它從來不會丟字。轉正的路：變髒、`save()`、雙擊標籤、右鍵「固定」、被不帶 `preview` 的開啟請求開啟一次（落盤後自動開啟、點引文、雙擊那一行）、關掉開關；單擊開啟一份已經固定的不把它降回臨時。從另一塊經 `editorOpen` 搬來的保持原樣，「移到另一側」搬來的轉正。重新整理恢復記著（快照裡的 `preview`，只放在 `pendingDrafts` 上，不隨開啟請求發出去）⚑。
- **最近關閉**按塊記（`store.ts` 的 `noteClosed`），只記 `Pane.discard`（作者親手關的）；搬家、換掉臨時標籤、原位換掉都不算。又開著了就從裡面拿掉。
- **特殊標籤**（敘事線重做三期，`store.ts` 的 `SpecialTab`，眼下是「敘事線總覽」與「時間線總覽」兩種）：不對應檔案的標籤，排在檔案標籤前面（`.ed-tab-special`，沒有髒標記）。`pane.ts` 只認這個介面（`label` / `show` / `hide` / `menu`），畫的東西由那個模組掛在 `.ed-stage` 上。**切過去時這一塊沒有當前檔案**（`activePath` 是 null、`activeFile()` 是 undefined，`Pane.activeSpecial()` 說是哪一個）：儲存、查詢、體檢、歷史版本、章節條這些「對當前檔案做事」的都當這一塊沒開檔案，不會對著藏在後面的那一份動手。切回一份檔案（`activate`，或作者從別處開啟一份到這一塊；重新整理恢復陸續回來的檔案不算，見下）它就藏起來；×、中鍵、Ctrl+W、「檔案 → 關閉編輯器」關掉它，回到切過去之前的那一份（還開著的話，否則最後一份）；檔案都關了、它還開著就顯示它；「▾」列表裡也有它。同一個特殊標籤同一時刻只在一塊裡（`openSpecial` 先從另一塊拿走，同「一個路徑只屬於一塊」）。**重新整理記著**：快照多 `specials` / `special`，`active` 記切過去之前的那一份；`restore()` 先開特殊標籤（不寫 localStorage——檔案還沒回來），陸續回來的檔案（`upsertFile` 認得出是重新整理恢復的：有 `pendingDrafts`、不是搬家）不把正顯示著的它換下去，作者此刻從別處開啟的照常切過去；認不出的 id、形狀不對的一律不認、不崩。換工程（`nf-workspace-reset`）一併關掉，不寫 localStorage。
- **標籤條**：整排換掉 DOM 之前留住 `scrollLeft`、換完放回再把當前那個滾進視野（`offsetLeft` 相對 `.ed-tabs-list`，它是 `position: relative`）；滾輪的豎向分量當橫向滾。「▾」彈的是 view 的選單（`showMenuAt`），點選要 `stopPropagation`，否則冒到 document 就把剛彈的選單收了；選單開著時再點「▾」反過來放它冒上去收起。
- **一塊區只有一個 textarea**，所有標籤共用，顯示的是當前檔案（`Pane.area`）。切標籤時整份換 `value`，所以游標位置、滾動位置、撤銷歷史都記在 `OpenFile` 上，而不是指望 textarea 自己記得。別的模組要拿「當前那塊區 + 當前檔案 + 它的 textarea」，用 `api.ts` 的 `activeEditor()` / `editorOf(pane)`。
- `activePane` 靠兩塊根元素上的 `focusin` / `pointerdown` 跟蹤，`Ctrl+S` / `Ctrl+W` 作用於它，`beforeunload` 則掃兩塊。標題欄的撤銷 / 重做也作用於它（焦點在哪塊區，它就是哪塊）。
- 「細綱」「草稿」兩顆按鈕的可見性由後端給的 `file.draftPath` 決定，前端不自己判斷什麼算章節。點它們發 `openPlot{path}` / `openDraft{path}`，**傳的是章節路徑**，細綱（沒有就按模板建）與草稿的路徑由後端推導並按需建立；後端記下上一次並排開的是哪一種，工程頁點章節時旁邊開同一種（`ChatController.companion`）。
- localStorage 的 `novelforge.editor.v1` 從 `{ open, active }` 升為 `{ v: 2, panes: { main, draft }, activePane }`；`restore()` 相容舊形狀（認得 `saved.open` 就當主區），老使用者的標籤頁不會在升級後消失。
- `activePane` 每次易主都要跟一句 `announceActive()`（`activate` / `upsertFile` / 兩塊之間的 `focusin`·`pointerdown` 切換、`dropFile` 關掉當前標籤），資源管理器的高亮才不會停在上一個檔案上。`upsertFile` 末尾那句讀的是 `activePane`，所以 `editorOpen` 分支必須**先**認下目標塊再 `upsertFile`。

## 外觀與專注

標題欄「檢視」選單的第二、三組（`view/lookMenu.ts`，接在 `viewMenu.ts` 的 `GROUPS` 裡；順序是標籤 → 外觀 → 專注 → 統計 → 體檢 → 補全）。狀態經 `nf-view-query` 的 `look` / `focus` 兩個欄位問編輯器（`editor/look.ts` / `editor/focus.ts` 各填各的，沒人回答就是 `undefined`、整組置灰），開關經 `nf-view-command` 交過去。

- **外觀**（`look.ts`，取值與校驗在 `lookCore.ts`）：字型（宋體 / 黑體 / 楷體 / 仿宋 / 跟隨系統，只列字型族名、不打包字型檔案）、字號（12–32px，預設 15）、行距（1.3–3 倍，步長 0.05，預設 1.95）、版心寬度（一行最多 20–80 字，`0` 是鋪滿、預設）。生效方式只有一種：寫 `<html>` 上那組 CSS 變數（見上面「高亮映象層」那條）；預覽也讀同一組。
  - **字號快捷鍵只在焦點在編輯區裡時攔**：`Ctrl+=` / `Ctrl++` 放大、`Ctrl+-` 縮小、`Ctrl+0` 還原掛在 `addKeyHandler` 上——只有正文的 textarea 收得到，組字中途的不收。焦點在對話輸入框、頁面上時一律放行，瀏覽器照常縮放整頁。選單裡那三項不看焦點。
  - **外觀面板**（`lookPanel.ts`，「檢視 → 外觀設定…」）：寫法與樣式照 `dialog.ts`（DOM 現造現拆、`.modal` / `.modal-head` / `.modal-body` / `.modal-foot`、焦點進出、`Esc` 關），但**不是模態的**：外面那一層是透明、不攔點選的 `.ed-look-overlay`，**不是** `.modal-overlay`（別的模組拿「有沒有 `.modal-overlay` 開著」判斷有彈窗，`Ctrl+P` 會因此不開），也不算 `isDialogOpen()`（不攔自動儲存）。改了當場生效；「恢復預設」從偏好裡刪掉排版那四項（以後預設改了也跟著走），主題不動（⚑）。段間距不單列（⚑）：textarea 畫不出段與段之間的額外間距，空行分段時段間距就是那一行空行（跟著行距變）。
  - **護眼主題**（`shell.ts`）：與深 / 淺同一個機制——`<html data-theme="sepia">`，`theme.css` 裡一套與淺色同樣全的變數（米黃底、深棕字），記在 `novelforge.theme`。管整個介面，不只編輯區（⚑）。標題欄按鈕按深 → 淺 → 護眼輪著換，按鈕上畫的是下一套。
- **專注模式**（`focus.ts`，F8 ⚑，`Esc` 或再按一次退出）：`<body>` 掛 `nf-focus`，當前那一塊編輯區掛 `ed-focused`（只專注 `activePane`，另一塊藏起來；每次 `render` 重新認一次，從別處開啟了另一塊裡的檔案就跟過去），`css/standalone/focus.css` 藏起活動欄、側欄、標題欄裡選單以外的雜項、標籤條、工具欄、章節條，狀態列淡成一行（只是 `opacity`，字數那一格照樣點得開碼字統計面板——面板掛在 `body` 上、不跟著淡；滑鼠移上去、焦點進來、面板開著時恢復清楚）。**衝突條、查詢條、對比標籤照常**。`Esc` 只在沒人接走時退出：查詢條先收（它 `preventDefault`）、「轉到…」先關、頁內對話方塊、外觀面板、碼字統計面板與快捷鍵一覽在捕獲階段吞掉 `Esc`、標題欄選單與右鍵選單開著時只收選單（捕獲階段先記一筆「按下時有選單開著」——它們在冒泡階段收自己，又不 `preventDefault`）。所以 `installFocus()` 要在 `installFind()` 之後裝。
- **全屏**（`focus.ts`）：Fullscreen API，**能力探測**（`document.fullscreenEnabled` 且有 `requestFullscreen`），不支援時選單項置灰、提示說不支援；全屏的是整個頁面，不記進偏好。F11 是瀏覽器的，不搶。桌面殼：Linux（WebKitGTK）上元素全屏會把視窗真正全屏；Windows（WebView2）上只把頁面撐滿 webview、視窗不變——要真全屏得在 Rust 那邊接 `ContainsFullScreenElementChanged` 調 `set_fullscreen`（頁面拿不到 Tauri 的 IPC，前端做不了），見 [../src/shells/desktop/README.md](../src/shells/desktop/README.md)。
- **打字機滾動**（`typewriter.ts`）：`edit`（帶 `change` 的；組字中途不帶，不認）與方向鍵 / 翻頁 / Home / End 之後下一幀，用 `measureOffset` 量游標那一行、按 `focusCore.typewriterScrollTop` 滾到視口中間。只在焦點在這塊 textarea 裡時滾（磁碟新版就地換進來時不替人滾）；不聽 `scroll` 與滑鼠點選——滾輪翻看前文時不拉回，下一次打字才回來。開著時 `<body>` 掛 `nf-typewriter`，`--nf-ed-pad-bottom` 墊半屏，最後一行也滾得到中間。
- **段落聚焦**（`paragraphFocus.ts`，只對正文 `isProse`）：⚑ textarea 的字整體調淡（`.ed-para-dim`：前景色 × 30% 的**半透明**色，`caret-color` 不變），高亮映象層的 `focus` 圖層把當前那一段包進 `<mark class="ed-hl-focus">`、用**實色**畫字——映象層在下，半透明的淡字疊在同一個字形的實色字上看起來就是實色。游標、選區、輸入法全是 textarea 自己的。代價：當前段畫了兩遍（筆畫邊緣略重），映象層與 textarea 萬一差半個畫素當前段會有重影；超過 `HIGHLIGHT_LIMIT` 不畫也**不調淡**。沒取「textarea 全透明、映象層畫全部文字」：那樣游標畫在看不見的字上、組字時的拼音也是透明的。當前段由 `focusCore.paragraphRangeAt` 按 `paragraphStyle` 認（空行分段：空行隔開的一塊；段首縮排：有縮排的那一行另起、沒縮排緊跟著的是續行；兩者都要：兩樣都算；標題行與場景分隔行自成一段）。改了字之後**在微任務裡**重算——`highlight.ts` 的訂閱先把各層平移、壓在改動上的丟掉，之後才落新的一段，瀏覽器兩次繪製之間只畫一次；游標挪了（`keyup` / `mouseup` / `select` / `selectionchange`）段落變了才重畫。

## 全書查詢替換（Ctrl+Shift+F）

`editor/bookFind.ts` 是面板（畫、按鍵、停頓再搜、點一處、預覽與勾選、兩段式、彙總），`editor/bookFindCore.ts` 是它的純函式
（`tests/unit/editor/bookFindCore.test.js`），標題欄那一項在 `view/bookFindMenu.ts`，樣式在 `css/standalone/bookfind.css`。
後端：查詢在 `core/views/bookFind.ts`、替換在 `core/features/bookReplace.ts`、一份檔案的口徑在 `core/model/bookFind.ts`、
訊息在 `core/protocol/bookFind.ts`（`bookFind` / `cancelBookFind` / `bookReplace` → `bookFindResult` / `bookReplaceDone`）。

- **只在獨立版**：在 editor.js 裡，探測不到 `#wbEditor` 就整個不裝（外掛形態 `Ctrl+Shift+F` 原樣放行）。`Ctrl+Shift+F` 開面板、焦點進
  查詢框，`Ctrl+Shift+H` 焦點進替換框（查詢框空著時仍進查詢框）；掛在 document 上，焦點在對話輸入框裡也開（這個鍵在那裡沒有別的用處）；
  組字中途、頁內對話方塊與 `.modal-overlay` 開著時不開；沒開工程（`body.no-workspace`）說一句、不開。查詢條（`find.ts`）不接帶 Shift 的那兩下；
  名詞補全的 `Alt+/` 帶 Alt、這兩下帶 Ctrl+Shift，互不相干，補全只認編輯區的 textarea（`addKeyHandler` / `onEditorChange`），面板裡的輸入框不彈。
- **放在哪（⚑）**：**壓在側欄上**，與 VS Code 的「搜尋」檢視一樣——面板現造、掛進 `#wbSide`，側欄掛 `bf-open`、`css/standalone/bookfind.css`
  把那幾頁 `.pane` 藏起來（頁頭任務條照常），編輯區一點都不擋：點一處，右邊跳過去，左邊的結果還在。不是遮罩、不進 `.modal-overlay`。
  點活動欄任一頁籤（document 上的 `click`，認 `.tabbar .tab`）、×、面板裡任何一處的 `Esc` 收起（不刪 DOM，結果、勾選、展開狀態都留著）；
  `Esc` 關掉時焦點還回開啟之前的地方。換工程（`nf-workspace-reset`）清空。頁面模板裡沒有它（`bookFind.test.js` 守著）。專注模式藏起側欄，
  但開著的面板照常露出來（`body.nf-focus .wb-side.bf-open`，與查詢條、對比標籤同一個說法）；面板裡的 `Esc` 不往上冒，先收面板、不退出專注。
- **停頓再搜**：查詢框的 `input`（組字中途不算，`compositionend` 再算）停頓 `BOOK_FIND_DEBOUNCE_MS`（300ms）才發 `bookFind`；開關、範圍一換、
  查詢框裡按 `Enter` 當場發。新的一次發出去之前先 `cancelBookFind` 上一次並作廢它的 requestId（`replace.ts` 的 `newRequestId` / `claimRequest`，
  回覆是廣播），「停止」同理。叫停**按請求認**：後端幾個視窗共用一個 controller，不能「新的一次頂掉同一個 controller 上的上一次」。
- **結果**：按範圍分組（`groupByScope`，組標題「正文 · 2 個檔案 3 處」）、一份檔案一塊（`.bf-file[data-path]`：三角、稱呼——後端按編輯器標籤
  的短標記 + 麵包屑最後一段給的——、處數，沒列全寫「列了 / 一共」），每一處一行（`.bf-hit`：行號、同一行前後一截、命中的字 `<mark>`）。
  點檔案那一行收起 / 展開。到了上限、沒搜的檔案、正則寫錯照實說（`resultNotes` / `resultStatus`）。使用者內容一律 `textContent`。
- **用的是磁碟上的內容（⚑）**：編輯器裡開著、有未儲存修改的檔案（`store.allOpenFiles()` 裡 `draft !== text` 的）在結果上標「未儲存」（列的是磁碟
  上那一份）；預覽裡那一份的勾選框勾不了，替換時照樣帶上、列進 `dirty`，後端跳過並在彙總裡說。打字、儲存之後停一下重畫這些標記（`onEditorChange` /
  `editorSaved`）。
- **點一處**：那份檔案開著就 `activate` 過去（在預覽裡就 `setPreviewing(false)` 切回編輯），沒開著就發 `openEditor { path, pane: 'main' }`（**不帶 `preview`**，開成正常標籤），等它的
  `editorOpen`（3 秒之內）再定位——所以 `installBookFind` **要在 `index.ts` 自己的 `onMessage` 之後裝**。定位按後端給的「行 + 列」認回編輯區裡的下標
  （`offsetAt`：磁碟上的 `\r\n` 進了 textarea 是 `\n`，按下標會差），再交給查詢條（`revealFindMatch`）選中離它最近的那一處；一處都沒有（有沒儲存的
  修改）就說一句。窄屏先 `revealEditor`。
- **預覽與替換**：「預覽替換」把 `bookFind` 帶上 `replacement` 再發一次；回來的每一處畫成 `<del>` 舊字 + `<ins>` 新字，每一處、每份檔案都有勾選框
  （檔案那一格三態，`fileCheck`）。勾掉的按 `hitKey`（路徑 + 位置）記，預覽重推時還認得出（`pruneExcluded` 拿掉沒了的）。改了勾選只就地改勾選框與數，
  不整個重畫（滾動位置不動）。「替換所選」**兩段式**（⚑，與表單的 `confirm` 同一個做法）：第一下只把字換成「再點一下：替換 N 個檔案 M 處」，4 秒
  沒點第二下、或改了勾選與輸入框就退回；預覽之後又改了輸入框，新的預覽回來之前不能點（`sameQuery`）。第二下發 `bookReplace`（`buildReplaceRequest`：
  勾著的那幾處、每份預覽時的 hash、`dirty`）。回 `bookReplaceDone`：彙總（`summaryLines`）畫在結果上面；換過了就回到只查詢、自動再搜一次（列出來的是
  還剩下的）；什麼都沒做（上一次還沒換完）預覽留著。
- **已開啟的標籤**這裡什麼都不做：後端替換完 `pushState`，`state` 一到 `diskSync.ts` 照常核對——沒改過的就地換成新內容（一步撤銷），改過的掛衝突條。

## 「轉到…」（Ctrl+P）

`editor/quickOpen.ts` 是面板（畫、按鍵、開啟、焦點、最近開啟的），`editor/quickOpenCore.ts` 是匹配與排序（純函式、零 DOM，`tests/unit/editor/quickOpenCore.test.js` 釘口徑），標題欄那一項在 `view/quickOpenMenu.ts`。

- **只在獨立版**：它在 editor.js 裡，`editor/index.ts` 探測不到 `#wbEditor` 就整個不裝（能力探測），外掛形態 Ctrl+P 原樣交給 VS Code。
- **資料按需要**：開啟時發 `requestQuickOpen { requestId }`，後端回 `quickOpenIndex`（`core/views/quickOpen.ts`：章節、角色卡、設定、架構幾件與大綱 / 文風 / 敘事線 / 全文大綱、草稿；讀了哪些盤寫在那個檔案頭上），認 requestId（回覆是廣播）。不進 `ProjectTree` / `ViewState`——那兩份每次檔案變動都全量重推。面板開著時工程變了不重新整理；上一份索引留著，再開啟先拿它畫、新的到了換掉（輸入沒變時停在原來那一條上）。換工程（`nf-workspace-reset`）作廢。
- **鍵盤照 `/` 命令面板的教訓**：過濾串從輸入框的值算，重算掛在 `input` 上（組字中途的 `input` 不算，`compositionend` 再算），不在 keydown 裡攢字；輸入框只接管 ↑↓ / Enter / Ctrl+Enter / Esc / Tab，組字中途一個都不攔。全域的 Ctrl+P 掛在 document 的冒泡階段：焦點在編輯區之外的輸入框裡（對話輸入框）**照樣開**——與查詢（`find.ts`）不同，這個鍵在那些地方沒有別的用處；組字中不響應；頁內對話方塊（它在捕獲階段吞掉 Ctrl 組合鍵）、`.modal-overlay` 開著時不開；沒開工程（`body.no-workspace`）時不開、說一句，「列印」照樣攔下。
- **不是遮罩**：掛在 `body` 上、`position: fixed` 頂部居中（`css/standalone/quickopen.css`），點外面（document 捕獲階段的 `mousedown`）關、不還焦點；Esc 關、焦點還回開啟之前的地方。行上 `mousedown` 先 `preventDefault`，點一行焦點不離開輸入框。
- **開啟什麼**：章節發 `openChapter`（與工程頁點章節行同一條：正文進主區、有細綱並排；沒有正文給細綱路徑），Ctrl+Enter / Ctrl+點選發 `openEditor { pane: 'draft' }` 開正文（沒有正文開細綱）；其餘發 `openEditor { pane: 'main' | 'draft' }`。**不帶臨時標籤那類標記**（`preview`）——從這裡開啟是作者明確要去的地方，開成正常標籤；按編輯器「被不帶 `preview` 的開啟請求開啟一次就轉正」那一條，要去的那一份正好是臨時標籤時它就此轉正，別的臨時標籤不被換掉。後端的 `openChapter` 在一條訊息裡先開正文再開細綱，兩份 `editorOpen` 按順序到；就算先後反了（獨立版對每條 WebSocket 訊息併發處理），哪一份到了都把焦點放回擁有 `focusAfter.path` 的那一塊，結果一樣（`tests/dom/standalone/quickOpen.test.js` 兩種順序都釘著）。開啟之後等那份檔案的 `editorOpen`（3 秒之內）把焦點放進擁有它的那一塊；章節並排的細綱隨後才到（`index.ts` 那時把 `activePane` 認成第二塊），到了也把焦點與 `activePane` 拉回正文那一塊。所以 `installQuickOpen` **要在 `index.ts` 自己的 `onMessage` 之後裝**：編輯區先收下檔案，它才找得到擁有者。
- **最近開啟的**：編輯器每啟用一份檔案（`nf-editor-active`，不論從哪開啟）記一筆，localStorage `novelforge.quickopen.recent` 按工程分鍵（`projectStorageKey`），最多 20 條；寫不進去就算了。空輸入時按路徑認回條目（同一章的正文與細綱算一條，刪了的、不在索引裡的跳過），最多 8 條，後面接前 10 章。

## 名詞補全（Alt+/ 與邊打邊彈）

`editor/names.ts` 是裝配（按鍵、候選框、插入、名詞表的收發、「檢視 → 補全」的編輯器一半），`editor/namesCore.ts` 是口徑（取查詢詞、匹配排序、邊打邊彈的判定、替換範圍，純函式、零 DOM，`tests/unit/editor/namesCore.test.js` 釘著），選單那一半在 `view/namesMenu.ts`。**不調模型**（第 4 條）。

- **名詞表按需要**：第一次要用時發 `requestNameIndex { requestId, have? }`，後端回 `nameIndex { requestId, sig, index? }`（`core/views/nameIndex.ts`：角色卡的名字與別名、設定條目的標題 / 關鍵詞 / 分類、設定名錄裡出現過還沒建條目的名字，各帶一句話；讀盤代價寫在那個檔案頭上），認 requestId。收到 `state` / `init`（磁碟上變過）記一筆「可能過期」，下一次要用時帶著手上那份的 `sig` 再問，沒變後端只回指紋；問的工夫裡照樣拿手上那份篩，手上還沒有時按鍵那一下等表到了再彈（3 秒之內）。邊打邊彈時至多 3 秒問一次。不進 `ProjectTree` / `ViewState`。換工程作廢。
- **快捷鍵 `Alt+/`**（⚑，Mac 上是 Option+/，按 `e.code === 'Slash'` 認，攔下打出 `÷` 的預設動作）：掛在 `addKeyHandler` 上，只有正文區收得到、組字中途收不到。`Ctrl+Space` 在 Windows / Linux 上常被系統拿去切輸入法，不用；瀏覽器與編輯器都沒佔 `Alt+/`。也可以點「檢視 → 名詞補全」（焦點不在編輯區時先放回去）。
- **查詢詞**：游標前 1~4 個字裡（碰到空白、標點就停），能匹配上某個名字或別名開頭的最長那段；匹配不上就是空查詢、列全部。之後接著打字按「起點到游標」那一段重篩（`queryBetween`），碰到空白標點、游標退到起點前面、一條都對不上就收起。
- **排序**：查詢詞開頭之前 2 萬字裡最近出現過的在前（越近越前）→ 只在游標後面 5 千字裡出現過的 → 沒出現過的；同一檔裡角色 → 設定 → 未建條目、正名先於別名、短的先於長的。一個名詞只列一行；別名命中寫「別名 → 正名」，插入的是那個別名（⚑）。拼音首字母不認：`/` 命令面板的拼音鍵是每條命令手寫的，沒有現成的漢字轉拼音表（⚑）。
- **邊打邊彈**（「檢視 → 邊打邊彈名詞補全」，預設關，`nameAutoPopup`）：只認帶 `change` 的 `typing` / `composition`（上屏那一下）、剛插入了字、游標就在插進來的字後面、沒有選區；查詢詞至少 2 個字（⚑）、不是哪個叫法的全稱（打完整了不彈）、剩下那截不在游標後面（`autoPopQuery`）。框裡只列還沒打完的。**不搶回車**：回車照常換段（框收起，按鍵放給 `enter.ts`），`Tab` 接受（⚑），`↑↓` 在框裡選；接著打字按同一個判定重看，不再成立就收起。
- **輸入法**：組字中途的鍵根本到不了 `addKeyHandler`；自動彈只認上屏那一下；框開著時一開始組字就先藏起來（document 捕獲階段的 `compositionstart`，比編輯區自己的監聽先跑），上屏之後按新的文字重篩，取消組字（編輯區不發 `edit`）也在下一拍重看一眼。
- **插入**：`insertionFor` 算出換掉哪一段（查詢詞，連同選區），經 `Pane.applyEdit(…, { source: 'completion' })`，一步撤銷，游標落在名字後面；自己那一下的 `edit` 不當成作者在打字。
- **只對作者會寫到名字的檔案**：後端給的 `kind`（`completionApplies`：`chapter` / `draft` / `plot` / `character` / `lore` / `outline` / `threads`），前端不拿路徑猜；小說配置、前提、世界觀後端都給 `setting`、分不出哪份是配置，一律不補（⚑）；敏感詞表（`sensitive`）、文風、全文大綱這些也不補——是白名單，以後新加的種類預設不補。按鍵時說一句、不發請求。
- **候選框**：掛在 `body` 上 `position: fixed`（`css/standalone/names.css`），現造現拆。位置借高亮映象層的 `measureOffset` 量查詢詞開頭那個字（**不另起測量 DOM**），放在那一行下面、放不下翻到上面、兩邊都不夠壓 `max-height`、橫向夾進視口；量不了（30 萬字以上、textarea 藏著）就擺在編輯區左上角附近。框裡按下滑鼠 `preventDefault`（不奪編輯區焦點），點一行接受。**收起**：document 捕獲階段 `mousedown` 在框外、編輯區換了檔案或切了預覽、滾輪、別處滾動、視窗改大小、編輯區失焦、撤銷 / 重做、改動落在查詢詞前面；編輯區自己滾（打字機滾動、打到底自動滾）時在微任務裡重擺，游標那一行滾出視口才收。使用者內容一律 `textContent`。
- **Esc**：收起並 `stopPropagation`——查詢條的 Esc 監聽不看 `defaultPrevented`，不攔的話一下 Esc 會把查詢條也收了；專注模式同理。

## 名詞高亮與懸停浮窗

`editor/nameMarks.ts` 裝配（`names` 圖層、浮窗、Ctrl+點選、「檢視 → 名詞高亮」的編輯器一半），認哪幾段是名字在 `editor/namesCore.ts` 的 `nameRanges`（`tests/unit/editor/namesCore.test.js`），樣式在 `css/standalone/names.css` 後半，`tests/dom/standalone/nameMarks.test.js` 釘整條鏈路。**不調模型**（第 4 條）。

- **名詞表與補全同一份**：`names.ts` 管收發（`currentNameCatalog` / `refreshNameIndex` / `onNameCatalog`）。開啟一份歸這一層管的檔案（與補全同一份白名單 `completionApplies`）就要表；收到 `state`（磁碟上變過）且正對著這樣的檔案就再問一次，沒變的話後端只回指紋；表換了整層重畫。開關關著時不要表。
- **認名字**（`nameRanges`）：正名與別名一趟掃完（`locateTerms`，折大小寫）；長的優先、不重疊；一個字的叫法不認（⚑，滿屏）；英文叫法要整詞；**卡或條目自己那一份裡不標它自己**（⚑，按 `path` 認）；兩條叫法撞了歸表裡排前面的（角色 → 設定 → 未建條目）。每份檔案按「哪一份文字、哪一張表」快取。
- **`names` 圖層**：`<mark class="ed-hl ed-hl-name-<來源>">`，角色 / 設定各一種淡底色，未建條目虛下劃線（作者定的）。什麼時候重算、打字 / 輸入法 / 撤銷時怎麼跟上與體檢同一套（`liveLayer.ts`）。選擇器與 `check` 圖層一樣重（`:where(.ed-mirror) mark.…`），`names.css` 在 `standalone.css` 裡排在 `check.css` 前面：撞在同一段字上時體檢的下劃線與敏感詞淡底色蓋過名字的；查詢的底色更重，蓋過兩者。
- **懸停浮窗**：`mousemove` 記下位置，下一幀用 `rangeAtPoint` 量是不是名字、按那一段的字認回表裡那一條（`nameItemOf`）；換了一個名字重新計時，停夠 `HOVER_DELAY_MS`（400ms）再認一次、還是它才彈。框掛 `body`、`position: fixed`、`pointer-events: none`（不擋滑鼠），貼著滑鼠往下襬、靠近底邊翻上去。寫正名、型別（角色 / 分類 / 「分類 · 未建條目」）、別名命中時「這裡寫的是……」、一句話（沒有就說沒有）、底下一行 Ctrl+點選能開啟什麼。移開、移出編輯區、打字（光按修飾鍵不算）、滾動、滾輪、組字、失焦、換檔案、編輯區重畫就收起；按著滑鼠拖選區時不彈；關著名詞高亮時不彈（浮窗靠畫著的那一層認名字）。
- **手指**（2026-10-24；2026-10-31 改）：手指點在名字上**當場彈浮窗**（不等懸停；點之後補發的 mousemove / mouseleave 不當滑鼠），浮窗底下是一顆「開啟角色卡 / 設定條目」（整隻浮窗接住手指，按鈕按下不奪焦點——正文區一失焦浮窗就收了）；點別的字、長按收起；軟鍵盤彈著（`kb-open`，正在打字、點名字是在挪游標）時不彈。軟鍵盤頂起來之後跟著名字挪（`resize` 時重量，挪出編輯區就收）。手指長按正文走系統的選字選單（`view/menu.ts`），沒有我們那一項；滑鼠右鍵名字，選單最前面「開啟「X」的角色卡 / 設定條目」（`api.ts` 的 `addAreaMenu`，未建條目不給）。
- **Ctrl+點選**（Mac 上 ⌘+點選，`isMacPlatform`：Mac 的 Ctrl+點選是右鍵）：`mousedown` 時量是不是名字，是就 `preventDefault`（不挪游標）、發 `openEditor { path, pane: 這一塊 }`（正常標籤，與「轉到…」一樣）；未建條目沒有檔案，`toast` 說一句。按住修飾鍵指著能開啟的名字時 textarea 加 `nm-link`（手形），`keydown` / `keyup` 修飾鍵時跟著重量。快捷鍵表只收鍵盤（`shortcuts.test.js` 逐條去按），Ctrl+點選寫在浮窗、選單說明與 README 裡。

## 資源管理器（「檔案」頁）

- **與「工程」頁是兩件事**：工程頁是按語義整理過的檢視（章節一條列表，帶流水線狀態與定稿狀態；角色帶別名），只看得見幾個可管理區裡的檔案；這一頁是磁碟上真實的目錄結構，一個都不藏。`.novelwarden/` 裡的會話、`project.json`，以及老工程留下、工程頁不再認的 `plots/`，只有這裡進得去——這就是它存在的理由，別為了「乾淨」把點開頭的目錄過濾掉（`fileTree.ts` 的 `HIDDEN_DIR_NAMES` 只擋 `node_modules` 與 `.git`）。
- **懶載入，按目錄**：展開哪個目錄才列哪個。每次展開/摺疊都把**當前展開著的全部目錄**發給後端（`listDir{dirs}`），不是增量——摺疊因此不必再發一條撤銷訊息，後端也據此記住該關注哪些目錄，工程有變動時原樣重推。
- **先 `requestDirs()` 再 `render()`**：請求那一步會把還沒資料的目錄記進 `pending`，順序反了剛展開的那一層會顯示「（未載入）」而不是「載入中…」。
- **能不能編輯由後端算**（`FsEntry.editable`，與 `fileEditing.ts` 同一份規則）。前端不復刻副檔名白名單，也就不會去撞一個必然失敗的 `openEditor`——不可編輯的檔案點選直接走 `openExternal`。
- **樹是扁平渲染的**，與工程頁同一套取捨：層級靠 `paddingLeft` 縮排表達，摺疊只是重畫一遍。展開集合存 localStorage 的 `novelforge.files.open`。
- **截斷要說出來**：目錄條目超過上限時後端給 `truncated`（真實總數），樹尾多一行「另有 N 項未列出」。

## 存檔點（工程頁頁籤條上的 ⚑）

`view/checkpoints.ts` 是彈窗（兩種形態都有），樣式在 `css/view/checkpoints.css`，`tests/dom/view/checkpoints.test.js` 釘著。後端：儲存在 `core/workspace/checkpoints.ts`、退回的編排在 `core/features/checkpoint.ts`、訊息在 `core/controller/checkpoints.ts` 與 `core/protocol/checkpoints.ts`（`listCheckpoints` / `createCheckpoint` / `noteCheckpoint` / `checkpointDiff` / `restoreCheckpoint` → `checkpoints` / `checkpointDiff`；「版本」側欄的全書改動收發同一對 `checkpoints` / `checkpointDiff`），設計見 [../docs/design/plans/2026-10-20-checkpoints.md](../docs/design/plans/2026-10-20-checkpoints.md)。**不調模型**；前端只發訊息、什麼都不寫。

- **入口與遮罩**：工程頁頁籤條（`#projectTabs`）最右邊、重新整理左邊的圖示 ⚑（`data-form="checkpoints"`，`project/index.ts` 的 `installProject` 接點選；只放圖示，與重新整理並排），獨立版另有「檔案 → 存檔點…」（`menubar.ts` 裡一項 `run: openCheckpoints`）。借 `providerModal` 那一層遮罩（同表單），寬度靠 `.modal:has(> .modal-body > .cp-panel)` 撐到 760px——不往 `.modal` 上加類：這一層還有別人用，中途被佔了就摘不掉。**誰佔著這一層各自判斷**（同表單、prompt、服務商彈窗）：面板認的是自己的根節點還在不在 `providerModalBody` 裡；後端推來的 prompt 中途佔了這一層，面板當自己已經關了，之後到的 `checkpoints` / `checkpointDiff` 不往上畫，× / Esc 也不去藏別人的彈窗。× / Esc 關（組字中的 Esc 不算；合併檢視蓋在上面時 Esc 不歸它——那一層自己沒有 Esc，這一下關掉的會是底下的面板），關掉就丟掉面板上的一切，下次開啟重新要。
- **列表**：開啟就發 `listCheckpoints`、說「正在讀…」。一行：時刻（「10-20 22:30」，不是今年的帶年份）、手動 / 自動、備註（沒寫就說「（沒寫備註）」）、「正文 N 章 · X 字 · F 份檔案」，超過 2 MB 沒存進去的說「N 份超過 2 MB 沒存」（路徑掛在提示上，第 2 條）。頂上一格備註 +「存一個存檔點」發 `createCheckpoint`（回車也算），列表回來之前「正在存…」、按鈕置灰；`unavailable`（還不是小說工程）照實說、置灰。自動的多一顆「留住…」：攤開一格（填著原來那句），「留住」發 `noteCheckpoint`——寫了備註就變成手動、不再被自動裁掉。列表那一塊單獨重畫：頂上的備註框不隨重推清掉，寫到一半的「留住」那一格連字帶焦點放回去。
- **跟現在比**：發 `checkpointDiff`、說「正在比…」，只認同一個 id 的回覆（返回列表之後才到的不認）。三組按「改過的 / 之後刪掉的 / 之後新建的」排，組標題帶份數，一樣的只報個數；一行是路徑、種類（按後端給的 `kind`，前端不拿路徑猜；架構三件合稱「架構」，同「轉到…」）、字數（「3,011 → 2,870 字」「當時 / 現在 N 字」，千位加逗號、不折成萬字——兩個數要對得出差了多少）。「對比」只給改過的與刪掉的，而且只在內建編輯器回答了 `nf-version-diff-query` 時才有——**能力探測**，外掛形態沒有 editor.js；點了關掉彈窗、經 `nf-version-diff-command` 在編輯區開「版本」的對比標籤（用回、恢復都只進編輯區，不寫盤）。
- **退回點兩下**（與表單的 `confirm`、全書替換同一個做法）：第一下只換字（「確定退回這一份？」「確定整本退回（N 份）」）並掛 `is-armed`（同表單兩段式的警示色），點在別處（document 捕獲階段的 `click`）或重畫就退回第一段。單份帶 `paths: [這一份]`；整本帶改過的 + 刪掉的，勾了「也把存檔點之後新建的 N 份搬進回收站」（預設不勾）才帶 `trash`。`expect` 是這一次比較裡每份的 `hashNow`，當時磁碟上沒有的給 `null`（後端的樂觀鎖）；`dirty` 經 `nf-dirty-query` 問。發出去之後「正在退回…」、按鈕置灰；後端重推 `checkpoints` 與這個存檔點的 `checkpointDiff`，停在這一頁重畫，勾選框回到不勾。
- **`nf-dirty-query`**（`globals.ts` 的 `queryDirtyPaths()`）：view.js 發一個 `{ paths: [] }`，editor.js（`editor/index.ts`）把兩塊編輯區裡開著、`draft !== text` 的路徑推進去——與全書替換的 `dirtyPaths()`、關標籤時的 `isDirty` 同一個判法。外掛形態沒有 editor.js、沒人回答，是空陣列：VS Code 自己的編輯器有它自己那一套。

## 觸屏與窄屏（手機、Android 殼）

2026-10-24 在 Android 殼（WebView）與 360×640 的無頭瀏覽器裡逐項看過之後改的。**區分形態只用能力探測**：媒體查詢 `(hover: none)`、`(pointer: coarse)`（與模擬器 / 容器裡沒登記觸屏時的 `(pointer: none)`）、`(max-width: 900px)`、`(max-height: 480px)`，以及**這一次**指標的 `pointerType`——不看 UA、不問是不是 Android 殼（`tests/contract/shellPurity.test.js`）。桌面上的滑鼠行為一處沒變（關鍵畫面前後逐畫素比過）。`tests/dom/standalone/touch.test.js`、`tests/unit/view/menuPlace.test.js` 釘這一組。

- **`src/touch.ts`**：`trackPointer()` 在捕獲階段記下最近一次 `pointerdown / pointerover / pointermove` 的 `pointerType`；`lastPointerWasTouch()` / `isTouchEvent(e)` 分清「滑鼠停在這兒」與「手指點了一下之後 Chromium 補發的 mouseover / mousemove / mousedown / click」——懸停浮窗、標題欄選單、敘事線總覽都靠它不把手指當懸停。同一臺機器可以既有滑鼠又有觸屏，所以按這一次的指標認。`avoidSoftKeyboard()`：切頁籤、開啟 / 切換檔案時**不順手聚焦**對話輸入框與正文區（手機上一聚焦就彈軟鍵盤蓋住半屏；頁面剛載入還沒指標時看 `(hover: none)`），作者明確要打字的（彈窗、挑了命令、預覽切回編輯）照舊聚焦。兩個產物各打包一份、各裝一次。
- **整頁不橫向溢位**：`body.workbench` 的列寫死 `minmax(0, 1fr)`（標題欄裡不折行的完整路徑從前把 grid 的 auto 列撐到 min-content，手機把整頁縮小、選單也跟著像是被截）；高度用 `100%` 不用 `100vh`。窄屏標題欄只露書名（`welcome.ts` 寫兩份 `.wb-title-full` / `.wb-title-short`，CSS 按寬度挑，`title` 是完整目錄），選單按鈕不折字。狀態列在窄屏上橫著滾，不再擠成零寬。
- **選單整個落在可視區裡**（`view/menuPlace.ts`，純函式）：右鍵選單在點上——右邊放不下往左翻、再不行貼邊，下面放不下往上翻、再不行平移貼底，比可視區還高從頂上開始壓 `max-height`、選單裡滾；標題欄下拉貼按鈕下沿、伸出右邊就與按鈕右沿對齊；子選單父項右邊 → 左邊 → 貼邊。可視區認 `visualViewport`（軟鍵盤頂起來之後那一塊）。桌面上同樣受益（右下角照舊往左上翻）。點子選單的父項也展開（手指沒有懸停），手指點之前補發的 `mouseenter` / `mouseover` **不**展開子選單、不換選單——不然窄屏上貼邊的子選單蓋到手指底下，緊跟的 click 落在子選單項上（實機上一點「開啟最近開啟的」就開啟了第一本書）。
- **長按不選字**（`css/standalone/touch.css`，`(hover: none)`）：整頁 `user-select: none`，再給輸入框、正文區、預覽、對話正文、報告卡、浮窗、日誌、合併檢視、`pre` / `code` 開啟——長按選單、行、按鈕不再選中一片字，要複製的照常能選。懸停才露的行內按鈕、氣泡的 ⋯、標籤上的 × 常顯。
- **點選目標**（`(pointer: coarse), (pointer: none)`）：標題欄加高到 44px（`--nf-title-height`，窄屏覆蓋層跟著它走）、選單項與右鍵選單項 40px、樹的行與頁籤 40px、圖示按鈕 40×40、一排控制元件 34px、分隔條加寬。只在這兩種指標下生效，桌面不變。

## 新增產物

加一個新的 `.js` / `.css` 產物：先寫原始碼入口，再改三處配置（AGENTS.md 與 `standalone/README.md` 說的「三處」就是下面的 2–4 步）：

1. `media/src/<名字>/index.ts`（或 `src/css/<名字>.css`）放原始碼；
2. [`../scripts/build-media.js`](../scripts/build-media.js) 的 `JS_ENTRIES` / `CSS_ENTRIES` 加一條；
3. [`../scripts/embed-media.js`](../scripts/embed-media.js) 的 `built` 陣列加一條——漏了這步，`bun build --compile` 出的單檔案會 404；
4. 頁面裡引用：獨立版 `standalone/page.ts`，需要時外掛 `vscode/webviewHtml.ts`。

**在已有產物內部拆模組不用改任何配置**，直接 import 即可——這正是這次改造要換來的東西。
