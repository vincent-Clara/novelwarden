# Novelwarden

**寫長篇小說的編輯器，邊寫邊把整本書整理清楚。**

寫長篇難的常常不是寫不出字，而是管不住：寫到幾十上百章，誰在哪幾章出過場、現在是什麼狀況，某個門派的規矩當初是怎麼定的，哪條伏筆埋了還沒收，哪條支線已經二十章沒動靜——全靠自己記，或者另開一堆筆記手工維護，越寫越亂。

Novelwarden 做兩件事：

1. **小說編輯器**（重點）——專門為寫長篇做的：多標籤、正文與細綱左右並排、按這本書的分段格式回車縮排、碼字統計、寫作體檢（禁用詞 / 敏感詞）、角色名與設定名的補全和高亮、全書查詢替換、不會悄悄蓋掉改動的儲存與歷史版本、整本書的存檔點。見[編輯器](#編輯器)。
2. **自動整理**——照你寫下的正文，把這本書整理成四份檔案：**每章細綱**、**角色卡**、**設定**、**劇情線**。寫好的書匯入之後一鍵補齊；之後每寫完一章點一下「同步」，檔案就跟到這一章。檔案由機器維護，**不用你動手改**；想改也隨時能改，改過的地方機器不會覆蓋。見[自動整理](#自動整理)。

![編輯器：左邊工程頁按章列出同步狀態與字數，中間是第 3 章正文（角色名、設定名標了底色），右邊並排開著這一章的細綱](docs/screenshots/editor.png)

所有資料都是工程目錄裡的普通 Markdown：可以用別的編輯器改，可以用 Git 管，程式掛了資料也還在。

除此之外它也能用 AI 往下寫——從一句話展開成架構、大綱、細綱，再一章一章寫成正文，見[也能接著寫](#也能接著寫)。

四種用法共用同一套核心：瀏覽器裡的獨立 Web 版（也能用 Docker 放到伺服器上）、桌面 App、Android App、VS Code 外掛。編輯器在前三種裡；外掛用的是 VS Code 自己的編輯器。

## 快速開始

### 獨立 Web 版

```bash
# 方式一：原始碼直接跑（需要 Bun）
npm install
npm run standalone                                   # 空視窗；上次沒關資料夾則恢復
npm run standalone -- sample-novel                   # 開啟該目錄
npm run standalone -- sample-novel --no-open --port 4000
npm run standalone -- init [目錄]                    # 終端互動式初始化（預設才是當前目錄）

# 方式二：編譯成單檔案可執行
npm run dist                                         # 產出 dist/novelwarden（當前平臺）
./dist/novelwarden sample-novel

# 方式三：npm 包
npm i -g novelwarden && novelwarden
```

服務預設只繫結 `127.0.0.1`、無鑑權，只服務本機；WebSocket 額外校驗 `Origin`，擋住惡意網頁跨源寫入。配置與 API Key 存在 `~/.novelwarden/config.json` / `secrets.json`；從舊版本升級的機器仍讀原來的 `~/.novelforge/`（新目錄不存在時回退過去，不會動舊檔案）。

頁面是一個 VS Code 式的工作臺：左邊活動欄切「對話 / 工程 / 檔案 / 版本 / 歷史 / 日誌 / 設定」，右邊是編輯器，中間的分隔條可拖（雙擊復位）。不帶目錄啟動時是空視窗（編輯區是歡迎頁，見[第一次用](#第一次用)），「檔案 → 新建一本書 / 匯入寫好的書 / 開啟資料夾」在同一程序裡開工程，不必重啟服務。每個瀏覽器視窗各開一個工程，網址上帶著 `?project=<工程目錄>`，重新整理、收藏都回到這個工程。

### Docker（放到伺服器上遠端訪問）

每次發版都會往 GHCR 推一份獨立版映象，amd64 / arm64 都有：`ghcr.io/noir017/novelwarden:latest`（或釘版本 `:X.Y.Z`；`:edge` 是在 CI 裡手動點出來的最新構建）。

映象裡服務綁 `0.0.0.0`，別的機器連得進來，所以**必須配訪問令牌**（環境變數 `NOVELWARDEN_TOKEN`，至少 16 位；舊名 `NOVELFORGE_TOKEN` 仍然認），沒配就拒絕啟動。用 docker compose：

```yaml
# docker-compose.yml；同目錄的 .env 裡寫一行 NOVELWARDEN_TOKEN=…（可用 openssl rand -hex 24 生成）
services:
  novelwarden:
    image: ghcr.io/noir017/novelwarden:latest
    restart: unless-stopped
    ports:
      - "3680:3680"
    environment:
      NOVELWARDEN_TOKEN: ${NOVELWARDEN_TOKEN}
      TZ: Asia/Shanghai
    volumes:
      - ./data:/data
```

```bash
mkdir -p data && sudo chown -R 65532:65532 data   # 映象以非 root 的 uid 65532 執行
docker compose up -d
```

- **一個卷全裝下**：`/data` 是容器裡的家目錄，配置與 API Key 在 `/data/.novelwarden/`，書也放在 `/data` 下（「開啟資料夾」從這裡開始列）。備份它就夠了。
- **用 git 同步書**：映象裡帶 git 與 ssh，在容器裡直接用，例如 `docker compose exec novelwarden git -C /data/我的书 pull`（要進 shell 就 `docker compose exec novelwarden bash`）。git 的身份（`git config --global user.name …`）記在 `/data/.gitconfig`，SSH 金鑰放 `/data/.ssh/`，都在卷裡、重建容器不丟。Novelwarden 自己不碰 `.git`——app 裡的版本管理是存檔點，git 只是你自己的同步工具。
- **登入**：瀏覽器開啟 `http://<服务器>:3680/`，輸一次令牌，記住 30 天。換令牌重啟之後，舊的登入全部作廢。
- **公網要套 HTTPS**：令牌在 http 上是明文傳的，直連只適合內網。要經公網訪問，就在前面加一層 HTTPS 反代，並且要轉發 `Host`（或 `X-Forwarded-Host`）和 WebSocket 升級頭（`Upgrade` / `Connection`），不然對話頁連不上。
- **MCP**：`claude mcp add --transport http novelwarden http://<服务器>:3680/mcp --header "Authorization: Bearer <令牌>"`。
- 不用 Docker 也行：獨立版可以用 `--host 0.0.0.0` 綁到別的地址，規則一樣，綁非迴環地址就必須設 `NOVELWARDEN_TOKEN`。只要設了令牌，即使只綁本機也照樣要登入。

### 桌面 App（Windows / Linux）

雙擊就開的普通桌面應用。它是一層純殼：裡面裝的就是獨立 Web 版的單檔案可執行，所以介面、功能、資料落點與獨立 Web 版完全一致。

```bash
npm run app:dev      # 開發執行（需要 Rust 工具鏈）
npm run app:build    # 出安裝包（Linux: AppImage / deb，Windows: NSIS）
```

Windows 安裝包必須在 Windows 上構建，見 [.github/workflows/app.yml](.github/workflows/app.yml)；細節與已知坑見 [src/shells/desktop/README.md](src/shells/desktop/README.md)。

### Android App

手機上用：裝 Release 裡的 `Novelwarden-<版本>-android-arm64.apk`（arm64 手機，Android 8 起）。介面就是獨立 Web 版的那個頁面，手機上是窄屏佈局。開啟就是本機用法，要連伺服器在返回鍵彈的選單裡點「服務端設定…」換：返回鍵先一層層收起選單、彈窗和正文，收完了才彈這個選單。

- **本機**：服務就跑在手機上，不用另外開電腦。書放在「Documents/Novelwarden」（舊版本是 `Documents/NovelForge`，已裝的 app 繼續讀舊目錄；要授「所有檔案訪問」，檔案管理器、同步盤都看得到，解除安裝 app 也不刪）；不授權就放在 app 自己的目錄，解除安裝時一起刪。API Key 留在 app 私有目錄。用著的時候通知欄掛一條「本機服務在執行」：寫一章要幾分鐘，切到別的 app 也不會斷；從最近任務裡劃掉 app，服務一起關。
- **遠端**：連一臺已經部署好的服務（上面的 Docker，或用 `--host` 綁出去的獨立版），填地址和令牌（令牌也可以空著、在網頁登入頁上輸，輸對一次 app 就記住）。書在伺服器上，手機只是個視窗。

手機上（瀏覽器開啟同樣如此）：導航在底欄，有對話、工程、正文、版本，檔案、歷史、日誌、設定收在「更多」裡；標題欄右邊的「⋯」是檔案 / 編輯 / 檢視 / 幫助選單；返回鍵先收選單、彈窗和正文。電腦上右鍵的地方改成**長按**（正文和輸入框裡長按是手機自帶的選字選單）；編輯區標籤條上有撤銷、重做、儲存，「⋯」裡有預覽、細綱、補全名詞這些；打字時頂上和底下的欄都讓開。電腦上要懸停才看得到的，手指點一下或長按也看得到——點正文裡的名字彈一句話（裡面有「開啟角色卡 / 設定條目」），長按章節行有「細綱速覽」，敘事線總覽點格子看這一格（長按開啟那一章）。還有幾處原生的懸停提示（行上的小圓點、時間線卡片上的完整日期）手機上看不到。構建與已知限制見 [src/shells/android/README.md](src/shells/android/README.md)。

### VS Code 外掛

```bash
git clone https://github.com/noir017/novelwarden.git && cd novelwarden
npm install
npm run compile
```

在 VS Code 裡開啟本倉庫，按 `F5` 啟動 Extension Development Host（自動開啟 `sample-novel/` 示例工程）。外掛在擴充套件市場裡叫 **Novelwarden**；命令面板裡搜 `Novel:` 能看到全部命令。外掛沒有內建編輯器，寫正文用 VS Code 自己的編輯器；整理與生成的功能都在。

### 第一次用

獨立版與桌面版一開啟是歡迎頁，左邊三條路：**新建一本書**、**匯入寫好的書（txt）**、**開啟資料夾**；右邊一段「怎麼上手」。之後隨時從「幫助 → 歡迎頁面」再開啟它。

**寫一本新書**

1. 點「新建一本書…」，填書名（作者可以空著），「放在」預設是上一本書所在的資料夾，點「選…」可以換。點「新建」，就在那裡建一個以書名命名的資料夾，整本書都在裡面。
2. 建好之後左邊自動切到「工程 → 章節」，點「新建第 1 章」，起個章名（也可以空著），右邊開啟就能寫。`Ctrl` + `S` 儲存；寫完一章，在「章節」頁空白處右鍵「新建章節檔案」接著建下一章。
3. 想讓 AI 從一句話起頭，跟著對話頁輸入框上方的主按鈕走（見[也能接著寫](#也能接著寫)）。

**匯入一本寫好的書**

1. 點「匯入寫好的書（txt）…」，挑一本 txt（UTF-8 / GBK 都認）。每章開頭要有單獨一行的章標題，如「第一章 雪夜」「第12章」「楔子」。
2. 表單上先告訴你認出幾章、多少字、丟掉了什麼（書名簡介、卷標題、目錄）；書名預設取檔名。點「匯入」，建好一本書，原稿按章切成一章一份放進去，原 txt 不動。認不出章的話改好 txt 裡的章標題再來。
3. 要把細綱、角色卡、設定、劇情線整理出來，先配一個模型（下一條），再點對話頁的主按鈕「從已寫正文補齊…」（見[已經寫好的書](#已經寫好的書匯入然後一鍵補齊)）。

**配模型（可選）**：光用編輯器不需要模型。要整理或生成時，到「設定」頁點一個預設新增服務商 → 填 API Key → 點該模型的「測試」（見[配置](#配置)）。之後每寫完一章點一下「同步」，檔案就跟到這一章。

**已經在用的書**（比如從 Git 拉下來的）用「開啟資料夾」；還不是小說工程的資料夾，工程頁會給「初始化小說工程」。正文字來就是一章一個檔案的，直接放進 `chapters/`（檔名以章號開頭，如 `001-雪夜.txt`）。外掛版沒有歡迎頁：開啟資料夾後用命令面板 `Novel: 初始化小說工程`。

**舊工程照常開啟**：以前用 Novel Forge 建的工程，後設資料目錄是 `.novelforge/`（更早的版本是 `.novel/`），照樣能開啟、能寫。程式只讀舊目錄，不會自動搬；要遷到新的 `.novelwarden/`，只會在你確認後改名，舊目錄不會刪。

## 編輯器

獨立版與桌面版右邊是一個專門寫小說的編輯器：多標籤、兩塊並排的編輯區、每個檔案各記各的撤銷、查詢替換、不會悄悄蓋掉別人改動的儲存與歷史版本、外觀與專注、碼字統計、寫作體檢、名詞補全與名詞高亮、全書查詢替換。外掛版用 VS Code 自己的編輯器，這一節說的都是獨立版（兩邊的差別見[與外掛版的差異](#與外掛版的差異)）。

下面寫的快捷鍵都是 Windows / Linux 的；Mac 上 `Ctrl` 換成 `⌘`、`Alt` 換成 `⌥`（選單與「快捷鍵一覽」裡會直接這樣寫）。全部快捷鍵見[快捷鍵一覽](#快捷鍵一覽)，在編輯器裡按 `Ctrl` + `/` 也能隨時調出來。

### 開啟與寫

#### 開啟檔案與標籤

- **怎麼開啟**：在「工程」頁點章節、角色卡、設定條目，或在「檔案」頁點任意文字檔案，就在右邊開啟；產物落盤後也會自動開啟寫入的那一份。在工程頁點章節行，正文開在左邊主區、這一章的細綱並排開在右邊（還沒有細綱就按模板建一份空的七節；上一次在右邊開的是草稿，就開這一章的草稿）。
- **能開啟什麼**：工程目錄裡、不超過 2 MB 的純文字——副檔名是 `.md` / `.markdown` / `.txt` / `.json` / `.yml` / `.yaml`，**或者**它本身就是一份章節（數字字首 + 非二進位制副檔名，所以 `001-楔子` 這種無副檔名的章節也打得開）。別的交給系統預設程式；工具欄上的「外部開啟」隨時可以換成你自己的編輯器。
- **轉到（`Ctrl` + `P`，或「檔案 → 轉到…」）**：不用回工程頁翻。頁面頂上出來一個輸入框，打幾個字就跳到一章或一個檔案。焦點在左邊對話輸入框裡時也能按；沒開啟工程時這個鍵不起作用。
  - **找章**：直接打章號——`12`、`第12章`、`第十二章`、`一百零五` 都行，那一章排第一
  - **找名字**：章節標題、角色名（包括別名）、設定標題、情節大綱 / 文風指南 / 敘事線 / 全文大綱、草稿的檔名。連著的幾個字最先，其次是按先後順序出現的幾個字（`林歸` 能找到「林昭歸來」）；名字裡都沒有，再按檔名和路徑找（打 `第一卷` 列出那一卷的章）
  - 每一條前面標著是什麼（章 / 角色 / 設定 / 架構 / 文件 / 草稿），下面一行小字寫「第 12 章 · 第一卷 · 3200 字」、角色的別名，或者檔案路徑；對上的字標了顏色。一次最多列 50 條，多打幾個字縮小範圍
  - 什麼都不打時，先列最近在編輯器裡開過的（每本書各記各的，記在瀏覽器裡），再列前幾章
  - `↑` `↓` 選，`回車` 開啟：章節和在工程頁點章節行一樣，還沒寫正文的章開細綱；`Ctrl` + `回車`（或按住 `Ctrl` 點）開在右邊第二塊編輯區。開啟之後游標就在正文裡，可以接著寫。從這裡開啟的是普通標籤；要去的那一份正好是臨時標籤的話，它就此固定下來。`Esc` 或點面板外面關掉
- **標籤**：沒儲存的標籤帶圓點。標籤上寫去掉副檔名的名字，前面一小格寫它是什麼——細綱、草稿、角色、設定……（正文不寫），同一章的正文、細綱、草稿一眼分得開；還撞名的（比如兩卷裡各有一個「003-夜訪」）後面淡淡寫上是哪個目錄。滑鼠停在標籤上看完整路徑。
- **臨時標籤**（預設開）：在「工程」頁、「檔案」頁**單擊**開啟的檔案，標籤名字是斜體的——它是臨時的，下一次單擊別的檔案時就在原位置換成那一個，不會越開越多。在裡面打了字、儲存了、雙擊這個標籤，或者在那兩頁**雙擊**那一行，它就固定下來。改過還沒儲存的標籤永遠不會被換掉。生成落盤後自動開啟的、點審稿報告引文開啟的、章節條上「並排看細綱」開啟的，一開始就是普通標籤。每塊編輯區最多一個臨時標籤；重新整理頁面後，原來斜體的那一個還是斜體的。不想要這個行為：「檢視 → 單擊開啟為臨時標籤」去掉勾（記在瀏覽器裡，不進工程）。
- **標籤多了**：在標籤條上滾滑鼠滾輪就是左右滾，當前那個標籤總會自動滾進視野。標籤條最右邊的「▾」列出兩塊編輯區裡開著的全部檔案（沒儲存的打著 ●；「敘事線總覽」「時間線總覽」那兩個標籤也在裡面），點一下就切過去；底下還列著最近關掉的幾個，點一下重新開啟。
- **標籤右鍵**：關閉 / 關閉左側 / 關閉右側 / 關閉其它，「移到另一側」（左邊的搬到右邊、右邊的搬到左邊，沒儲存的內容和撤銷記錄一起搬過去）、「在檔案頁中定位」、「複製相對路徑」、「重新開啟剛關閉的」（左右兩塊各記各的），臨時標籤多一項「固定」。重新開啟沒有快捷鍵——瀏覽器不讓網頁用 `Ctrl` + `Shift` + `T`。
- **工具欄上的路徑**寫成「細綱 › 第一卷 › 第 3 章 夜訪」「角色 › 林晚」這樣（章節那一段寫的是這一章現在的標題，與章節條、「轉到…」一樣——改了標題而檔名沒跟著變時也對），滑鼠停在上面看原始路徑；點前面某一級（「細綱」「第一卷」）會在「檔案」頁定位到那個目錄。
- **兩塊編輯區**：主區放正文，右邊第二塊放草稿或並排的細綱，各有自己的標籤條、工具欄與狀態列，中間的分隔條可以拖、雙擊復位。儲存、關標籤這些快捷鍵作用於**有焦點的那一塊**。第二塊關掉最後一個標籤就整塊收起；窄屏（≤900px）放不下並列，它自動藏起來。同一個檔案不會同時開在兩塊裡——從另一塊開啟它（或標籤右鍵「移到另一側」）會連同沒儲存的內容與撤銷記錄一起搬過去。
- **細綱與草稿**：開啟的是章節正文時，工具欄多「細綱」「草稿」兩個按鈕——點「細綱」在右邊開這一章的細綱（還沒有就按模板建一份），點「草稿」在右邊開這一章的草稿（見[章節草稿](#章節草稿)）。之後在工程頁點章節，右邊跟著開上一次點的那一種。
- **章節條**：開啟的是一章的正文或細綱時，編輯區上方多一條：這一章寫了多少、走到哪一步，「寫這一章 / 接著寫 / 重寫 / 審稿 / 同步」幾顆按鈕（按這一章的狀態亮哪幾顆，說明裡寫著呼叫次數），以及「並排看細綱 / 並排看正文」。條上的字數和狀態隨時是新的，不管左邊開著的是哪一頁。
- **上一章 / 下一章**：章節條兩頭的「‹ 上一章」「下一章 ›」，或 `Alt` + `PageUp` / `Alt` + `PageDown`。章節按章號排（檔名開頭的數字，與放在哪個卷目錄裡無關），到頭了按鈕是灰的。看著正文就翻到相鄰那一章的正文，看著細綱就翻細綱；這一份沒改過就在原位置換掉，改過了就另開一個標籤（改的東西一個字不動）。右邊那一塊正開著這一章的細綱（或正文）的話，它也跟著翻，游標還留在你按鍵的那一塊。相鄰那一章還沒寫正文、或者還沒排細綱時，會直接告訴你，不會開啟一個不存在的檔案。
- **Markdown 預覽**：`.md` 檔案的工具欄上有「預覽」（或按 `Ctrl` + `Shift` + `V`），再按一下回到編輯；frontmatter 單獨框出來，不混進正文。**每個標籤各記各的**：切到別的標籤再切回來，原來在預覽裡的還在預覽裡（滾到哪也記著），重新整理頁面之後也一樣。切換時兩邊滾到同一處——編輯區頂上那一行，在預覽裡對應的那一段停在頂上，反過來也一樣；切回編輯時游標要是已經不在眼前，就放到眼前第一行的行首，免得一打字又跳回原處。`.txt` 章節沒有 Markdown 可預覽，按鈕不出現，`Ctrl` + `Shift` + `V` 照常是貼上。

#### 寫

- **撤銷 / 重做**：`Ctrl` + `Z` 撤銷，`Ctrl` + `Y` 或 `Ctrl` + `Shift` + `Z` 重做（「編輯」選單裡的也一樣）。每個開啟的檔案各記各的，切到別的標籤再切回來照樣退得回去；關掉標籤或重新整理頁面之後從頭記。一口氣打的字算一步，回車另起一步；用輸入法打字時，一次上屏算一步。編輯器替你做的改動——排版、替換、名詞補全、「還原」、「用磁碟版本覆蓋編輯器」、磁碟上同步進來的新版——也都能一下撤銷。
- **`Tab` 縮排**：正文（章節與草稿）一級是兩個全形空格，角色卡、細綱、設定這些是兩個半形空格。沒選中時在游標處插一級；選中幾行（哪怕只選了一行裡的幾個字）按 `Tab`，每行行首加一級，選中的字不會被替換掉；`Shift` + `Tab` 去掉一級。
- **輸入法優先**：用輸入法打字、拼音還沒上屏時，`Tab`、回車、方向鍵和各種 `Ctrl` 組合鍵都照常交給輸入法，編輯器一個都不搶。

#### 段落與標點

這幾樣裡說的「正文」指章節與草稿；角色卡、細綱、設定這些不算。

- **分段格式**是整本書的設定，三選一：**空行分段**（段與段之間空一行、段首不縮排，網文常見，也是預設）、**段首縮排**（段首兩個全形空格、段與段之間不空行，出版常見）、**縮排加空行**（兩樣都要）。在「編輯 → 段落格式」裡切，當前那項打著 ✓；它記在 `.novelwarden/config.md` 開頭的 `paragraphStyle` 一行（寫 `blank` / `indent` / `both`，或者直接寫中文「空行分段」「段首縮排」「縮排加空行」都認）。切換隻改這一行，已經寫好的正文一個字不動——想把它們排成新格式，用下面的「一鍵排版」。
- **回車**按分段格式另起一段：空行分段就空一行，段首縮排就換行再縮排兩格。游標後面跟著的空格會順手刪掉；在只有空白的行上回車只換行、不縮排（連按回車不會堆出一串縮排行）；在段首回車是把這一段整個往下推一行。`Shift` + `回車` 只換行、不縮排——寫詩、寫信、短句一行一行排時用。角色卡這些 Markdown 裡回車沿用上一行的縮排，列表（`- `、`* `、`1. `）會接著往下寫，在空的列表項上回車就結束列表。
- **段落快捷鍵**（所有檔案都能用，空行不算一段；每個都能一下撤銷）：
  - `Alt` + `↑` / `↓`：游標所在這一段（選中了就是選中的那幾行）與上 / 下一段對調，中間的空行不動
  - `Shift` + `Alt` + `↓` / `↑`：把這一段複製一份放在下面 / 上面（正文按分段格式隔開）
  - `Ctrl` + `Shift` + `K`：刪掉這一段（空行分段時連帶刪掉多出來的那個空行）
  - `Ctrl` + `回車`：不管游標在這一段的哪裡，都在它下面另起一段
- **成對符號**：打出 “ ‘ 「 『 （ 《 【 〈 的左半邊，右半邊自動補上，游標停在中間；選中一段字再打左半邊，就把這段字包起來。緊挨著自動補上的右半邊再打一次右半邊會直接跳過去，不會多出一個（輸入法常常自己交替出 “ ”，這樣正好對得上）；剛補完還沒打字就退格，左右一起刪。只在游標後面是行尾、空白或標點時才補——後面緊跟著正文時補了反而要回頭刪。半形括號不補。不想要可以在「編輯 → 成對符號自動補全」關掉（記在瀏覽器裡，不進工程）。
- **一鍵排版**：工具欄「排版」按鈕（只在正文上出現，挨著「預覽」），或者「編輯 → 一鍵排版」。按這本書的分段格式把正文重排一遍：每個非空行是一段，去掉首尾多餘的空格（半形、全形、製表符都算），段首該縮排就縮排，段與段之間原來空了幾行都收成一種；`#` 開頭的標題行和只有符號的分隔行（`* * *`、`※`、`◇◇◇`……）不縮排；開頭的 frontmatter 原樣留著。選中了幾行就只排這幾行，否則排整章。做完會說改了幾處，一下撤銷就回去。
- **半形標點轉全形**：「編輯 → 半形標點轉全形」。只在中文裡轉——前一個字是漢字或中文標點時，`,` `.` `?` `!` `:` `;` 換成全形；`3.14`、`1,000`、英文句子、`config.md` 這種檔名、網址、程式碼都不碰。`...` 和 `。。。` 換成 `……`，漢字之間的 `--` 換成 `——`，括號裡有漢字（或者像 `(1)第一條` 這樣挨著漢字）時一對一起換成全形；直雙引號只在同一行裡成對、中間有漢字時才換成 “”，單引號不動（英文的 `don't` 會把配對攪亂）。同樣是選中幾行就只轉這幾行。

<a id="章节草稿"></a>
#### 章節草稿

每一章都可以有一塊**和正文並排的塗改區**：放廢棄的段落、備選的寫法、給自己的批註。草稿是普通文字檔案，跟著工程走、可 Git、可手改，和別的東西一樣。

在章節上右鍵點「新建草稿」（已有草稿時顯示「開啟草稿」），或者在內建編輯器裡開啟正文後點工具欄的「草稿」按鈕。**首次點的時候才建立**——不會給一個已經二百章的工程憑空撒二百個空檔案。

草稿存在工程根的 `drafts/` 下，路徑映象章節在 `chapters/` 之下的那一段，檔名（含副檔名）原樣沿用：

```
chapters/001-楔子.md        →  drafts/001-楔子.md
chapters/第二卷/003-夜访.md  →  drafts/第二卷/003-夜访.md
chapters/005-手记.txt       →  drafts/005-手记.txt
```

幾條要記住的：

- **草稿不進 LLM 上下文。** 裝配器任何階段都不讀它——想讓模型看見，就在 `@ 引用` 裡手動挑（草稿單列一組，只列已經建過的）。
- **絕不覆蓋。** 第二次點「開啟草稿」只是開啟，不會把你寫的東西換成模板。
- **草稿跟著章節走。** 章節改名或移動，草稿一併搬過去；如果新位置已經有草稿了，兩份都留著並提示你自己去合。
- **刪章節不刪草稿。** 確認框裡會說明草稿留在哪兒。
- 草稿**不是**可管理區：它不出現在工程頁的樹上，也不能在介面上重新命名/移動/刪除——它的位置由章節路徑推導，直接改它只會讓下次點「開啟草稿」建出一個新的空檔案。要清理就在檔案管理器裡刪。
- 草稿字數不計入章節字數，也不影響同步狀態。

#### 檔案頁（資源管理器）

活動欄第三個頁籤，獨立版專屬——外掛形態裡這件事由 VS Code 自己的資源管理器承擔。

它列的是**工程目錄的原樣結構**，與「工程」頁那個整理過的檢視不同：這裡一個檔案都不藏，**包括 `.novelwarden/` 這類點開頭的資料夾**。細綱與全文大綱（`summaries/`）、會話記錄（`sessions/`）、歷史版本（`history/`）、`project.json`、`style.md` 都在裡面——會話、`project.json` 這類工程頁上不列的檔案，想手改只有這裡。

- 點資料夾展開/摺疊，按需載入（幾百章的工程不會一進來就掃全盤）；展開狀態記在瀏覽器裡，重新整理後還在
- 單擊文字檔案在右側編輯器裡開成**臨時標籤**（見下面「內建編輯器」），雙擊開成正常標籤；圖片、壓縮包這類打不開的檔名字置灰，點了交系統預設程式
- 編輯器裡當前編輯的那個檔案在樹上高亮，工具欄的 ◎ 可以定位到它；在編輯器裡點路徑上的某一級目錄、或在標籤上右鍵「在檔案頁中定位」，會切到這一頁、展開到它，並用虛線框標出那一行
- 右鍵：展開/摺疊、在系統中開啟、複製相對路徑

這一頁**只看不改**：新建、改名、刪除仍然在「工程」頁做（那裡的操作鎖在章節/角色/設定三個區內，刪除也是搬進回收站而非真刪）。

### 查詢、儲存與版本

#### 查詢替換

在**這一份檔案**裡找；要在整本書裡找，用下面的[全書查詢替換](#全書查詢替換)。

- `Ctrl` + `F` 開啟查詢條（選中了一行之內的幾個字時直接填進去），`Ctrl` + `H` 連替換那一行一起開啟；「編輯」選單裡也有「查詢」「替換」。每塊編輯區各有一條，只找這一塊裡當前的檔案
- 邊打字邊從游標往後找，所有找到的地方都標上底色，當前這一處顏色更深，條上寫著「第幾處 / 一共幾處」
- `Enter` 或 `F3` 下一處，`Shift` + `Enter` 或 `Shift` + `F3` 上一處，到頭了繞回來；`Esc` 關掉，游標回到正文裡剛找到的那一處
- 「Aa」區分大小寫，「.*」按正規表示式找（寫錯了條上會說一句）；按正則替換時可以用 `$1`、`$2` 引用括號裡的那一段
- 「替換」換掉當前這一處、跳到下一處（游標還不在某一處上時，第一下只是選中它，看清了再按）；在替換框裡按 `Enter` 也一樣。「全部替換」一次換完並告訴你換了幾處，`Ctrl` + `Z` 一下全部退回
- 焦點在左側對話輸入框裡時，`Ctrl` + `F` 還是瀏覽器自己的查詢；在預覽裡按會先切回編輯。超過 30 萬字的檔案照樣能查能換，只是不畫底色

<a id="全书查找替换"></a>
#### 全書查詢替換

`Ctrl` + `Shift` + `F`，或「編輯 → 全書查詢替換…」；`Ctrl` + `Shift` + `H` 直接把游標放進替換框。在整本書裡一起找、一起換，比如「把人名林晚全書改成林婉」。面板佔的是左邊側欄的位置（和 VS Code 的「搜尋」一樣），右邊的正文一點都不擋；點左邊活動欄上任一頁籤、面板上的 ×、或按 `Esc` 收起，結果留著，再開啟還在。

- **找**：打字停一下就開始搜；「Aa」「.*」兩顆開關和單個檔案的查詢條是同一套（正則裡也能用 `$1`）。下面一排勾選**在哪找**：正文（預設只勾這一項）、細綱、草稿、角色卡、設定條目、其他創作檔案（情節大綱、小說配置、故事前提、世界觀、文風指南、敘事線、全文大綱）。編輯區裡選著一行之內的幾個字時按 `Ctrl` + `Shift` + `F`，直接拿它來搜
- **結果**按正文、細綱……分組，一份檔案一行：「第 3 章 夜訪」「細綱 · 第 3 章 夜訪」「角色 · 林晚」這樣的稱呼和一共幾處，下面每一處一行上下文，找到的字標著顏色。點一處就在右邊開啟那份檔案、選中那幾個字（那份檔案的查詢條也亮著同一個詞，`F3` 接著往下跳）；點檔案那一行收起 / 展開
- **搜的是磁碟上存著的內容**：編輯器裡改了還沒儲存的檔案，結果上標著「未儲存」——列的是磁碟上那一份，替換時也會跳過它
- 一次最多列 1000 處，多了會說「只列了前 1000 處」、搜到哪一份就停了；多打幾個字縮小範圍。超過 2 MB 的檔案不搜，也會說出來。搜得慢的時候點「停止」
- **換**：填好替換框，點「**預覽替換**」——每一處都畫成「舊的劃掉、新的跟在後面」，每一處、每個檔案前面都有勾，預設全勾；「林晚霞」這種不該換的就勾掉。確認之後點「**替換所選**」，按鈕先變成「再點一下：替換 N 個檔案 M 處」，再點一下才真的換
- 換完會告訴你**換了幾個檔案幾處、跳過了哪些、為什麼**：編輯器裡改了沒儲存的跳過（先儲存或放棄修改，再換一次）；預覽之後在別處改過的跳過（不會拿預覽時的內容蓋掉新改的），重新預覽一次就行。然後自動再搜一遍，列出還剩下的
- **每個改過的檔案都可以在「版本」裡找回替換前那一版**（開啟那份檔案，點工具欄上的「歷史」或活動欄的「版本」）——換之前每一份都先存了一版。跨好幾個檔案的替換**沒有一步撤銷**，歷史版本就是退路。已經開在編輯器裡、沒改過的標籤會自動換成新內容
- **不會動的東西**：細綱、角色卡、設定開頭那段 frontmatter 里程式自己記的賬（指紋、章號、字數、狀態……）不搜也不換——搜「3」換成「三」不會把它們弄壞；名字、別名、標題、出場人物照樣換。細綱的「關鍵事件」、角色卡的「當前狀態」這些小節的**標題行**也不換（換了程式就認不出那一節了），情節大綱裡「第1–5章」那一截同理
- **會不會讓章節掛 ⟳**：細綱和正文在同一次替換裡**都**改了（全書改名就是這樣），那一章不會因此掛 ⟳、同步過的也不會退回「待同步」；只改了細綱、正文沒跟著改的，正文會掛 ⟳；只改了正文、細綱沒跟著改的同步過的章，回到「待同步」；改了大綱、細綱沒跟著改的，細綱掛 ⟳——這幾種換完都會在彙總裡列出是哪幾章
- **角色改名**：角色卡裡的名字或別名換了，檔名不會跟著改（`林晚.md` 還叫 `林晚.md`）——認人看的是卡裡的名字和別名，不看檔名；彙總裡會提一句，想改檔名就在工程頁右鍵「重新命名」。出場統計、設定名錄這些會按新的名字重新算

<a id="保存冲突与历史版本"></a>
#### 儲存、衝突與歷史版本

- **儲存**：`Ctrl` + `S`（或工具欄「儲存」、「檔案 → 儲存」），存的是有焦點那一塊的當前檔案；「檔案 → 全部儲存」存所有改過的。工具欄「還原」丟棄修改、重新讀盤（有修改時先問一句，放棄之後還能 `Ctrl` + `Z` 撤銷回來）。
- **儲存狀態看狀態列**：右下角那一格寫著「● 未儲存」→「儲存中…」→「已儲存 14:32」（這次開啟頁面以來最後一次存成的時刻）。存成了不彈提示條；撞上衝突、出錯照樣彈。點了儲存 10 秒還沒回音（多半是和伺服器斷線了，頁面頂上會出現紅色的重連條），這一格會說「還沒收到迴音，連上後會自動發出」——編輯器裡的內容一直都在，連上之後那次儲存自動發出去，整個頁面的狀態也會重放一遍。
- **自動儲存**（預設關）：「檔案 → 自動儲存」，開著時打 ✓，狀態列上多一枚「自動儲存」。開著時：停筆 2 秒（用輸入法打字、拼音還沒上屏不算停筆）就存當前這一份；切到別的標籤時存剛離開的那一份；切到別的視窗、或者把瀏覽器頁籤藏到後面時，所有改過的都存。這個開關記在瀏覽器裡，不進工程。
  - 它照樣帶著「磁碟上是不是還是那一份」的核對：撞上衝突就**停下這一份的自動儲存**（那一枚寫「自動儲存已暫停」），等你在衝突條上選了再接著存，絕不替你強制覆蓋；磁碟上已經沒有了的檔案也不替你重建
  - **注意**：正文一儲存，已經同步的章就會回到「待同步」（同步記的是正文的指紋）。開著自動儲存時，在同步過的章裡改一個字，停筆兩秒它就回到「待同步」了——想先改著看看、不急著動同步狀態的話，先把自動儲存關掉
- **關標籤時問一句**：有未儲存修改的標籤關掉之前（標籤上的 ×、中鍵、`Ctrl` + `W`、「檔案 → 關閉編輯器」），會問「儲存 / 不儲存 / 取消」。選「儲存」要等這一份真的存成了才關；撞上衝突、出錯就不關，衝突條留著讓你取捨。一次關好幾個（右鍵「關閉其它 / 左側 / 右側」）時，沒儲存的那幾份合在一個對話方塊裡問一次，列出是哪幾份：「全部儲存 / 全部不儲存 / 取消」。對話方塊裡 `Enter` 選主按鈕，`Esc` 取消。`Ctrl` + `W` 在瀏覽器裡多半被瀏覽器拿去關整個網頁（有沒儲存的內容時瀏覽器會先問），桌面版裡才是關標籤。
- **重新整理與離開頁面**：重新整理頁面不丟未儲存的修改（存在瀏覽器本地；磁碟上的內容變過就丟棄並提示，不拿舊的蓋新的）。帶著未儲存內容關掉瀏覽器頁籤或重新整理時，瀏覽器會先問一句。
- **磁碟上的改動會同步進來**：同步寫回細綱、批次寫章、外部 agent 改了檔案、你在別的編輯器或 git 裡動了檔案，開著的標籤會跟著變——
  - 沒改過的標籤：直接換成磁碟上的新版，不切標籤、不搶游標；正看著的那一份狀態列會說「磁碟上有新版本，已載入」，`Ctrl` + `Z` 可以退回換之前的樣子
  - 改過的標籤：你的修改一個字不動，標籤上掛一個「!」，切過去能看到衝突條，處理辦法見下一條
  - 磁碟上已經沒有了（被刪、被改名）：標籤名劃掉、掛紅色「!」，衝突條上說「磁碟上已經沒有這個檔案」。編輯器裡的內容還在；這時按儲存，會先問你要不要在原路徑重新建一份（如果是在別處改了名，新名字那邊已經有一份，重建會多出一份）
  - 什麼時候查：每次磁碟上有變動、以及你切回這個視窗的時候
- **不靜默覆蓋**：儲存帶內容指紋的樂觀鎖。檔案在你編輯期間被別處改過（你在別的編輯器裡改了、或者外掛寫入了內容），儲存會被拒絕，衝突條上給三個選擇——**「對比合併…」**（排在第一個）：左邊磁碟上的、右邊編輯器裡的，逐處挑用哪邊、結果格可以手改，點「放回編輯器」之後編輯區換成挑出來的那一份（一下撤銷就回去），衝突條收起；這時它仍是未儲存的，照常 `Ctrl` + `S` 就行，不必強制儲存（開著自動儲存的話，因為撞衝突停下的自動儲存也接著走；之後磁碟上再變，照樣會提醒你）。或者整份二選一：「用磁碟版本覆蓋編輯器」「用編輯器內容強制儲存」（還會再確認一次）。磁碟上已經沒有這個檔案時沒有可合併的，「對比合併…」不出現。同一個工程開在兩個瀏覽器視窗裡、兩邊都在改同一份檔案時也一樣：一邊存了，另一邊改過的標籤掛衝突條，不會拿著舊的那份把它蓋掉。
- **歷史版本**：每次覆蓋一份已有的稿子之前——編輯器裡儲存、重寫或修稿落盤、同步寫回細綱、全書替換、外部 agent 的 `edit`——磁碟上的舊內容會先存成一版，放在 `.novelwarden/history/` 裡（見[目錄結構](#目錄結構)）。左邊活動欄的「**版本**」（或工具欄「歷史」、「檔案 → 歷史版本…」）列出編輯區當前這份檔案的時間線，新的在前：
  - 最上面「**還沒儲存的改動**」（編輯器裡改了還沒存時才有）；然後是存下的各版（「3 分鐘前 · 14:32」、多少字、比現在多或少幾個字），和這份檔案在各[存檔點](#存檔點)裡的樣子（◆ 手動、◇ 自動，帶備註；幾個存檔點裡它一字沒動就只列一次）
  - **點一行，編輯區裡馬上開「對比」標籤**：左邊那一版、右邊現在（編輯器裡的，沒儲存的也算），按段比，一段裡改了哪幾個字也標出來（刪的紅、加的綠）；沒改的段落折起來，點開再看。頂上「上一處 / 下一處」跳著看；只差縮排、空行時會照實說「只有空白不同」。對比標籤只有一個，點別的一行就換內容；關掉它回到那份檔案
  - 每處改動旁邊「**用回這一處**」把編輯區裡那一處換回左邊那樣；頂上「**恢復整份**」把編輯區整個換成那一版。都**不寫盤**：換進來之後是未儲存的，一下撤銷就回去，存不存由你。放回之前，磁碟上現在那一份會先存成一版（與最近一版一樣就不重複存），所以放回的內容存下去之後，被它蓋掉的那一版照樣在列表裡。**開著自動儲存時，放回的內容會很快寫回磁碟**——停筆 2 秒就存；存之前那一版已經進了歷史，可以再恢復回來
  - 右鍵一行：「跟後一版比」看那一次改了什麼（兩邊都是存下的，只能看）；「恢復整份到編輯區」
  - 「版本」頁**最上面是「全書改動」**（像 VS Code 的「原始碼管理」）：跟一個[存檔點](#存檔點)比，之後全書改過、新建、刪掉的檔案按章節 / 細綱 / 角色卡 / 設定……分組列出來，帶字數差。預設跟最近一個**手動**存的存檔點比（自動的在批次動作之前都存，太密），下拉可以換。點一份同樣在編輯區開對比標籤（沒開著的先開成臨時標籤）；之後刪掉的只能看。存檔之後列表跟著變。退回不在這裡——要整份退回去，用存檔點彈窗
  - 「**＋**」（現在存一版）把磁碟上**現在**這一份先存下來（編輯器裡還沒儲存的修改不在裡面——要留住它們，儲存就行，儲存時被覆蓋的舊內容同樣會存一版）
  - 只給工程裡的稿子存：章節、草稿、細綱、角色卡、設定、架構三件、文風、敘事線、全文大綱、敏感詞表；工程根下的隨手記、`README` 這些不存，「歷史」按鈕也是灰的
  - 不會存出幾百份：與最近一版一字不差的不存；最近一版不到 10 分鐘、而且這次只是零星小改（300 字以內）的也不存——所以自動儲存、邊寫邊存都只會隔一陣子留一版；整章重寫、修稿、一鍵排版、同步這種大改總是存。每份檔案最多留最近 50 版，再多就刪掉最舊的——這些是程式自己另存的副本，不是你的檔案，刪它們和「刪除一律進回收站」那條不衝突（你的檔案一個位元組都沒動）
  - 第一次存的時候會在 `.novelwarden/history/` 裡放一個 `.gitignore`（內容是 `*`），Git 預設不收這些快照；想連歷史版本一起提交，刪掉它就行，之後不會再補回來
  - 存快照出了問題（磁碟滿了之類）只記一條日誌，儲存照常進行
  - 外掛版沒有「版本」這一頁，但快照照樣會存：在 VS Code 的資源管理器裡開啟 `.novelwarden/history/<那份文件的路径>/` 就能看到按時間命名的各版

<a id="存档点"></a>
#### 存檔點

工程頁頂上頁籤條最右邊、重新整理旁邊的 ⚑（獨立版也可以從「檔案 → 存檔點…」開啟）管**整本書**的版本：把某一刻全書的樣子存成一個點，之後隨時看跟現在比改了什麼，整本或單份退回去。[歷史版本](#儲存衝突與歷史版本)管的是一份檔案被覆蓋之前的那一版；批次寫了二十章、全書替換改了幾十份，一份一份找回去不現實，就用存檔點。

- **存**：彈窗上面寫一句備註（可以空著，比如「第一卷寫完」），點「存一個存檔點」。**批次動作之前會自動存一個**——批次寫章、補齊架構、拆細綱、全書替換、按目錄整理設定、批次展開設定、匯入原稿、從已寫正文補齊、立即同步、從正文補記敘事線、補推 / 重推故事時間，你點了「開始」之後、第一個檔案寫下去之前。跟最近一個存檔點一模一樣時不另存。自動存不下（比如磁碟滿了）只在日誌裡記一條，不擋那個批次動作。
- **存了什麼**：章節、草稿、細綱、角色卡、設定、架構、文風、敘事線、全文大綱、寫作技能、敏感詞表（與歷史版本同一批）；會話、日誌庫、回收站、歷史版本不存。單份超過 2 MB 的不存，列表上會說。**同樣的內容只存一份**：第二個存檔點只多存這期間改過的那幾份，存幾十個也佔不了多少地方。
- **看**：一個存檔點一行——時間、手動還是自動、備註、那時正文幾章多少字。點「跟現在比」分三組列出**改過的**、**之後刪掉的**、**之後新建的**，每份帶當時與現在的字數。獨立版與桌面版每份還有「對比」：彈窗關掉，編輯區裡開「對比」標籤，左邊存檔點裡的、右邊現在的，可以一處一處用回（只進編輯區，存不存由你，同[歷史版本](#儲存衝突與歷史版本)；外掛版沒有這一項）。平時不想開彈窗，左邊活動欄「版本」頁最上面的「全書改動」就是跟存檔點比的結果。
- **退回**：「退回這一份」，或底部的「整本退回」，都要點兩下。退回之前**先自動存一個「退回到 … 之前」**——退回本身也能撤回；被蓋掉的每一份另外也在它自己的「歷史」裡留了一版。存檔點之後新建的檔案預設不動，勾上「也把存檔點之後新建的 N 份搬進回收站」才搬（進 `.trash/`，不真刪）。編輯器裡有沒儲存修改的檔案、彈窗開啟之後別處又改過的檔案會跳過，提示裡逐份說出來。有任務在跑時（比如批次寫章還沒寫完）不讓退回。
- **退回是原樣的**：每份檔案一個位元組不差地回到當時，細綱裡記的指紋也一起回到當時——整本退回之後，哪章待寫、哪章掛 ⟳，都和那時一模一樣。只退回一份細綱、正文沒跟著退時，那一章可能顯示「同步之後正文改過」，那是實情。
- **留多少**：手動存的一直留著；自動存的只留最近 30 個，更早的自動刪掉。想留住某個自動存檔點，點「留住…」寫一句備註，它就變成手動的。
- 存檔點在 `.novelwarden/checkpoints/` 裡（第一次存時放一個 `.gitignore`，內容是 `*`，Git 預設不收）。裡面是一堆按內容指紋命名的檔案，不是給人直接看的，要看、要找回都走這個彈窗。**和 Git 不衝突**：Novelwarden 不碰 `.git`，你照樣可以用 Git 同步、備份整個工程。

### 外觀、統計與體檢

#### 外觀與專注

標題欄「檢視」選單裡的「外觀」「專注」兩組。這些設定都記在瀏覽器裡，不進工程，換一本書也還是這樣。

- **字號**：游標在編輯區裡時按 `Ctrl` + `=` 放大、`Ctrl` + `-` 縮小、`Ctrl` + `0` 還原（預設 15，最小 12、最大 32）；「檢視 → 放大字號 / 縮小字號 / 還原字號」也一樣。游標在別處（左邊的對話方塊、頁面空白處）時這幾個鍵還是瀏覽器自己的整頁縮放。
- **外觀設定**：「檢視 → 外觀設定…」在右上角開一個小面板，改了當場就能看見，不用點確定：
  - **正文字型**：宋體（預設）、黑體、楷體、仿宋、跟隨系統。用的是你電腦上裝的字型——沒裝的會退回到同類的字型（裝了「霞鶩文楷」的話，楷體用的就是它）
  - **字號**、**行距**（拖滑塊）
  - **版心寬度**：一行最多放多少字（30 / 35 / 40 / 45 / 50 / 60 / 70 字），螢幕寬的時候那一欄放在中間，讀起來不用左右甩頭；「鋪滿」（預設）就是佔滿編輯區。預覽也跟著同一套字型、字號、行距和版心
  - **主題**：深色、淺色、護眼。護眼是米黃底、深棕字，整個介面一起換（標題欄右上角那顆按鈕也能切，按一下換下一套：深色 → 淺色 → 護眼）
  - 沒有單獨的「段間距」：空行分段時段與段之間就是那一行空行（跟著行距變），段首縮排的格式本來就不空行
  - 「恢復預設」把字型、字號、行距、版心放回預設，主題不動。`Esc` 或「關閉」收起面板
- **專注模式**（`F8`，或「檢視 → 專注模式」）：只留正文——左邊的側欄、標籤條、工具欄、章節條都藏起來，底下的狀態列淡成一行（滑鼠移上去才看清；字數那一格照樣點得開碼字統計），標題欄只剩選單。左右兩塊編輯區都開著時只專注你正在寫的那一塊。衝突提醒、查詢條、對比標籤、全書查詢替換照樣會出來。`Esc` 或再按 `F8` 出來（碼字統計、外觀面板、查詢條這些開著時，`Esc` 先收它們）；重新整理頁面後還在專注模式裡。
- **全屏**：「檢視 → 全屏」，整個頁面佔滿螢幕，`Esc` 退出（瀏覽器自己的 `F11` 也行）。瀏覽器不支援時這一項是灰的。桌面版在 Linux 上是真的全屏；在 Windows 上目前只是把頁面撐滿視窗、視窗本身不會變成全屏，那時用視窗的「最大化」加專注模式代替。
- **打字機滾動**（「檢視 → 打字機滾動」）：游標所在那一行始終停在編輯區中間附近——打字、回車、方向鍵移動之後自動滾過去，寫到最後一行也一樣，眼睛不用一直往螢幕底下追。用輸入法打字時等字上屏了才滾；用滑鼠滾輪往上翻看前文時不會把你拽回來，接著打字才回到游標那裡。
- **段落聚焦**（「檢視 → 段落聚焦」）：正文裡游標所在的那一段照常顯示，其餘的段落變淡。按這本書的分段格式認哪裡是一段：空行分段就是空行隔開的一塊，段首縮排就是從有縮排的那一行起。只對正文（章節與草稿）起作用；超過 30 萬字的檔案不做（整篇照常顯示）。

#### 碼字統計

底部狀態列從左到右是：檔名、字數、寫作體檢（見下一節）、行列位置（在預覽裡寫「預覽」）、儲存狀態。字數那一格就是碼字統計：

- 平時寫「全文 3,120 字」；選中一段時寫「選中 120 字 / 全文 3,120 字」。數法與工程頁一樣：中文一個字算一個，英文一個詞算一個，標點和空白不算；章節開頭那行 `# 標題` 也不算。字元數（連標點空白一起）在滑鼠停上去的提示裡
- 開著某一章的**正文**時，寫成「3,120 / 4,000 字，還差 880」，後面一條細細的進度條，寫到八成換成綠色（這一章算寫夠了的線），超了就寫「超出 120」。目標就是寫正文時用的那個數：細綱裡寫的目標字數，沒寫就是小說配置裡的每章字數，兩樣都沒有就不顯示。字數跟著你打字當場變，不用先儲存。細綱、草稿、角色卡這些不顯示目標
- **點一下這一格**彈出碼字統計：本章字數與目標、**本次碼字**（從開啟這個頁面起你碼了多少字、寫了多久、每小時多少字）、**今日碼字**（這本書今天一共碼了多少）、本次按檔案分開的明細，還有「重新開始計時」。`Esc` 或點別處收起
- **怎麼才算碼字**：只算你親手打的字——鍵盤打的、輸入法上屏的、名詞補全裡挑了補上的都算，退格刪掉的會扣回去；貼上、一鍵排版、查詢替換、對比合併、恢復歷史版本、磁碟上同步進來的新內容都不算。撤銷跟著那一步走：撤銷自己剛打的字，那幾個字就扣回去；撤銷一次貼上，碼字數不動
- **時長只算在寫的時候**：停筆超過 2 分鐘，中間那段不計時，去倒杯水回來速度不會被拉低。寫夠 1 分鐘才報速度
- **今日碼字**記在瀏覽器裡（每本書各記各的），重新整理頁面、同時開好幾個視窗都接著累計，不會重複算，也不會互相蓋掉；過了半夜就從零開始算新的一天。它不往工程目錄裡寫——換一臺電腦、清了瀏覽器資料就沒了。瀏覽器不讓記的時候只算這一頁
- 「檢視 → 統計」裡選狀態列上還顯示哪幾項：「距目標」（預設開）、「本次碼字」「今日碼字」（預設關），開著時字數後面跟著「· 本次 +356 字 · 今日 1,820 字」；「檢視 → 重新開始計時」讓本次碼字從現在起重新算（今日的不受影響）。這幾個開關記在瀏覽器裡，不進工程

#### 寫作體檢與名詞補全

**寫作體檢**（只看正文：章節與草稿）：寫的時候把這本書不該用的詞直接標在正文裡，狀態列上一格告訴你一共幾處。**不調模型、不花錢**，只是按詞表在正文裡找字，也不會替你改字。

- **標出來的四樣**，樣子各不相同（深色、淺色、護眼三套主題下都看得清）：
  - **敏感詞**（實線下劃線加一層淡底色）：你自己的敏感詞表裡的詞，見下面。英文不分大小寫
  - **禁用詞**（紅色波浪線）：文風指南里「禁用詞表」那一節括起來的詞、小說配置「全域要求」裡寫著禁止的詞、古代 / 修真這類題材裡不該出現的現代說法（能量、神經、頻率……）——**與寫正文時模型寫完之後數的是同一份**，在這裡標出來的，就是生成時會提醒你「用到了這本書不該用的詞」的那幾個
  - **比喻詞**（黃色波浪線）：「彷彿」「猶如」「宛如」「如同」……全章合計超過 3 次（寫正文時給模型定的上限）才標，沒超不標
  - **英文縮寫**（藍色點線）：PTSD、CPU 這種兩個以上大寫字母的縮寫，只是提醒——都市、科幻裡的 CEO、AI 是正常的，故事的年代用不上才改
- **狀態列「體檢」那一格**：「體檢 3」是一共 3 處（比喻詞算超出的那幾個），沒問題時寫「體檢 ✓」；開著的不是正文時不顯示。點一下彈出體檢面板：按類列出命中的詞和次數，**點一個詞就跳到它在正文裡的位置並選中**，再點跳到下一處（面板上寫著「2/5」），到底了從頭再來。`Esc` 或點別處收起
- 打字時當場跟著變；幾萬字的章節也不卡（兩萬字以上隔一小會兒才重查一次，已經標著的會跟著字挪）。用輸入法打字、拼音還沒上屏的時候不查——拼音字母不會被當成英文敏感詞
- 「檢視」選單「統計」後面那一組：「**體檢高亮**」（預設開，關掉之後正文裡不畫，狀態列那一格照樣數）、「**狀態列顯示體檢**」（預設開）、「**編輯敏感詞表…**」。兩個開關記在瀏覽器裡，不進工程
- 與查詢、段落聚焦同時開著時互不干擾：查詢畫的是底色，體檢畫的是下劃線，段落聚焦管的是字的深淺。超過 30 萬字的檔案不畫（面板裡照樣數、照樣跳）

**敏感詞表**：釋出平臺不讓出現的詞，你自己維護，放在 `.novelwarden/sensitive.txt`。體檢面板底下或「檢視 → 編輯敏感詞表…」開啟它——還沒有的話先建一份帶說明的模板（不會蓋掉已有的）。格式：

```text
# 井號開頭的行是註釋，空行不算
某平臺
賭博 => 博戲
Free Money
```

- 一行一個詞；`詞 => 替換詞` 給出建議的替換（只認半形的 `=>`）。英文不分大小寫，全形字母當半形
- 有替換詞的，體檢面板裡那一行多兩顆按鈕：「**替換本處**」換掉選中的那一處、接著選中下一處（還沒選中時第一下只是選中，看清了再按）；「**全部替換**」把這份檔案裡的都換掉。兩樣都只改編輯區裡這一份、一下 `Ctrl` + `Z` 就退回，存不存由你；不動別的檔案
- 寫錯的行（`=>` 前面沒有詞、後面沒有替換詞、一行兩個 `=>`、一個詞超過 32 個字、和前面某一行重複）會跳過，不報錯，面板裡會說「第 N 行沒看懂」，滑鼠停上去看為什麼
- 儲存它和儲存別的檔案一樣（會留歷史版本）；存了之後體檢馬上按新詞表標
- **現在只用於編輯器裡的體檢**：寫正文時模型看不到這份詞表，也不會替你避開它們；它也不在細綱、正文的指紋鏈上，改了它不會讓任何一章掛 ⟳

**名詞補全**（`Alt` + `/`，或「檢視 → 名詞補全」）：寫到角色名、地名、門派、法寶這些名字時按一下，游標下面彈出一個小框，挑一個就補上，不用每次都把「太上忘情訣」打全，也不怕把「沈懷山」打成「沈懷珊」。

- **名字從哪來**：角色卡的名字和別名、設定條目的標題和關鍵詞，還有設定名錄裡「出現過 · 未建條目」的那些名字。不調模型、不花錢。新建或改了角色卡、設定，下一次彈出來就是新的
- **列哪些**：游標前已經打了幾個字（比如「沈懷」），就只列以它開頭的名字；什麼都沒打、或者打的字對不上任何名字時，列出全部，**這一章裡剛出現過的排在最前面**
- 每一行寫著名字（打過的字標了顏色）、型別（角色，或者設定所在的目錄：地點、門派、物品……）和卡或條目裡那一句簡介。對上的是別名時寫成「老沈 → 沈懷山」，選它插進去的是「老沈」——你打的就是這個叫法
- `↑` `↓` 選，`回車` 或 `Tab` 插入：已經打的那幾個字換成整個名字，游標停在名字後面，`Ctrl` + `Z` 一下就撤回。`Esc` 收起。框開著時接著打字它會跟著篩；打了標點、點了別處、切了標籤、滾動頁面時收起
- **邊打邊彈**（預設關）：「檢視 → 邊打邊彈名詞補全」打上勾以後不用按鍵——打出某個名字的**頭兩個字**、還沒打完整時，框自己彈出來。這時**回車照常換段**（框順手收起），要插入名字按 `Tab`；接著打別的字它就自己收起。名字已經打完整了、只打了一個字時不彈（不然「林」「沈」這種常用字一打就彈）。這個開關記在瀏覽器裡，不進工程
- 用輸入法打字、拼音還沒上屏時不彈，也不搶任何鍵
- 只在正文、草稿、細綱、角色卡、設定條目、情節大綱和敘事線裡有；小說配置、故事前提、世界觀、文風、敏感詞表這些不彈
- 補全插進去的字算你碼的字（「本次 / 今日碼字」照算），撤銷了就扣回去

**名詞高亮**（預設開，「檢視 → 名詞高亮」開關）：正文裡出現的角色名、設定名標出來，一眼看得出這一段提到了誰、哪裡。名字和名詞補全是同一份（角色卡的名字和別名、設定條目的標題和關鍵詞、設定名錄裡「出現過 · 未建條目」的名字），同樣不調模型。

- **怎麼標**：角色名一種淡底色，設定名另一種淡底色；名錄裡出現過、**還沒建條目**的名字畫一條虛下劃線——看到它就知道這個名字還沒有條目
- **滑鼠停在名字上**一會兒，旁邊彈出一個小框：名字、型別（角色，或者設定所在的目錄）、卡或條目裡那一句簡介；你寫的是別名時會說「這裡寫的是『阿昭』」。移開、打字、滾動就收起
- **`Ctrl` + 點選**名字（Mac 上是 `⌘` + 點選）：在這一塊編輯區開啟它的角色卡或設定條目。按住 `Ctrl` 指著能開啟的名字時，滑鼠變成手形。還沒建條目的名字沒有檔案可開，會提示一句
- 認名字的規矩：長的名字優先（「林昭陽」不會被認成「林昭」）；只有一個字的名字或別名不標（不然「道」「氣」這種設定會滿屏都是）；英文名要整個詞對上；角色卡、設定條目自己那一份裡不標它自己
- 和寫作體檢標在同一處時，體檢的下劃線照畫；和查詢的高亮疊在一起時，查詢的顏色蓋過它
- 只在正文、草稿、細綱、角色卡、設定條目、情節大綱和敘事線裡標，和名詞補全一樣；超過 30 萬字的檔案不標。新建或改了角色卡、設定，儲存之後就按新的標。這個開關記在瀏覽器裡，不進工程

#### 快捷鍵一覽

<a id="自动整理"></a>
## 自動整理

照正文把這本書整理成檔案，檔案跟著正文走。你只管寫（或者把寫好的稿子導進來），整理交給它。

### 整理出什麼

| 檔案 | 放在哪 | 裡面有什麼 |
|---|---|---|
| **每章細綱** | `.novelwarden/summaries/`，一章一份，路徑與正文一一對應 | 梗概、出場人物、時間地點、關鍵事件、看點、狀態變更、連續性事實（每條掛一句正文原話作證據），外加這一章出現了哪些設定 |
| **角色卡** | `.novelwarden/characters/` | 身份、外貌、性格、語言習慣、人物關係、當前狀態（寫著截至第幾章）、暗設（讀者還不知道的事）；在哪幾章出過場按細綱現算 |
| **設定** | `.novelwarden/lore/<分类>/` | 地點、勢力、物品、概念……一樣一條：一句話簡介、概要、規則與邊界、現狀，可選暗設；目錄就是分類；出現在哪幾章按細綱現算 |
| **劇情線** | `.novelwarden/threads/` | 主線（全書一條）/ 支線 / 感情線 / 人物線，一條一個檔案：意圖、當前進度、掛線上下的伏筆、每章在這條線上發生了什麼（帶原文證據） |

順帶整理出來的還有：**情節大綱**（各章細綱「梗概」那一句的彙總，不單獨存檔案，在大綱裡改就是改各章的梗概）、**全文大綱**（`summaries/global.md`，已寫部分的主線是怎麼一步步走過來的），以及**小說配置 / 故事前提 / 世界觀**。

![角色頁：每個人出場幾章、上次更新卡之後又出場了幾章（＋N），同步過的章裡出場卻還沒有卡的人單列一組；右邊是一張角色卡](docs/screenshots/characters.png)

同步過的細綱裡，連續性事實長這樣——證據是程式回到正文裡找出來的原句，找不到的事實不記：

```markdown
## 連續性事實
- 林昭左臂被青鱗劃傷，未愈 〔證據：「血順著左臂往下淌，他把袖子紮緊了」〕
## 設定
- 青雲宗〔宗門/正道〕：外門弟子不得夜出
```

<a id="已经写好的书导入然后一键补齐"></a>
### 已經寫好的書：匯入，然後一鍵補齊

1. **匯入原稿**：還沒有工程時用歡迎頁的「匯入寫好的書（txt）…」，一步建好一本書並導進來（見[第一次用](#第一次用)）；已經開著一本書，就在工程頁「章節」組右鍵「匯入原稿（選一本 txt）…」（「章節」還空著時那一頁上直接有這顆按鈕）。挑一本 txt（UTF-8 / UTF-16 / GBK 都認，最大 64 MB），按章標題切成一章一份，接在已有章節之後放進 `chapters/`。認得 `第一章 雪夜`、`第12章：雪夜`、`第三回 夜奔`、`Chapter 7`，以及序章、楔子、尾聲、番外這些；書名簡介、卷標題、目錄會丟掉，確認框裡寫清認出幾章、丟了什麼。**這一步不調模型**，切得不對就改 txt 裡的章標題再導一次。
2. **從已寫正文補齊**：匯入之後主按鈕就是「從已寫正文補齊…」（「故事架構」組右鍵也有）。它照第 1 章起連續寫好的正文，按這個順序**只補空白**：

   ```
   每章細綱 → 小說配置 → 故事前提 → 角色卡 → 世界觀 → 設定條目 → 全文大綱 → 劇情線
   ```

   - 問兩次：先報細綱要調幾次（一章一次）；細綱出來之後再報其餘幾樣——建幾張卡、幾條設定，要看細綱裡認出了誰。
   - 角色卡給出場兩章以上的人建，讀他出場的那幾章正文；設定條目給出現兩章以上的設定建，只讀細綱裡提到它的那幾句。
   - 劇情線排在最後：先排出幾條線，再從第 1 章起逐章認這一章在敘事線上發生了什麼（每章 1–3 次）。一章沒認成就停在那裡，之後在「敘事線」頁籤點「從正文補記」接著來。[故事時間](#故事時間)另在「時間線」組裡點「補推時間」。
   - 已經有的一件不動；一件失敗就停，寫好的留著，失敗掛在那一行上。

補完之後這本書的檔案就齊了：接著自己寫，或者讓 AI 接著寫都行。

### 寫一章，同步一章

寫完（或改完）一章，點一下**同步**——章節右鍵、編輯器上方的章節條、對話頁的主按鈕「同步第 N 章」都行。同步做四件事：

1. **照正文更新這一章的細綱**：寫偏的改成正文實際寫的，沒寫到的刪掉，一致的保留原話；補上連續性事實，記下這一章出現了哪些設定、實際誰出了場。舊版先複製一份進 `.novelwarden/.trash/`。
2. **更新出場角色的「當前狀態」**，寫到這一章。
3. **認這一章在劇情線上發生了什麼**：哪條線推進了、人物關係怎麼變了、哪條伏筆埋了或收了，正文裡第一次出現的線與伏筆也在這時認出來；再把動過的線的「當前進度」更新到這一章。
4. **推這一章的故事時間**：單獨一次，看著上一章的結尾判這一章比上一章晚了幾天、章裡又跳了幾天、停在什麼時段，正文寫明的日子與季節也記下，寫進[時間線](#故事時間)。

一章 3–6 次呼叫，動手前寫明。攢了好幾章沒同步，工程頁「概覽」頂上的黃條會說有幾章，點「立即同步」逐章同步。

**為什麼要點一下，而不是在後臺自動跑**：每次同步都要調模型、花錢，所以不偷偷跑——寫了正文還沒同步的章，「概覽」黃條和活動欄「工程」上的小圓點會提醒你。同步之後正文又改了，這一章回到「待同步」，再點一次就行。

### 之後：哪裡有新東西就補哪裡

同步只更新細綱、角色狀態與劇情線；給新人物建卡、往設定條目裡並新內容是另外的動作。要做什麼，工程頁都替你列好了：

- **角色**：同步過的章裡出場、還沒有卡的人列在「出場人物 · 未建卡」，右鍵建卡（通讀他出場的那幾章），或者「給全部 N 人建卡」。卡落後於正文時行尾掛 `＋N`，右鍵「更新角色卡」只讀新增的那幾章。「清理別名」「查詢並合併重複角色卡」不調模型，只改 frontmatter，不動你寫的正文。
- **設定**：同步過的章裡出現、還沒有條目的名字列在「出現過 · 未建條目」，右鍵「建條目」（只讀細綱裡提到它的那幾句，不重讀正文）。條目落後於正文時掛 `＋N`，「整合設定」把新內容並進去——只並不刪你寫的字。「按目錄整理…」讓模型照目錄樹給條目歸類，先出一份搬家清單，你點了才搬。
- **劇情線**：「敘事線」頁籤一條線一行，一眼看出各條線走到哪、哪條斷了好幾章（主線 5 章、其餘 15 章）、哪條伏筆過了計劃回收章還沒收（排細綱時推遲到更晚一章收的，按推遲到的那一章算）。一條線其實早就走完、卻一直掛著「斷了」的，右鍵那一行「標為收束」或「標為放棄」（不調模型，記在它最近一次有動靜的那一章）。掛不上線的伏筆先進「未歸屬的伏筆」，同步到它被揭開的那一章、認得出它在哪條線上時，整條挪到那條線下。同步過、劇情線還沒認的章，頁籤頂上說「⚠ 第 31–60 章還沒判」，點「從正文補記」逐章補上（每章 1–3 次）。
- **故事時間**：「敘事線」頁籤最上面單獨一組「時間線」：推到第幾章、現在是哪天，對不上的地方一條一行，章按月分段一章一行，點一章在[時間線總覽](#時間線總覽)裡看它；之前同步過、時間線裡還沒有的章點「補推時間」，推得不好的點「重推」。見[故事時間](#故事時間)。
- **全文大綱**：「文風與摘要」組裡點「重建」，從同步過的各章細綱每 15 章一批匯總、再合併。

<a id="叙事线总览"></a>
### 敘事線總覽

![敘事線總覽：橫著是章、豎著是線與伏筆，實心是正文裡實際發生的，空心是計劃，綠豎線是同步到的那一章](docs/screenshots/threads.png)

工程頁「敘事線」頁籤標題旁的「**總覽**」，或一行右鍵「**在總覽裡看**」，在編輯區裡開啟一個不對應檔案的標籤「敘事線總覽」：一張章 × 線的時間軸，一眼看出每條線走到哪、哪條伏筆該收了、計劃的事哪一章沒發生。不調模型，全是從敘事線檔案與章節現算的。

- **橫著是章**：從第 1 章畫到計劃或已寫的最後一章（細綱、正文、計劃裡提到的回收章都算）。列頭寫章號，底下一道顏色說這一章同步沒有：綠的同步了、藍的寫了還沒同步、灰的只有細綱；同步了、敘事線還沒判的，那道綠是虛的、字壓暗。分卷的書上面多一行卷名。一條綠色豎線標在「同步到第 N 章」那裡；敘事線落後於同步時另有一條虛的，標在「敘事線判到第 M 章」，頭上也寫著這兩個數。
- **豎著是線**：按主線、支線、感情線、人物線分組，每條線下面縮排列它的伏筆，最後是「未歸屬的伏筆」。線名前的 ● ○ ✓ ✕ 和工程頁一樣是進行中、計劃中、已收束、已放棄；有 ⚠ 的滑鼠停上去看是什麼。
- **線的格子**：○ 只有計劃（拆細綱時排的），● 只有實際（同步時認出來的），◉ 計劃了也發生了；**紅圈**是計劃了、那一章也同步了（敘事線也判過了），卻沒有發生——最該回頭看的就是它。還沒判的章上的計劃不算，補記完才知道發生沒有。線的計劃區間畫一條淡底。
- **伏筆一行**：埋 ● 到收 ◆ 之間連一條線；還沒收的虛線延到計劃回收的那一章（那一格一道豎線），過了還沒收的整條標紅；棄了畫 ✕；還沒埋的按計劃畫一條淡虛線，計劃的埋與收畫空心。排細綱時把回收推遲到更晚一章的，虛線延到晚的那一章。
- **滑鼠停在一格上**看那一章這條線上計劃了什麼、實際發生了什麼，帶原文證據。**點一格或列頭**開啟那一章（正文在左、細綱在右，還沒寫的開啟細綱）；**點線名、伏筆名**開啟那條線的檔案。左邊一列與表頭不動，橫著滾看後面的章。
- **故事時間**：列頭與格子的懸停帶著這一章是哪天，埋了沒收的伏筆說故事裡已經過了幾天。時間線本身在它自己的[時間線總覽](#時間線總覽)裡看，這裡只管線與伏筆。
- 開著時你儲存了檔案、同步了一章，它自己跟上；標籤右鍵或右上角「重新整理」也行。重新整理頁面後這個標籤還在。

<a id="故事时间"></a>
### 故事時間

細綱的「時間地點」寫的是「次日清晨」「三天後」這種相對說法，沒人把它們累加成日期。時間線替你記：**同步一章時單獨判一次這一章的時間**——看著上一章的結尾，判這一章開頭比上一章晚幾天、章裡又往後跳了幾天、停在什麼時段，正文寫明的日子（「八月十五」「除夕」「二十一日」）與季節也記下——寫進 `.novelwarden/threads/时间线.md`，一章一行：

```markdown
---
calendar: 簡單歷
start: 大衍三年三月初七
---

- 第 1 章：+0 天，傍晚 → 深夜〔依據：「連日大雨的第三天傍晚」〕
- 第 4 章：+1 天，清晨 → 夜裡，歷時 3 天〔依據：「次日清晨，雨停了」〕〔文中：八月十五（中秋），開頭後 2 天「今夜便是中秋」〕
- 第 7 章：回憶，約二十年前〔推測：整章是回憶〕
- 第 9 章：+?〔推不出：正文沒交代過了多久〕〔季節：冬「北風捲著碎雪」〕
- 第 12 章：八月十五
```

- **日期是算出來的**：檔案裡記「晚幾天」，日期從第 1 章往後累加，在「時間線」組、[時間線總覽](#時間線總覽)和寫正文的上下文裡看。`start` 寫第 1 章那一天（「大衍三年三月初七」「三月初七」「2026-03-07」都認，日期照這個寫法出），不寫就只顯示「第幾天」；`calendar` 寫「簡單歷」（每月 30 天、一年 12 個月，節日按農曆口徑）或「公曆」。曆法與起點在「時間線」組標題上，滑鼠停上去看，**右鍵「改曆法與起點…」**改。沒填起點、正文又寫明過日子時，組裡多一條 ⚠ 替你倒推第 1 章是哪天，右鍵「填為起點」。
- **正文寫明的日子當校準點**：累加到寫著〔文中〕的那一章，就按正文對齊，後面的章跟著順延——一路累加的誤差在那裡清零；差得多的（2 天以上）在「時間線」組裡說「前面推下來是七月廿一，正文寫八月十五」，你一眼看出是哪一段推錯了。只寫了日沒寫月的（「二十一日」）只對賬、不對齊。季節對不上、往回跳又沒標回憶、連著幾章推不出，也各說一句。
- **你說了算**：「時間線」組裡右鍵一章（或時間線總覽裡右鍵一張卡片）「改時間…」，寫「八月十五」「第 200 天」「+3 天」「同日」「回憶」都行，可以帶時段（「八月十五，傍晚」）。**改過的就是你定的**——行尾不帶〔依據〕〔推測〕那一段——機器再也不動它，後面的章跟著順延；清空就是刪掉那一行，留給機器重推。檔案照樣能直接改：刪掉行尾那一段，那一行就算你定的。誰說了算：你定的 > 正文寫明的 > 累加的。
- **機器寫的它能重來**：重新同步一章時，機器寫的那一行照新推的換；「時間線」組標題旁「重推」把機器寫的全部重推一遍，右鍵一章「重推這一章」「從這一章起重推」只推一段（幾章一批、一批 1 次，動手前寫明會換掉幾行、你定的幾行不動，先存一個[存檔點](#存檔點)）。
- **之前同步過的章**：時間線裡還沒有的，點「補推時間」幾章一批補上，只填空。
- **寫正文、拆細綱時帶著**：上下文裡有一節「故事時間」，說上一章是哪天、停在什麼時段、眼下什麼季節、最近幾章的節奏，模型照著接，不用自己算。

### 時間線總覽

![時間線總覽：豎著按故事裡的日子排，一個日子一行，那一天的幾章一章一張卡片，帶這一章在各條線上發生的事；中間空了幾天寫「N 天后」，對不上的卡片左邊一道紅](docs/screenshots/timeline.png)

「時間線」組標題旁的「**總覽**」，或**點組裡的一章**，在編輯區裡開啟一個不對應檔案的標籤「時間線總覽」（和[敘事線總覽](#敘事線總覽)各開各的）。不調模型，全是從時間線與敘事線現算的。

- **豎著按故事裡的日子排**：一個日子一行，左邊寫那一天（`三月初七`，下面小字「第 1 天」），右邊是這一天開頭的幾章，一章一張卡片。月份變了插一行「大衍三年三月 · 春」；兩個日子之間空了 2 天以上，插一行「5 天后」（只壓空白、不按比例，幾百章也看得下）。往回跳的章排到它那一天去，所以這裡看的是故事裡誰先誰後，不是章號。
- **卡片**：狀態點（● 有依據、○ 推測、◆ 正文寫明、★ 你定的、? 推不出）、章號章名、時段（「清晨 → 夜裡」，跨了幾天的寫到哪天、幾天）與比上一章晚多久、依據原話；下面是**這一章在各條線上發生了什麼**——線名做成帶色塊的小標籤，收著時列 3 條；一條都沒有的寫細綱的梗概。對不上的卡片左邊一道紅，紅字寫哪裡對不上。整章回憶的章是虛線框，縮排掛在前一章後面（它不知道是哪天）。
- **單擊一張卡片**展開：那一天的全稱、故事第幾天、歷時，依據原話、正文寫明的日子、季節、對齊了幾天，各條線上的事帶原文證據，細綱寫的時間地點；再點收起。**右鍵**：改時間、重推這一章 / 從這一章起重推、開啟這一章、開啟細綱、開啟時間線檔案。
- **右鍵標題欄或空白處**：改曆法與起點、填為起點、補推時間、重推、開啟時間線檔案。標題欄上只有兩個篩選：「只看有問題的」（對不上的、推不出的、還沒推的）與「線」（只看在某條線上有事發生的章）。
- 開著時你同步了一章、改了時間，它自己跟上；右上角「重新整理」也行。

### 不用手改，也不怕手改

- **正文是唯一真相**：一切從 `chapters/` 整理出來。誰在哪幾章出場、某條設定出現在哪幾章、哪條線斷了幾章，都是從同步過的細綱現算的，不另存一份會過期的賬。
- **機器維護，你改過的它不覆蓋**：角色的「當前狀態」、劇情線的「當前進度」你手改過，下次同步就不寫，掛一個黃 ❗，右鍵可以對比機器那一版再決定；已有的角色卡、你改過的設定條目，更新時一律先給你對比；劇情線的意圖和你手寫的行，機器一個字不動。
- **有證據才記**：連續性事實、劇情線上的事件，都要在正文裡逐字找得到原話才記。
- **不偷偷花錢**：要調模型的動作，動手前都寫明預計呼叫次數；確認框上還能只為這一次換模型、換上下文詳細度。
- **改壞了能退**：覆蓋之前舊版先存進[歷史版本](#儲存衝突與歷史版本)；批次動作之前自動存一個[存檔點](#存檔點)；刪除一律搬進回收站 `.novelwarden/.trash/`。
- **出錯掛在出錯的東西上**：哪張卡、哪一章、哪條設定沒整理成，那一行前面掛 ❗（紅色是整體失敗、磁碟上一個字沒改；黃色是部分完成或需要你看一眼），成功之後自動消失。

## 工程頁

活動欄「工程」頁是整本書的目錄，頂上五個頁籤：

| 頁籤 | 內容 |
|---|---|
| **概覽** | 同步進度黃條（幾章寫了還沒同步，「立即同步」）；故事架構（小說配置 / 故事前提 / 角色圖譜 / 世界觀 / 設定清單 / 情節大綱）；文風與摘要（全文大綱、文風指南） |
| **章節** | 一個章號一行，細綱與正文是同一行的兩面：`第12章 夜入青云　待同步　2980 / 3000`；分了卷的按卷分段 |
| **角色** | 角色卡、「狀態截至第 K 章」、出場幾章、`＋N`；連同「出場人物 · 未建卡」 |
| **設定** | 按目錄分類的設定條目、出現在哪幾章、`＋N`；連同「待完善」「出現過 · 未建條目」；幾百條時用篩選框 |
| **敘事線** | 「時間線」一組（對不上的地方、按月分段一章一行，點一章在時間線總覽裡看；「補推時間」「重推」「總覽」，右鍵改時間、改曆法與起點）；「敘事線」一組（一條線一行，斷了幾章、伏筆逾期；「從大綱排出」「從正文補記」「總覽」） |

最右邊是 ⚑（[存檔點](#存檔點)）與重新整理。

- **行上只有內容，操作都在右鍵選單裡**，和檔案管理器一樣。章節、角色、設定三個區能建資料夾、隨便嵌幾層；新建、重新命名、移動、刪除都在右鍵裡。
- **章節那一行**：行首圓點說同步沒有（`●` 已同步、`○` 還沒同步或同步之後正文又改過、`·` 還沒寫正文），徽章說這一章該做哪一步，細綱在正文寫完之後改過時掛 ⟳（只比對指紋，不調模型）。點名字，正文開在左邊、細綱並排開在右邊；**滑鼠停在行上會浮出這一章的細綱**。

  <img src="docs/screenshots/chapter-hover.png" alt="章節頁：滑鼠停在第 2 章上，浮出這一章的細綱" width="420">
- **分卷**：`chapters/` 下的一級目錄就是一卷，右鍵「新建卷…」；新章預設進最新的一卷。卷只是收納，章號全書連續。
- **匯出全文**：「章節」組右鍵「匯出全文（txt）」，全部章節按章號拼成一份 txt，寫到工程根下的 `导出/<书名>.txt`（再導一次就覆蓋）。章標題寫成「第一章 楔子」，分卷的書進一卷前單起一行卷名，沒有正文的章不放進去。不調模型；讀的是磁碟，編輯器裡沒儲存的不在裡面。
- **改名、移動跟著搬**：章節改名或挪目錄時，草稿與細綱跟著搬，細綱裡的標題跟著改。不跨區、不覆蓋同名檔案、不真刪。
- **任務條**：批次同步、補記這類連著調幾十次模型的動作，頁簽上面有一條任務條：當前那一章、第幾項 / 共幾項、已用時、停止。停下時已完成的保留；重新整理頁面後自動接上。
- **日誌**頁記下每一次模型呼叫、每一章同步、每一次檔案操作，可以按級別、關鍵字篩，往前翻得到重啟之前 30 天的。日誌裡不出現 API Key，也不記 prompt 與正文全文。

## 也能接著寫

除了整理，Novelwarden 也能用 AI 把一本書往下寫：

```
一句話  →  故事架構  →  情節大綱  →  細綱  →  正文  →  同步
如果……    配置 前提     一章一條     一章一份   自動續寫    照正文更新細綱
          角色 世界觀                每批 5 章  到八成      + 角色狀態 + 劇情線
```

- **跟著主按鈕走**：對話頁輸入框上方永遠只有一個主按鈕，寫著這本書現在該做的那一步（生成小說配置 → 故事前提、角色圖譜、世界觀…… → 情節大綱 → 拆細綱 → 寫第 N 章 → 同步第 N 章），旁邊寫著要調幾次模型。每一步的產物先攤在對話裡，點「寫入」才落盤。
- **正文寫夠才停**：寫第 N 章時帶著這一章的細綱、上一章結尾（不許重演）、後 5 章細綱（不許提前寫）、出場角色卡與前幾章同步留下的原文片段；沒寫夠目標字數的八成就自動接著寫。寫完會提醒重演、後面幾章的人提前登場、比喻詞超標。
- **續寫大綱**：大綱快不夠用了，在哪一層都能打 `/续写大纲`，從大綱排到的下一章起往後排 20 章，跑完回到原來那一章；工程頁「情節大綱」那一行與「章節」組的右鍵裡也有。停在一章上時，對話頁頂上「大綱 · 細綱 · 正文」三格里的「大綱」回到全書那一層，這一章還沒排進大綱時它掛 ⚠。
- **討論與落定**：直接打字就是討論，AI 不動你的檔案；聊定了打 `/落定细纲` 把結論整理成細綱，`/落定设定` 把聊定的設定寫成條目。
- **審稿與修稿**：正文層打 `/审稿`，逐條引原文挑問題、逐項核對細綱裡的關鍵事件，只出報告；你勾選之後按勾選的條目修稿。
- **批次**：工程頁「補齊架構」「批次拆細綱…」「批次寫章…」（可選「寫完即同步」），都只補空白、不覆蓋已有的。
- **按階段裝配上下文**：定架構、排大綱、拆細綱、寫正文各帶各的東西，帶了什麼、少帶了什麼都列在每條回覆下面的明細裡（「複製完整上下文」能把這一輪發給模型的訊息原樣複製出來）。帶多少由[上下文詳細度](#上下文詳細度)定。
- **寫作技能**：給規劃 / 寫正文 / 審稿 / 修稿某個階段綁一份技能（一個目錄裡一份 `SKILL.md`），這個階段的每一次生成都把它放在提示詞最前面。內建一份「去 AI 味」；[skills/writing/](skills/writing/README.md) 裡另備了 33 份預設，在設定頁「技能」裡從 GitHub 裝。
- **從參考書學寫法**：挑一本別人的書，學文風（寫進 `style.md`）或結構與節奏（寫成一份規劃技能），原文不進工程。
- **外部 agent（MCP）**：獨立版在同一個埠掛了 MCP 入口，Claude Code、Codex 這類 agent 接進來做多步的活，落盤前照樣在對話頁問你。接入命令打在啟動服務的終端日誌裡，例如：

  ```
  claude mcp add --transport http novelwarden http://127.0.0.1:36800/mcp
  ```

## 配置

設定頁分「模型配置」「上下文管理」「通用」（只有獨立版有）「技能」幾個頁籤。API Key 按服務商存在 `~/.novelwarden/secrets.json`，不寫進配置檔案。

### 服務商與模型

兩種協議：`kind: "openai"` 走 OpenAI 的 Responses 介面（`/responses`），`kind: "anthropic"` 走 Anthropic 的 Messages 介面。**只認 `/chat/completions` 的服務商（DeepSeek、智谱、Kimi、通义、本地 Ollama 等）在 `openai` 下會 404**，要在 `baseUrl` 填一個自己那側的 `/responses` 相容閘道器。設定頁備了 OpenAI / Anthropic / Copilot 三個預設，每個模型行右邊有「測試」。

模型用 **`前缀/模型名`** 引用，字首就是服務商的 id；**只在第一個斜槓處切分**，`openrouter/z-ai/glm-4.6` 的服務商是 `openrouter`：

```jsonc
"novel.providers": [
  {
    "id": "openrouter",
    "kind": "openai",                                         // openai / anthropic / vscode-lm
    "baseUrl": "https://openrouter.ai/api/v1",
    "models": [
      { "name": "z-ai/glm-4.6", "contextWindow": 200000 }     // 模型名自帶斜槓
    ]
  }
],
"novel.model": "openrouter/z-ai/glm-4.6"
```

### 模型分檔

工程頁的後臺任務可以按難度分三檔用不同的模型，每檔是一份有序清單（第一個失敗就在同檔裡換人，絕不跨檔）：

| 檔位 | 放什麼模型 | 內建預設包含的任務 |
|---|---|---|
| **快速檔** | 便宜、快的 | 同步 · 照正文更新細綱、全文大綱 · 分批匯總、設定 · 記設定、轉寫 · 整理成 JSON |
| **均衡檔** | 折中的 | 設定 · 建條目與整合、角色卡 · 更新 / 建卡、劇情細綱、批次寫正文、批次審稿 |
| **精標檔** | 最聰明的 | 故事架構、全文大綱 · 最終合併、提取角色、提取文風 |

不配就是不分檔，全部沿用「預設模型」。對話頁的單次生成不走分檔，永遠用你在輸入框旁選的那個模型。

唯一的例外是**轉寫**：凡是要整理成固定結構的步驟（細綱、同步、敘事線、故事時間、角色卡、設定、審稿、小說配置與角色圖譜……），模型都按格式寫自然語言（不再要它直接寫 JSON——那樣寫出來的東西明顯差，還容易因為少一個引號整批作廢），寫完由「轉寫」那一檔的模型照抄成程式要的 JSON，每一段字都得出自原文，改了字就重轉。對話頁、工程頁都用它，確認框上為這一次換的模型也不管它；那一檔沒配就用預設模型。所以這些步驟每寫一次都多一次呼叫（寫細綱是 2 次：寫 1 次、轉寫 1 次）。

<a id="上下文详细度"></a>
### 上下文詳細度

設定 → 上下文管理，四級：1 精簡 / 2 標準 / **3 詳細（預設）** / 4 完整。級別越高，每次帶的前文、細綱、設定與劇情線越多、越貴；**不改呼叫次數**，只改每次帶多少。工程頁動作的確認框上可以只為這一次換模型、換級別，不寫回設定。

### 其餘設定項

| 設定項 | 預設值 | 說明 |
|---|---|---|
| `novel.providers` | `[]` | 服務商與模型清單，見上 |
| `novel.models` | 第一個可用 | **預設模型列表**（有序）。工程頁任務序列時用第一個，失敗隨機換用其餘；併發時輪轉負載均衡。也是**所有未配置檔位的兜底清單** |
| `novel.model` | 列表第一項 | 當前模型引用，如 `glm/glm-4-plus`。恆等於 `novel.models[0]`，相容保留 |
| `novel.tierModels` | `{}` | **模型分檔**：快速 / 均衡 / 精標三檔各自的模型清單，見下 |
| `novel.taskTiers` | `{}` | 每項工程頁任務歸在哪一檔，只需寫與內建預設不同的項 |
| `novel.concurrency` | `3` | 工程頁批次任務的併發請求數，1 表示序列 |
| `novel.fallbackAttempts` | `2` | 一次呼叫失敗後換用**同檔**其它模型重試的次數上限，0 表示不重試 |
| `novel.temperature` | `0.8` | 摘要類任務內部固定用 0.3 |
| `contextDetail` | `3` | 上下文管理：[上下文詳細度](#上下文詳細度) 1–4，認不出的值按 3 |
| `novel.chaptersDir` | `chapters` | 章節（正文）目錄（相對工作區根） |
| `novel.draftsDir` | `drafts` | 章節草稿目錄（相對工作區根） |
| `novel.summaryBatchSize` | `15` | 上下文管理：重建全文大綱的批大小（多少章一批） |
| `novel.requestTimeoutMs` | `300000` | 空閒超時：流式還在吐字時不計時，卡住這麼久沒資料才中止 |

## 目錄結構

```
chapters/                    正文，唯一真相；一級目錄就是一卷，章號全書連續
├── 001-楔子.txt
└── 第二卷/003-夜访.txt       新建的正文是 .txt；副檔名不挑：.md、.txt、沒有副檔名都算章節
drafts/                      章節草稿，路徑映象 chapters/，按需建立
匯出/<書名>.txt               匯出的全文（章節組右鍵「匯出全文（txt）」），再導一次就覆蓋
.novelwarden/
├── summaries/               每章細綱，路徑映象 chapters/（副檔名換成 .md），如 summaries/第二卷/003-夜访.md
│   └── global.md            全文大綱
├── characters/<名字>.md      角色卡
├── lore/<分類>/<條目>.md      設定條目：目錄就是分類，可以巢狀
├── threads/<線名>.md         劇情線；掛不上線的伏筆在「未归属的伏笔.md」
├── config.md                小說配置（含分段格式 paragraphStyle）
├── premise.md · world.md    故事前提、世界觀
├── style.md                 文風指南
├── project.json             章節索引；全文大綱、劇情線各整理到第幾章
├── skills/ · skills.json    本工程的寫作技能與階段繫結
├── sensitive.txt            敏感詞表（只給編輯器的寫作體檢用）
├── sessions/                對話歷史
├── history/                 歷史版本（Git 預設不收）
├── checkpoints/             存檔點（Git 預設不收）
├── novelwarden.db            失敗記錄與日誌歷史（SQLite，可隨時刪）
└── .trash/                  回收站
```

- **細綱跟著正文的路徑走**：`chapters/第二卷/003-夜访.txt` 的細綱是 `.novelwarden/summaries/第二卷/003-夜访.md`，草稿是 `drafts/第二卷/003-夜访.txt`。在工具裡改名、挪目錄時兩樣跟著搬；在工具之外改了正文的檔名，舊細綱不會被認過來，那算一章新的。
- **舊工程**：Novel Forge 時代的工程後設資料在 `.novelforge/`（更早是 `.novel/`），開啟時照舊認；遷到 `.novelwarden/` 只在作者確認後改名，不刪除舊目錄。
- **章節順序只看檔名前面的數字**，和放在第幾層目錄無關。圖片、Office 文件、壓縮包這類不算章節；`047 细纲.txt`、`048 作话.txt` 這種去掉數字後整個名字就是「細綱」「大綱」「作話」「筆記」「設定」「草稿」之類的也不算——那是你放在卷目錄裡的筆記，照樣能開啟、不進正文（叫「設定崩塌」的照樣是章節）。角色卡與設定條目只認 `.md`。
- **`novelwarden.db` 可以刪**：裡面只有失敗記錄與日誌歷史，作品內容一個字都不在裡面，刪了下次自動重建。
- 老工程裡從前的 `volumes/`、`manuscripts/`、`scenes/`、`.novelforge/plots/` 一個位元組都不動，只是不再讀。

## 開發

```bash
npm install
npm run compile      # 打包外掛與前端資源（F5 除錯前必須有）
npm run watch        # 監聽構建
npm run typecheck    # tsc --noEmit
npm test             # typecheck + 全部測試（不需要 API Key）
npm run standalone   # 起獨立 Web 服務（改完樣式需重啟）
npm run dist         # 編譯獨立版單檔案可執行（dist/novelwarden）
```

測試在 [`tests/`](tests/README.md)，按型別分 unit / integration / dom / e2e / contract，執行器是 Node 自帶的 `node:test`。三個殼的 F5 配置見 [.vscode/README.md](.vscode/README.md)。程式碼結構、模組地圖與必須遵守的行為約束見 [AGENTS.md](AGENTS.md) 與 [src/README.md](src/README.md)。
