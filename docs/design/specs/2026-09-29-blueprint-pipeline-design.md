# 設計：換成「設定先行 + 一章一綱」的生成鏈路

日期：2026-09-29　分支：`refactor/blueprint-pipeline`（基於 `main@8100cdf`）

## 為什麼改

舊鏈路 `大綱 → 卷 → 劇情段 → 中轉站正文 → 拆章` 跑出來的正文不可用。對照 AI-Novel-Writer（GPL-3.0，思路源自 AI_NovelGenerator）的原始碼，判斷主因在規劃層，不在裝配器：

1. **細綱太虛，又沒有長度錨點。** 細綱被禁止寫場景和動作，也不規定起訖；劇情段不按章切，`targetWords` 可以不填。模型拿到一條抽象因果鏈去「擴寫」，寫出來是梗概體的流水賬。
2. **沒有前置設定。** 角色卡、設定都是寫完以後從摘要裡反推的，等於拿模型上一次的發揮去約束它下一次的發揮。
3. **寫正文時不給後續劇情作邊界**，模型會提前把後面的事寫掉，或者在結尾強行收束。
4. **沒有審稿和修稿。**

完整對比見 `~/workspace/project-reports/novelForge-vs-AI-Novel-Writer-对比-20260929.md`。

## 新鏈路

```
一句話 ─▶ 設定 config.md
       ─▶ 架構：故事前提 premise.md → 角色圖譜 characters/*.md → 世界觀 world.md → 情節大綱 outline.md（標章號區間）
       ─▶ 細綱 plots/NNN-标题.md（一章一份，每批 5 章）
       ─▶ 正文 chapters/NNN-标题.md（直接寫入；按目標字數自動續寫）
       ─▶ 定稿後處理：摘要 + 角色「當前狀態」
       ─▶ 審稿（逐字引證 + 本章目標逐項核對）→ 按勾選的意見最小改動修稿
```

**一條軸**：細綱號 = 章號。段號和章號兩條軸、劇情段顯示位次、中轉站、拆章，統統刪掉。

## 關鍵決定

| # | 決定 | 理由 |
|---|---|---|
| D1 | **刪掉「卷」這一層** | 情節大綱按章號區間組織，細綱每批 5 章、帶前序細綱一覽，已經起到中等尺度參照的作用。卷只剩收納用途，不值得多一層狀態機和指紋鏈 |
| D2 | **刪掉中轉站 `manuscripts/` 和拆章** | 一綱一章以後沒有「按自然長度寫完再切」的需要。正文確認後直接落 `chapters/NNN-标题.md`，章節仍是唯一真相，第 9 條不變 |
| D3 | **細綱改成藍圖欄位，並且允許具體** | frontmatter：`no` / `title` / `role`（本章在結構中的功能）/ `characters[]` / `targetWords`；正文三節：`## 本章目的`、`## 關鍵事件`（100–300 字，**可以寫具體場面**）、`## 章末鉤子`（必填）。模組名 `plotFile` / `plots/` 保留不改，因為「細綱」在中文網文裡本來就指一章的綱 |
| D4 | **設定是一個獨立階段 `setting`**，下轄四個 target：`config`、`premise`、`characters`（角色圖譜）、`world` | 四步前後銜接：前提 → 角色 → 世界觀 → 大綱，每一步都吃上一步的產出 |
| D5 | **角色卡由角色圖譜生成**，沿用現有七節格式（已經有「當前狀態」「未收伏筆」兩節）；定稿後只增量更新「當前狀態」 | 事後從摘要反推的那條路保留，作為補漏手段 |
| D6 | **正文目標字數必填**，預設取 `config.md` 的 `wordsPerChapter`。生成時不到目標的 80% 就自動續寫，最多續 N 輪；續寫沒有增長就丟棄並恢復一次；最後仍不到 80% 就報「未寫夠」，但不丟已寫的內容 | 移植 AI-Novel-Writer 的續寫邏輯，**不搬它寫死的 8192 單次上限**：輸出上限一律用模型配置 |
| D7 | **寫正文時加三道邊界**：後 5 章細綱列為「禁止提前寫」；上一章結尾約 1000 字 +「不許重演」+ n-gram 重演檢測；提示詞末尾用執行卡把本章關鍵事件和鉤子再列一遍 | AI-Novel-Writer 驗證過的做法，這裡沒有 |
| D8 | **去 AI 味禁令並進正文系統提示**：禁止段尾總結句，「彷彿/猶如/宛如」全章不超過 3 次，對話要分得出是誰在說，結尾不加哲理旁白 | 同上 |
| D9 | **審稿和修稿複用現有能力**：審稿是正文層的新能力 `review`，只出報告、不寫檔案；修稿走 `generate`，把勾選的審稿條目塞進已有的 `revision` 層，並要求最小改動，覆蓋前照舊審閱 diff | 不新增落盤路徑，第 3、19 條原樣成立 |
| D10 | **批次寫正文改成嚴格序列**：寫一章 → 落盤 → 摘要 → 更新角色狀態 → 下一章。跳過已有正文的章 | 第 N 章要讀第 N-1 章的結尾和狀態，不能併發 |
| D11 | **不做向後相容**：老工程的 `volumes/`、`manuscripts/`、老格式細綱在磁碟上一個位元組都不動，程式碼不再讀它們，也不遷移 | 使用者已確認舊設計可以刪；第 1 條（容錯不崩）照舊 |
| D12 | **agent 層保留，只改工具**：`generate` 工具的 stage/target 跟新模型走 | agent 本身與鏈路設計無關 |

## 上下文裝配（新配方要點）

- **設定層**：一句話 + `config.md` + 已有的前提、角色、世界觀。不帶正文。
- **大綱層**：`config.md` + 前提 + 角色圖譜 + 世界觀 + 故事結構指導（按總章數算出三幕 20/55/25 等章號區間）。
- **細綱層（拆 5 章）**：設定四件 + 情節大綱 + 前序細綱一覽（最近 100 章，一章一行）+ 已寫章節的摘要。
- **正文層**：P0 強制：文風、本章細綱 + 執行卡、上一章結尾、後 5 章細綱（邊界）、修改意見；P1：本章出場角色卡 + 主角、前提 / 世界觀、情節大綱裡本章所在的那一段、歷史對話；P2：全書摘要、命中關鍵詞的設定；P3：近 2 章全文；P4：更早的摘要。P0–P4 預算器與「不靜默截斷」明細照舊。

## 分期

> 2026-09-30 起以 [總計劃](../plans/2026-09-30-blueprint-pipeline-roadmap.md) 為準：前面加了零期（修 bug + 測試基建），WebUI 改造並進各期，最後加七期（敘事線）。下表是當初的六期劃分，留作記錄。e2e 已可在本機跑（Bun 1.4.2），納入每期驗收。

每期結束：`npm run typecheck` + `npm run test:node` 全綠。

| 期 | 內容 | 驗收 |
|---|---|---|
| 一 | **資料層與狀態機**：`model/pipeline.ts` 換成 `setting / outline / plot / manuscript` 四階段；新增 `config` / `premise` / `world` 三種文件；細綱換成 D3 的格式；刪掉卷、中轉站、拆章、劇情段位次；workspace 的 kind / handler、views 跟著改；`sample-novel` 重做 | 老流水線的測試刪掉，新狀態機、細綱解析、落盤都有測試 |
| 二 | **設定 + 架構 + 細綱生成**：移植配置、前提、角色圖譜、世界觀、情節大綱的提示詞和輸出契約；故事結構指導；拆細綱每批 5 章；解析三層降級；採納落盤 | 假模型整合測試跑通「一句話 → 前 5 章細綱」 |
| 三 | **正文生成**：新正文提示詞（D7、D8）、新裝配層、自動續寫、重演檢測、直接落 `chapters/` | 假模型測試覆蓋續寫、截斷、重演拒絕。**真實模型驗收：同一句腦洞跑到前 3 章，匯出給作者讀，讀得下去才進四期** |
| 四 | **定稿後處理 + 批次序列**：摘要之後更新出場角色的「當前狀態」；批次寫正文改成序列鏈 | 整合測試：連寫 3 章，第 3 章的上下文裡能看到第 2 章更新過的狀態 |
| 五 | **審稿 + 修稿**（D9） | 引證不在原文裡的條目被丟棄；修稿走覆蓋審閱 |
| 六 | **前端收尾與文件**：流水線條、工程頁分組（卷 → 設定）、下一步按鈕；README 與 AGENTS.md 第 8、18、21、22、23 條重寫；清掉死程式碼 | 全量測試 + 手動過一遍獨立版 |

前端改動隨各期一起做，第六期只做收尾。

## 不做

- 知識庫 / 向量檢索、提示詞三級覆蓋、中英雙語、定稿來源收據那一套：對「寫得好不好」沒有貢獻。
- 老工程遷移。
- 任何寫死的輸出 token 上限。
