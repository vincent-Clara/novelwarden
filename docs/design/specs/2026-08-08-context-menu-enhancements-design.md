# 右鍵功能完善設計

日期：2026-08-08
狀態：已評審通過

## 背景與目標

獨立版的三處介面缺少常見的右鍵/鍵盤操作，本設計補齊：

1. **檔案編輯頁**（editor.js）：標籤頁右鍵選單（關閉當前/左側/右側/其它）；正文區右鍵選單（剪下/複製/貼上/全選）。
2. **檔案頁**（explorer.js）：檔案與資料夾的剪下/複製/貼上，檔案與資料夾均可重新命名；支援 Ctrl+X/C/V，剪貼簿以應用內部狀態為主、相對路徑外送系統剪貼簿。
3. **工程頁**：「角色」分組新增「更新所有角色卡」與「從頭重建所有角色卡」兩個批次動作。

檔案頁由此從只讀變為可寫——這是對 AGENTS.md 行為約束 #7 的**有意修訂**，寫入口收斂在新模組 `core/projectFiles.ts`，仍帶工程根包含檢查與安全約束。

## 已確認的關鍵決策

| 決策點 | 結論 |
| --- | --- |
| 檔案頁寫操作範圍 | 整個工程根內（含 `.novelforge/`），不限於三個管理區 |
| 檔案重新命名 | 檔案與資料夾都可重新命名 |
| 剪貼簿語義 | 應用內部狀態為主；複製/剪下時把相對路徑以純文字寫進系統剪貼簿（外送）；不解析外部剪貼簿內容 |
| 批次角色卡採納 | 總確認框裡讓使用者選「逐張確認」或「全部直接採納」 |
| 「更新所有角色卡」語義 | 增量：只讀各卡上次更新後的新出場章節；無新章節/未出現在摘要的卡跳過並報數 |
| 批次關閉標籤確認 | 逐個確認（與現有單標籤關閉一致），取消一個跳過它繼續其餘 |
| 正文區右鍵選單項 | 剪下/複製（無選中置灰）/貼上/全選 |

## A. 後端：全工程檔案操作（`src/core/projectFiles.ts`）

新模組，core 層、零 vscode 依賴。與 `fileOps.ts` 並列而非合併——`fileOps.ts` 的「鎖在三個區內」是工程頁的產品承諾，繼續保留。

### 操作與入口

- `renameAny(project, relPath)`：重新命名檔案或資料夾，保留副檔名；章節 `.md` 檔案的 `NNN-` 序號字首與正文 H1 同步邏輯與 `fileOps.renameEntry` 一致（共享內部實現）。
- `moveInto(project, sources[], targetDir)`：剪下+貼上的後端。逐個移動。
- `copyInto(project, sources[], targetDir)`：複製+貼上的後端。`fs.cp` 遞迴複製（二進位制安全）。
- 三個函式都返回逐項結果 `{ from, to?, ok, error? }[]`，供前端 remap 編輯器標籤。

### 安全約束（違反 = toast 報錯 + log.warn，絕不靜默）

1. **工程根包含**：複用 `fileOps.normalizeRel`；絕對路徑、`..` 逃逸一律拒絕。
2. **不靜默覆蓋**：目標已存在同名項 → 該項拒絕，其餘項繼續，逐項報錯。
3. **資料夾不進自身子孫**：移動/複製的落點不能是源目錄自己或其子目錄。
4. **垃圾箱不搬**：源在 `.novelforge/.trash/` 內一律拒絕。
5. **落點自由**：目標目錄可以是工程根內任意位置（含 `.novelforge/`），這是使用者的明確選擇。

### 章節聯動

- 源或落點在 `chapters/` 下的改名/移動/複製，走與 `fileOps.ts` 相同的 `carryDraft` + `syncManifest` 處理（從 `fileOps.ts` 抽取共享 helper，避免兩份規則漂移）。
- 章節被移出 `chapters/`：草稿留在舊映象路徑不刪，記 warn 日誌說明。
- 複製出的章節檔案由 `syncManifest` 收編為新條目。

### 協議變更（`protocol.ts`）

- `FileAction` 增加 `'paste'`（不需要單獨的 copy——剪下/複製只是前端登記剪貼簿狀態，真正的磁碟動作只有貼上這一次）。訊息新增欄位 `relPaths: string[]`（僅 paste 使用）與 `op: 'cut' | 'copy'`（僅 paste 使用，區分移動還是複製）；`relPath` 保持單數供 rename/move/delete 使用。`targetDir` 為落點。
- 新 `OutMessage`：`filesOpDone { op: 'rename'|'move'|'copy'; results: { from: string; to?: string; ok: boolean; error?: string }[] }`。前端據此 remap 已開啟的編輯器標籤並清除剪下態。
- 目錄重新整理不另發訊息：watcher 觸發的 `dirListings` 重推已經覆蓋。

## B. 檔案頁前端（explorer.js）

### 選單項

- 檔案行：剪下 / 複製 / 貼上 / 重新命名，加在現有「開啟 / 在系統中開啟 / 複製相對路徑」之前，分隔線隔開。
- 資料夾行：同樣四項，加在現有「摺疊·展開 / 在系統中開啟 / 複製相對路徑」之前。
- 「貼上」僅在有剪貼簿狀態時可用（disabled 控制）；在**資料夾行**上貼上落進該資料夾，在檔案行上貼上落進其父目錄。

### 剪貼簿狀態

- 模組級 `{ op: 'cut' | 'copy', paths: string[] }`。
- 每次剪下/複製，另把相對路徑以純文字 `navigator.clipboard.writeText`（多路徑按行連線）寫進系統剪貼簿——僅外送，不讀回。
- 待貼上的行（剪下源）加暗色標記，貼上成功或再次剪下/複製後清除。

### 鍵盤快捷鍵

- 行加 `tabindex="0"`；焦點在檔案樹內時 Ctrl+X / Ctrl+C / Ctrl+V 作用於焦點行。焦點判定保證與編輯器內的文字 Ctrl+C/V 互不干擾。
- 單擊行仍然開啟檔案，同時讓該行獲得焦點。

### 與內建編輯器的聯動

- 收到 `filesOpDone` 後，對每個成功的 rename/move：若舊路徑在編輯器裡開著（任一 pane），explorer 發 `openEditor` 開啟新路徑；editor.js 識別「搬家」場景——把舊標籤的未儲存草稿與 hash 原樣帶到新標籤（localStorage 的 pending 草稿鍵同步改寫），再靜默關閉舊路徑。不丟草稿、不留重複標籤。
- 剪下態在 move 貼上成功後清空；複製態保留（可在別處再貼上）。

## C. 編輯器右鍵選單（editor.js）

### 標籤頁選單

右鍵某個標籤（或標籤條空白處，此時以當前啟用標籤為準），選單項：

- 關閉（當前）：現有 `closeFile`，髒則問。
- 關閉左側 / 關閉右側 / 關閉其它：按順序遍歷目標集合，每個髒標籤各彈一次確認（逐個確認）；取消某項跳過它繼續其餘。

選單作用域是右鍵所在的那一塊編輯區（主區/草稿區各自獨立），沿用 `createPane` 工廠，草稿區自動獲得同樣能力。

### 正文區選單

- 僅編輯模式（預覽模式不出現）：剪下 / 複製（無選中時 disabled）/ 貼上（游標處插入，替換選中）/ 全選。
- 實現優先 `document.execCommand('cut'|'copy')` 與 `navigator.clipboard.readText()` 後 `execCommand('insertText')`——保住 textarea 原生撤銷棧；失敗回退 Clipboard API；貼上被瀏覽器拒絕時 toast 說明。
- 通過 view.js 暴露的 `__nfContextMenu` 登記，複用全域選單引擎，不引入第二套選單。

## D. 批次角色卡（工程頁 + characterCard.ts）

### 入口

「角色」分組標題欄與分組空白處的右鍵選單（現有「在此新建角色卡」之下）增加：

- 更新所有角色卡
- 從頭重建所有角色卡

### 後端：`updateAllCharacterCards(project, scope: 'incremental' | 'full')`

1. **制定計劃**：列出全部角色卡 → `buildCastIndex` 給每卡的出場章節；incremental 模式過濾出 `updatedThrough` 之後的新章節。無新章節、或從未出現在摘要裡的卡計入跳過並報數。為每卡預估批數（複用 `planBatches` 的預算口徑，匯出純函式供估算與測試）。
2. **總確認框**（modal）：「將更新 N 張角色卡（跳過 M 張：無新出場/未在摘要出現），共需通讀 X 章、約 K 批，預計呼叫模型 K 次。」按鈕：「逐張確認後開始」/「全部直接採納並開始」/取消。同時滿足「不偷偷燒 token」（先報呼叫次數）與採納方式選擇。
3. **單個 `runTask`**（標題「更新所有角色卡」）：逐卡序列，進度報「第 i/N 張 · 批 j/k」；停止按鈕中止整輪；單卡失敗不阻斷（水位線語義與單卡更新一致）。
4. **審閱**：逐張確認模式複用現有 diff review；全部直接採納模式直接寫盤（使用者在第 2 步已明確選擇）。
5. **收尾**：toast + 日誌彙總「已更新 a 張，跳過 b 張，失敗 c 張」。批次模式**不自動開啟**更新後的卡（區別於單卡流程，避免連開幾十個標籤），路徑只進日誌。

### 協議變更

- `CharacterAction` 增加 `'updateAllCards' | 'rebuildAllCards'`，不帶 name/relPath。

## 約束脩訂

AGENTS.md 行為約束 #7 中「獨立版『檔案』頁的目錄列舉只讀，不提供任何寫入口」修訂為：檔案頁寫入口僅經 `core/projectFiles.ts`，受工程根包含、不靜默覆蓋、垃圾箱豁免等約束；`fileTree.ts` 的列舉仍只讀。

## 測試計劃

- **新增 `scripts/smoke-projectFiles.js`**：根內改名/移動/複製成功；同名拒絕；`..` 逃逸拒絕；資料夾移入自身子孫拒絕；`.trash` 源拒絕；章節改名/移動帶草稿、同步 manifest；多項貼上逐項報錯。
- **擴充套件 `scripts/smoke-characterCard.js`**：批次計劃計算（跳過計數、增量過濾、批數估算）——計劃器以純函式匯出供測。
- **前端**：`scripts/smoke-view.js` 在 jsdom 可覆蓋處補充分組選單登記斷言；編輯器/檔案頁互動走手動驗證（F5 外掛形態不受影響——editor.js/explorer.js 只在獨立版載入；獨立版經 Bun 起服務手測）。
- **門檻**：`npm run typecheck` 零錯誤；`npm run smoke` 全綠。

## 明確不做（YAGNI）

- 不解析系統剪貼簿裡的外部內容做檔案貼上（只外送路徑文字）。
- 不在「更新所有角色卡」裡給未建卡人物建卡（那是既有的「提取角色」流程）。
- 不提供檔案頁的刪除入口（刪除仍只在工程頁，走 `.trash`）。
- 批次更新後不自動開啟角色卡檔案。
