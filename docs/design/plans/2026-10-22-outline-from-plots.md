# 情節大綱改成各章細綱「梗概」的彙總

> 2026-10-22。單獨一件，**在 main 上直接開發**。接著 [2026-10-21-outline-per-chapter.md](2026-10-21-outline-per-chapter.md)（一章一條、按遠近帶，未發版）。起因：作者指出大綱已經一章一句，細綱裡本來就有「梗概」，同一件事存了兩份——大綱改從細綱讀。

## 作者定的（2026-10-22）

作者提方向、說「開工」。下面 ⚑ 是我評估時給的推薦，作者沒逐條答，按推薦做，待作者看。

| # | 問題 | 定案 |
|---|---|---|
| 1 | ⚑ 加一節「一句話簡介」還是用「梗概」 | **用「梗概」**：一句話寫這一章發生什麼、結果如何，最多再補兩句（≤150 字）。它就是大綱裡這一章那一條。再加一節，細綱裡又是兩份相似的東西 |
| 2 | ⚑ 整份大綱怎麼手改 | **彙總文件**：工程頁「情節大綱」照舊開啟 `## 第N章：標題` 格式的整份大綱；儲存時按章號拆回各章細綱 |
| 3 | ⚑ 大綱裡章節之外的東西（開頭一句話、卷標題、備註） | **不儲存**。全書一句話在小說配置裡；卷由正文的目錄管 |
| 4 | ⚑ 老工程磁碟上的 `outline.md` | **不讀、不遷移、一個位元組不動**（區間格式本來就不認，一章一條的格式沒發過版） |

## 存在哪

- 磁碟上**沒有** `outline.md`。`.novelforge/outline.md` 這個路徑仍是情節大綱的身份（編輯器標籤、MCP 的讀寫、`@` 引用），讀寫都由閘道器接住：
  - **讀**：各章細綱（按章號配對的那一份，`pairPlots`）裡「梗概」非空的，一章一條拼成 `## 第N章：標題\n梗概`。`readOutline()` 只給條目；給編輯器的整份另帶一行 `# 情節大綱` 與一段說明。
  - **寫**：按章號拆回去（`model/outlineFile.ts` 的 `planOutlineSplit`，`Workspace.writeOutline` 落盤）。
- 只有梗概、別的幾節都空的細綱叫**空殼**——大綱排到了、細綱還沒拆。`isPlotFilled` 只看「關鍵事件」，空殼天然是「待寫細綱」，狀態機不用改。
- 老工程磁碟上若還有一份 `outline.md`，讀寫都繞開它（閘道器按種類走彙總），檔案留在原處。

## 儲存時怎麼拆（`planOutlineSplit`）

| 情形 | 做什麼 |
|---|---|
| 一條在，這一章有細綱，梗概或標題變了 | 只換「梗概」一節（外科式，別的節與 frontmatter 不動，先存一版歷史）；標題變了走 `writePlot`（還沒有正文時檔名跟著改，與改名同一條路） |
| 一條在，這一章還沒有細綱 | 建一份空殼（有正文落正文的映象，沒有就跟上一章放在一起），`upstreamHash` 不記 |
| 原來有、這一回刪掉了：空殼（除梗概外全空、沒有正文、沒定稿過） | 進回收站（`deletePlot`） |
| 原來有、這一回刪掉了：已經排了細綱或寫了正文 | ⚑ **不刪**，說一聲（要刪去工程頁刪細綱）；彙總文件下一次讀回來那一條還在 |
| 同一章寫了兩條 | 取先出現的（與原來一樣） |
| 章號改了 | ⚑ **按章號對，不搬細綱**：在大綱裡把第 5 章改叫第 6 章，等於改第 6 章那一條、刪第 5 章那一條。插章仍要改檔名（與原來一樣，沒有批次順延） |

覆蓋審閱、樂觀鎖都在整份彙總文件上做（現有 ↔ 新版，審閱框裡看到的就是會寫下去的樣子）；拆回去之後每份細綱各自存歷史版本。

## 指紋鏈（第 18 條）

- 細綱的 `upstreamHash` 從「大綱裡這一章那一條的指紋」改成「**這一章梗概的指紋**」（`plotSynopsisHash`）：排細綱、編輯器裡存細綱時記下當時的梗概。
- 在彙總文件裡改了一章的梗概，細綱 frontmatter 不動 → 這一章已經排了細綱（「關鍵事件」非空）的掛 ⟳（「大綱改了，細綱沒跟」）。⚑ 空殼不掛。
- 定稿照正文改寫梗概，`upstreamHash` 跟著刷成新梗概的指紋（原來沒記過的照舊不記，第 18a 條）。
- 梗概在七節裡，改梗概就是改細綱：寫過正文的章，正文照樣掛 ⟳（「細綱在正文之後改過」）。

## 生成

- **續寫 / 重寫大綱**：模型照舊輸出 `## 第N章：標題` 一章一條；採納時並進彙總文件（`mergeOutline`），審閱，拆回各章細綱。
- ⚑ **重寫大綱只重寫還沒寫正文的章**：寫過的章，梗概由定稿照正文寫，大綱那一條就是實際寫成的樣子，不再讓模型照正文另整理一份。
- ⚑ **「從已寫正文補齊」去掉補大綱那一步**：補齊先給沒定稿的章整理細綱（帶梗概），大綱自然就有了。
- ⚑ **拆細綱（批次）沿用已有的梗概**，不讓模型改寫——空殼的梗概是上游；單章重排細綱以模型產出為準（照舊走覆蓋審閱）。藍圖合同裡 `synopsis` 改成「大綱裡這一章那一條，已有的照抄」，≤150 字。
- 定稿的「梗概」改成一句話加最多兩句（≤150 字）。

## 連帶

- 全書查詢替換不再單列情節大綱（梗概在細綱裡，搜細綱就搜到了）；`outlineOnly` 刪掉。
- 新工程不建 `outline.md`。
- VS Code 殼：情節大綱開在一個虛擬檔案系統（`novelforge:` scheme）上，讀寫同樣經閘道器。
- 示例工程：刪掉 `outline.md`，第 5–10 章改成空殼，第 1–4 章的梗概收成大綱那一條（指紋重算）。
- 外部的 autopilot 指令碼（`skills/novelwarden-autopilot`）算覆蓋到第幾章改成掃細綱的梗概。
- 歷史版本、存檔點不管 `outline.md`（它沒有位元組）：存回去時改了的每份細綱各自存歷史，細綱在存檔點裡就退得回。
- 新的一份一條章標題都認不出（舊格式、散文式）卻要整份換掉有條目的大綱：拒，不寫（照拆會把空殼全刪掉）。

## 我按推薦定的（⚑，待作者看）

1. ⚑ 用「梗概」，不新增一節；梗概收成一句話加最多兩句（合同 ≤150 字，解碼翻倍才截）。
2. ⚑ 彙總文件的路徑沿用 `.novelforge/outline.md`；老工程磁碟上那份不讀、不顯示、不遷移。
3. ⚑ 大綱裡刪掉一條：只刪空殼；排過細綱、寫過正文、定稿過、記過設定的都不刪，說一聲。
4. ⚑ 改章號不搬細綱，按章號對。
5. ⚑ 批次拆細綱沿用空殼上的梗概與標題；單章重排以模型產出為準（走覆蓋審閱）。
6. ⚑ 改標題不算改上游（只改名，不掛 ⟳）；空殼不掛 ⟳。
7. ⚑ 定稿重新整理上游指紋；改過大綱那一條卻照舊稿寫了正文的章，定稿會把梗概改回正文的樣子（⟳ 已經提醒過）。
8. ⚑ 重寫大綱只重寫沒寫正文的章；「從已寫正文補齊」去掉補大綱那一步。
