# 存檔點：整本書存一版、看改了什麼、整本或單份退回去

### 為什麼不接 git

- **三個殼裡有兩個本來沒有 git**：桌面版裝在 Windows 上預設沒有；Docker 映象從前是 distroless（作者要求之後現在有了，但那是給作者自己用的）。要接只能把 isomorphic-git 打進去，專案至今零執行時依賴。
- **會跟作者自己用的 git 打架**：app 自動提交會把作者的提交歷史刷滿「自動存檔」；整本退回用 checkout 會蓋掉作者沒提交的改動（第 3 條）；與 VS Code 的 git 搶 `index.lock`；容器裡沒有提交人身份。
- **一半已經有了**：`workspace/history.ts` 本來就是自己寫的按檔案存歷史。缺的只是「整本書一起存一版、一起回去」。
- （當時還說過「Windows 的 autocrlf 會讓指紋對不上」——**說錯了**：`model/fs.ts` 的 `hash()` 先把 `\r\n` 歸一成 `\n`，換行不影響指紋鏈。已向作者更正，不影響結論。）

git 強的地方（異地備份、多機同步、成熟的 diff 工具）在 app 裡重寫不划算，作者繼續在外面用 git。兩套互不干擾：存檔點的目錄放 `.gitignore`。

## 存法

```
.novelforge/checkpoints/
├── .gitignore                        第一次建這個目錄時放，內容 `*`（同歷史版本：作者刪掉就是想讓 git 收，之後不再補）
├── objects/3f/a9c1…（sha256 餘下 62 位）  檔案內容，位元組原樣（不轉碼、不壓縮）；同樣的內容只存一份
└── points/2026-10-20_22-30-05+0800.json   一個存檔點一份清單（名字的格式同歷史版本的快照，同一秒第二個帶 -2）
```

清單：

```json
{
  "v": 1,
  "time": 1792505405000,
  "note": "第一卷寫完",
  "auto": false,
  "files": { "chapters/第一卷/003-深处.txt": { "sha": "3fa9c1…", "bytes": 9120, "words": 3011 } },
  "skipped": ["chapters/超大的一章.txt"]
}
```

- **存哪些**：`kindOfPath` 不是 `other` 的——與歷史版本同一個口徑（章節、草稿、細綱、角色卡、設定、架構三件、大綱、文風、敘事線、全書摘要、技能、敏感詞表）。敘事線重做之後的 `threads/` 目錄換了種類也自動跟上，不用改這裡。會話、工程庫、回收站、歷史版本、`project.json`（manifest，從章節重算）都不存。只掃章節根、草稿根與 `.novelforge/` 三處，不掃整個工程根。
- **⚑1 超過 2 MB 的單份不存**（`MAX_EDITABLE_BYTES`，與閘道器讀寫同一個上限），記進 `skipped`，介面上說出來（第 2 條：不靜默丟）。
- **去重**：內容按 sha256 定址，第二個存檔點只多存這期間改過的那幾份；清單本身幾十 KB。
- **先寫物件、最後寫清單**：清單是提交點。寫到一半失敗，剩下的只是沒人引用的物件，下一次清理時刪掉。
- **⚑2 整個目錄算 Novelwarden 的內部檔案**（`isInternalPath`）：讀當不存在、寫搬刪都拒、`list` 與全文檢索看不見（「檔案」頁那一層一個檔案都不藏，目錄照樣列得出來，點開讀不到——與會話一樣）。與歷史版本不同（那裡的快照按原路徑排、點開就是一份舊稿），這裡是一堆按 hash 命名的物件，點開沒有意義；要看、要找回，走「存檔點」面板。`watchPolicy` 擋掉它的變動（外掛殼的監聽只吃 `.md`，本來就碰不到）。

## 存

- **手動**：工程頁頁籤條上的 ⚑（或「檔案 → 存檔點…」）→ 寫一句備註（可以空著）→「存一個存檔點」。**⚑3 與最近一個存檔點一模一樣也照樣存**（作者要的是一個帶名字的點；只多一份清單，不佔地方）。
- **自動**：批次動作之前（下一節）。與最近一個存檔點一模一樣就不另存——最近那一個已經就是現在的樣子。
- **同一個工程同一時刻只做一件**：存、清理、退回在程序裡排隊（按工程根一把鎖）。另一個程序同時清理時，只刪一個小時以前寫下的沒人引用的物件，不會刪掉別處正在存的那一份。

## 看

- **列表**（新的在前）：時間、手動 / 自動、備註、這一刻全書正文多少字、多少份檔案。
- **跟現在比**（點一個存檔點）：逐份比 sha，分三類——改過的、存檔點之後刪掉的、存檔點之後新建的；每份帶當時與現在的字數。一模一樣的只報個數。
- **單份對比**：存檔點裡的那一份 ↔ 磁碟上現在這份，走宿主的合併檢視（`Host.mergeTexts`，獨立版與桌面版有）。**⚑4 挑好之後直接寫盤**（經閘道器 `write`，`review: false`、帶開啟對比時的 hash 當樂觀鎖）——這裡沒有編輯區可以放回去，合併檢視裡點的「寫入」就是那一問。外掛殼沒有合併檢視，只說一句。

## 退回

兩種：**退回這一份**、**整本退回**。都在面板上點兩下（按鈕文案兩段式，同全書替換），點的就是那一問。

1. **有任務在跑（批次寫章之類）、或正在生成，就不退**：一邊寫一邊退，結果誰也說不清。
2. **先自動存一個「退回到「10-20 22:30」之前」**——退回本身也能撤回。**⚑5 這一個存不下就不退回**（自動存檔點存不下一律不擋別的動作，唯獨這裡擋：沒有它，整本退回就收不回來了）。
3. 逐份寫回，**位元組原樣**：
   - 編輯器裡有未儲存修改的跳過（前端隨請求帶 `dirty`，同全書替換）；
   - **樂觀鎖**：面板開啟「跟現在比」時每份記下的 hash，退回時對不上（這期間別處又改過）就跳過；當時不存在的、這期間又被建出來的也跳過；
   - 寫回走閘道器新加的 `Workspace.restoreBytes`：過守衛（越界、寫不進去的三處、大小、樂觀鎖），覆蓋之前照樣給這一份存一版歷史（跳過節流），然後原樣寫下位元組。**不跑 handler 的記賬**——⚑6 細綱連同 frontmatter 裡的 `upstreamHash` / `writtenFrom` / `sourceHash` 一起回到當時的樣子，不按大綱此刻的指紋重記（第 18 條：指紋鏈整本退回之後就是當時那條鏈）。只退回一份細綱、正文沒跟著退回時，那一章可能顯示「定稿之後正文改過」——那是實情。
   - 章節寫完之後統一同步一次 manifest。
4. **⚑7 存檔點之後新建的檔案預設不動**；面板上勾「也把存檔點之後新建的 N 份搬進回收站」才搬（經 `remove` 進 `.trash/`，第 6 條）。同樣帶樂觀鎖。
5. 彙總：退回了幾份、搬進回收站幾份、跳過的逐份說為什麼（toast + 日誌），面板隨後重新比一次。

## 保留與清理

- **⚑8 手動的永遠留；自動的留最近 30 個**，多的刪掉最舊的清單，再清掉沒人引用的物件。
- 給一個自動存檔點寫備註就是把它**留住**（變成手動）。
- **⚑9 這一期不提供刪除**：手動的不佔多少地方（去重），要刪可以在磁碟上刪 `points/` 裡那一份，下一次清理帶走沒人引用的物件。

## 自動存檔點

**鉤子在 `features/` 層**（MCP 的外部 agent 調同一個批次功能，也一樣先存）：作者在確認框上點了「開始」、第一次寫盤之前，調 `checkpointBefore(project, '批次寫章之前（第 12–20 章）')`。

| 動作 | 位置 | 備註怎麼寫 |
|---|---|---|
| 批次寫章（含寫完即定稿、邊寫邊拆） | `pipelineBatch.ts` `runWriteBatch`，`runTask` 回呼開頭 | 批次寫章之前（第 a–b 章） |
| 補齊架構 | `pipelineBatch.ts` `fillSettings`，`runTask` 回呼開頭 | 補齊架構之前 |
| 批次拆細綱 | `pipelineBatch.ts` `runPlotBatches`，`runTask` 回呼開頭 | 批次拆細綱之前（第 a–b 章） |
| 全書替換 | `bookReplace.ts` 第 3 步之前，有要換的才存 | 全書替換之前（「甲」→「乙」，N 份） |
| 按目錄整理設定 | `lore.ts` 作者點了「照這樣整理」之後、`applyMoves` 之前 | 按目錄整理設定之前 |
| 批次展開設定 | `lore.ts` `expandLoreEntries`，`runTask` 回呼開頭 | 展開設定之前（N 條） |
| 匯入原稿 | `importManuscript.ts` 確認「匯入」之後 | 匯入原稿之前 |
| 從已寫正文補齊 | `derive.ts` 兩段各自的 `runTask` 開頭（第二段與第一段之間沒有別的改動就不另存） | 從已寫正文補齊之前 |
| 立即同步（逐章定稿） | `summarize.ts` `syncSummaries`，`runTask` 回呼開頭 | 同步章節細綱之前（N 章） |

- **⚑10 比當時說的五個多了幾處**（批次拆細綱、批次展開設定、立即同步）：都是一次改很多份的批次動作，與最近一個一樣時不另存，多掛幾處沒有代價。從已寫正文補齊是兩段（先整理細綱、再補其餘幾樣），第一段存過第二段就不另存——退回去就是整件事之前；代價是沒法只撤第二段、留下第一段花錢整理的細綱。
- **⚑14 連著的兩件事各存一個**：批次拆細綱勾了「拆完展開本批新設定」，展開那一步另存一個（拆完狀態已經變了，展開本來也另問一次）；匯入原稿之後接著補齊，先後存「匯入原稿之前」「從已寫正文補齊之前」兩個。
- **⚑15 備註裡的區間與份數照確認框說**：批次寫章寫的是實際要寫的第一章到最後一章（寫完即定稿時帶上「寫完即定稿」，寫完即審稿不提）；批次拆細綱寫作者選的整個範圍；全書替換的「N 份」是通過核對、準備要寫的份數，查詢串與替換串各截到 12 個字。
- **⚑11 存不下不擋批次動作**：記一條 warn、任務日誌裡說一句，照常跑（第 1 條；每份檔案覆蓋之前的歷史版本照常存）。
- 放在 `runTask` 回呼裡（而不是確認框之後立刻）：確認之後模型池可能「沒有可用的模型」直接返回，那樣存了一個沒用的點。
