## 0. 結論

1. **鏈路整條搬過來**：一句話 → 設定 → 前提 / 角色圖譜 / 世界觀 / 情節大綱 → 細綱（一章一份，每批 5 章）→ 正文（自動續寫到目標字數的 80%）→ 定稿（摘要 + 連續性事實 + 角色當前狀態）→ 審稿（逐字引證 + 目標核對）→ 按勾選的意見最小改動修稿 → 序列批次。只有和「寫得好不好」無關的發行級工程不搬，逐項取捨見 §1。
2. **順手修掉上游自己的四個缺口**：
   - 角色設計原則沒發給模型；
   - 英雄之旅、節拍表兩種結構沒有章號區間；
   - 單章入口的執行卡漏了章末鉤子；
   - 精修不帶上下文。

   另外不搬它寫死的 8192 輸出上限。
3. **WebUI 從「對話頁驅動」改成「工程頁就是進度」**：
   - 工程頁每一行都帶狀態，只有下一章給「寫這一章」的按鈕；
   - 任務進度在所有頁籤都看得見；
   - 細綱和正文可以並排看；
   - 覆蓋和修稿一律走 diff，並且能逐段採用。

   量化目標：從一句話寫到第 3 章，現在約 **44 次點選、3 次手動切頁**（推斷，見 §3.1）。改完後單步路徑 **≤ 22 次**，批次路徑 **≤ 10 次**。
4. **分八期（零到七）**：
   - 三期結束是**真實模型驗收關卡**：前 3 章讀得下去才往下做。
   - 七期做敘事線；匯入已有小說延後，不排期。
   - 每期結束 `npm run typecheck` + `npm run test:node` 全綠，工程**始終能跑**，不留半截狀態。
5. **量級**：src 刪約 1.5k 行、重寫約 4.7k 行、新增約 5–6k 行（core 約 3k，前端約 2.5k）；測試重寫或新增約 7k 行。

### 2.2 狀態機（`model/pipeline.ts` 重寫）

- **創作階段**：`setting | outline | plot | manuscript`。`setting` 下有四個 target：`config / premise / characters / world`。
- **能力**：保留 `discuss / generate / settle`；新增 `review`，只掛在正文層；刪掉 `split`。
- **一條軸**：細綱號 = 章號。刪掉 `segmentDisplayNo`、`volumeLabel`、`segmentLabel` 等位次和稱呼函式。

**全書下一步**（`deriveBookNextStep`，按順序取第一個不滿足的）：

| 狀態 | 主按鈕 |
|---|---|
| 沒有 `config.md` | 生成設定（開啟「一句話」彈窗） |
| 前提 / 角色 / 世界觀缺哪一件 | 生成前提 → 生成角色圖譜 → 生成世界觀（按順序一件一件推） |
| 沒有大綱，或下一批細綱超出大綱覆蓋的章號 | 生成情節大綱（第 a–b 章） |
| 下一可寫章沒有細綱 | 拆細綱（第 N–N+4 章） |
| 進入單章狀態機 | ↓ |

**單章下一步**（`deriveNextStep`，「下一可寫章」= 連續已有正文的最大章號 + 1）：

| 狀態 | 主按鈕 |
|---|---|
| 有細綱、沒正文 | 寫第 N 章 |
| 正文不到 `targetWords` 的 80% | 接著寫 |
| 細綱在正文之後改過（hash 不符） | 重寫第 N 章 |
| 正文寫夠，摘要缺失或過期 | 定稿第 N 章（摘要 + 角色狀態，2 次呼叫） |
| 都齊 | 跳到下一可寫章 |

審稿**不進主按鈕**，它是可選動作，放在正文層的 `/审稿` 和章節工作臺的工具欄裡。第 20 條「只推一個下一步」不變。

**指紋鏈**（第 18 條重寫）：`config / premise / characters / world` → `outline` → `plot` → `chapter` → `summary`。每一環的上游指紋都記在下游：
- 細綱記在 frontmatter；
- 正文記在 `project.json` 的 manifest（沿用從前放 `beatsHash` 的位置）；
- 摘要記 `sourceHash`。

鏈上不再有「拆分」這道人工閘口：已經定稿的章只掛 ⟳ 提醒，不會被推回「待寫」。

### 2.4 生成機制

- **續寫迴圈**：放在 `generation/`，不放進 feature。
  - `generate.ts` 的流式迴圈接上 `stop` 事件（現在忽略了它，`generate.ts:211-225`）。
  - 停止原因是 `maxTokens`，或者正文不到目標的 80%，就續寫。續寫提示詞帶最後 1600 字 + 細綱 + 執行卡。
  - 同一個 Draft 裡追加，介面實時顯示「第 k 輪 · 已寫 x / 目標 y 字」。
  - 最多 7 輪。一輪新增 <300 字且又被截斷：丟棄這一輪，只給 1 次恢復機會。
  - 思考把輸出預算耗光（截斷且正文 <100 字）：直接報「輸出上限不夠思考」，提示調大 maxOutputTokens 或降低思考深度。
  - 最後仍不到 80%：報「未寫夠」，**已寫的內容不丟**，卡片照樣可以「寫入」。

- **測試**：用假模型覆蓋以下情況：
  - 一次寫夠；
  - 截斷後續寫；
  - 不到 80% 時續寫；
  - 續寫沒有增長被丟棄，恢復一次；
  - 思考耗盡報錯；
  - 最終未寫夠但已寫的不丟；
  - 重演被拒；
  - 預計呼叫次數的文案。
- **真實模型驗收**：同一句腦洞跑到前 3 章，匯出 Markdown 發給你讀。**你判斷讀得下去，才進四期。** 讀不下去就在這一期裡調提示詞和配方，不往後堆功能。預計 15–25 次呼叫，走 newapi 閘道器，模型用 `step-5-preview` 或 `gemini-3-flash-lite`（地址和 key 到時實測確認）。

### 四期 · 定稿 + 證據 + 序列批次（M）

- **定稿動作**：先生成摘要（六節 + 連續性事實），再用 bigram 給每條事實掛證據（零呼叫），然後更新出場角色的「當前狀態」（一次呼叫出所有人的，按 D15 決定寫不寫）。共 2 次呼叫。
- **`evidence` 層**：按 D18 實現，明細裡列出定位成功和降級的條目。
- **批次寫章**（`features/pipelineBatch.ts`）改成嚴格序列：寫一章 → 落盤 → （寫完即定稿模式下）定稿 → 下一章。已有正文的章跳過；失敗立刻停；只在章與章之間暫停。工程頁批次任務不帶思考深度（第 26 條）。
- **前端**：W8 全域任務條、W9 批次彈窗、定稿按鈕；角色卡上顯示「狀態截至第 K 章」。
- **驗收**：整合測試連寫 3 章，第 3 章的上下文裡能看到第 2 章更新過的角色狀態，也能看到第 2 章的證據原文段落。作者手改過「當前狀態」的卡不會被覆蓋，而是掛黃 ❗。

### 五期 · 審稿 + 修稿 + 預檢（M）

- **`review`**：一次呼叫出報告 JSON，1–10 條，每條帶逐字引文；目標核對清單逐項判定。
- **引文校驗**：在正文裡逐字找（歸一化空白和標點後），找不到的條目丟棄；目標核對裡找不到引文的降成「待核實」。「沒寫到」只能判待核實，不能判未完成。
- **修稿**：只把勾選的條目塞進 `revision` 層，要求最小改動；續寫最多 3 次；完整性校驗照搬 `refinement-completeness.ts:3-41`；覆蓋前走 diff。
- **精修**：補上本章細綱作上下文（修上游的缺口）。
- **一致性預檢**：零呼叫，警告掛在寫章卡片上，可以「僅本次忽略」。
- **前端**：W10 審稿報告卡、W11 diff / 合併檢視。
- **驗收**：偽造引文的條目被丟棄；修稿後長度低於閾值時報錯；diff 檢視裡「採用」不會沖掉手改過的段（DOM 測試）。

## 7. 測試策略

- **假模型**：零期擴充套件後能指令碼化多輪迴復和 stop 原因。續寫、截斷、修復鏈全靠它測，不花錢。
- **測試怎麼動**：
  - 老流水線的測試**先刪後寫**，不在舊斷言上修修補補；
  - 通用的測試（預算器、agent 迴圈、工具登錄檔、runtime、角色卡、lore 等，約 9k 行 src 對應的那部分）一律不動，它們變紅就說明改錯了。
- **夾具**：sample-novel 重做時 3 章正文不動，只改 `.novelforge/` 下的東西。
- **契約測試**：corePurity、shellPurity、layerBoundary 全程守著分層。
- **真實模型**：只在三期驗收時跑一次，之後每期結束可以選跑前 1 章做冒煙（每次約 3–5 次呼叫，要你點頭才跑）。

## 8. 風險

| 風險 | 緩解 |
|---|---|
| 提示詞搬過來了還是寫不好 | 三期設了關卡，不過關不往後做；問題收斂在提示詞和配方上，那兩處改起來最便宜 |
| 一期改動面最大，中途工程跑不起來 | 一期結束的驗收要求獨立版能開啟、主按鈕正確；一期內部按「model → workspace → views → protocol → 前端」自底向上，每個 commit 編譯通過 |
| 思考模型把輸出預算吃光 | §2.4 專門識別這種情況並報錯，提示調大 maxOutputTokens 或降低思考深度 |
| 自動續寫把賬單拉高 | 上限 7 輪，呼叫次數寫在動手之前；批次不帶思考 |
| 從 GPL 專案搬提示詞 | AGPL 與 GPLv3 按 §13 可以組合；移植處在註釋裡註明來源 |
| diff 檢視自己寫有 bug | 段級 LCS 是純函式，單測覆蓋；VS Code 殼不用它 |
| 老工程開啟後什麼都沒有 | D11 已接受；「匯入已有小說」是補救路徑（2026-10-02 已做：主按鈕在有正文卻缺架構時推「從已寫正文補齊」，見 [拆書計劃](2026-10-02-book-import.md)） |
