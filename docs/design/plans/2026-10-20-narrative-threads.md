## 現狀：為什麼「不會自動」

1. **線只有一個來源**：只能從細綱排（`features/threads.ts:137`），而且只有批次拆細綱、批次寫章邊寫邊拆這兩處自動排（`pipelineBatch.ts:219`、`:720`）。對話頁逐章生成的細綱、拆書匯入、從已寫正文補齊（`derive.ts` 只調 `summarizeChapters`）都不排。定稿只判已有的線，**不會新建線**。
2. **一樣東西記了四份，互相不通**：細綱「新增伏筆」（`plotFile.ts:98`）、全書摘要「未收伏筆」（`summarizePrompt.ts:87/105`，它唯一的來源就是細綱那一節）、角色卡「未收伏筆」（`types.ts:88`）、`threads.md` 的「埋下」事件。
3. **排細綱時不看線**：`plot` 配方里沒有敘事線這一層（`recipes.ts:121-141`），回收靠運氣；寫前檢查、審稿也不看它。只有寫正文時提醒一句，可那時細綱已經定死了。
4. **看不出進度**：工程頁只有一行計數（「5 條 · 3 條進行中」），沒有一條線現在走到哪的說法，也沒有時間軸。
5. **沒線時什麼都不說**：定稿第三步 0 次呼叫時完成提示一個字不提（`finalize.ts:137`），「立即同步」的提示卻照樣說「敘事線跟到了這幾章」（`summarize.ts:359`）。0.2.4 及以前的「立即同步」根本不判敘事線（`5744917` 才補上），那些章已經算定稿，黃條不會再提醒。

- **一條線一個檔案**是這條線的唯一真相：意圖、當前進度、伏筆、計劃事件、實際事件都在裡面。

- 細綱裡不再有任何關於線的東西；全文大綱只寫主線怎麼走過來的；角色卡只寫現在的關係。**同一樣東西只有一份。**

## 資料格式

### 一條線：`.novelforge/threads/<线名>.md`

```markdown
---
kind: 感情線            # 主線 / 支線 / 感情線 / 人物線；認不出當支線
origin: 計劃            # 計劃 / 正文：排線排出來的，還是定稿時從正文裡認出來的

progressThrough: 12     # 「當前進度」寫到第幾章
progressHash: …         # 機器最後一次寫「當前進度」時的指紋；對不上就是作者改過
generatedBy: novelwarden

# 林昭與沈青

## 意圖
從互相猜忌到並肩，第 40 章前確定心意。

第 12 章兩人在青崖鎮結盟，沈青仍瞞著自己是沈家遺孤。

- 第 3 章 · 計劃 · 埋〈玉佩的來歷〉：打鬥中玉佩露出來
- 第 3 章 · 推進：兩人在鎮口初遇，沈青出手試探 〔證據：「她的劍停在他喉前三寸」〕
- 第 3 章 · 埋〈玉佩的來歷〉：玉佩第一次露面 〔證據：「他摸了摸懷裡那塊溫潤的玉佩」〕
```

- **檔名就是線名**（同名按 `normalizeQuote` 歸一判）。`未归属的伏笔.md` 是保留名，排線、定稿都不許用它當線名。
- **意圖**：排線時寫，之後機器不改（≤200 字）。
- **當前進度**：一兩句話說這條線現在走到哪了（≤150 字），**機器維護、指紋守著**——照角色卡「當前狀態」的做法（`model/characterState.ts`）：空的或指紋對得上才寫；作者改過就不寫，掛黃 ❗ 在這條線上。
- **伏筆**：一行一條，`名：是什麼（計劃第 a 章埋、第 b 章前收）`，括號可缺。機器只往末尾加新的，不改已有的行。
- **進展**：一行一個事件，`第 N 章 · [計劃 · ]型別[〈伏筆名〉]：一句話[ 〔證據：「原文」〕]`。
  - 線的事件：**推進 / 關係 / 收束**（這條線走完了）**/ 放棄**；伏筆的事件：**埋 / 收 / 棄**。
  - 帶「計劃 ·」的是計劃事件（拆細綱寫進來的），不帶的是實際事件（定稿寫進來的，必須帶證據）。
  - 作者手寫的行可以沒有證據，照認；認不出的行原樣留著、不當事件（第 1 條）。
- **狀態現算**：線是「計劃中」（沒有實際事件）/「進行中」/「已收束」/「已放棄」，另算「最近一次推進在第幾章」「斷了幾章」「過了計劃收束章」。伏筆是「計劃」/「已埋」/「已收」/「已棄」，另算「逾期」（過了第 b 章還沒收）。「現在」指定稿到的最後一章；寫第 N 章時一律按「寫到第 N 章時」算（只看第 N 章之前的事件，同七期的 `asOf`）。

### 未歸屬的伏筆：`.novelforge/threads/未归属的伏笔.md`

與一條線同樣的「伏筆」「進展」兩節，沒有意圖、當前進度、種類。作者把一行伏筆連同它的事件剪到某條線的檔案裡，就是掛上了（不另做「挪」的按鈕，⚑）。

### 誰能寫什麼

| 內容 | 誰寫 | 怎麼寫 |
|---|---|---|
| 新線、新伏筆 | 排線、拆細綱、定稿 | **只追加**：新檔案 / 「伏筆」末尾加一行；同名跳過 |
| 計劃事件 | 拆細綱（批次與單章） | **隨細綱走**：第 N 章的細綱寫入時，各線裡第 N 章的計劃事件整組換掉（寫入卡片上列出來）；別的章不動 |
| 實際事件 | 定稿 | **只追加**，證據逐字校驗；重新定稿第 N 章時，第 N 章機器記的事件裡**證據已經不在正文裡的**刪掉（⚑，舊版先存一版歷史） |
| 當前進度 | 定稿 | 指紋守衛：作者改過就不寫、掛黃 ❗ |
| 意圖、作者手寫的任何行 | 作者 | 機器一個字不動 |

```
定稿第 N 章
  1. 照正文更新細綱（1 次）
  2. 角色狀態（0–1 次）
  3. 敘事線（1–3 次）
     a. 認事件（1 次）：正文 + 沒收束的線 + 沒收的伏筆 + 本章計劃事件 → 實際事件、新線、新伏筆、關係變動（證據逐字校驗）
     b. 當前進度（0–1 次）：本章有實際事件的那幾條線 → 各自的當前進度
     c. 歸併（0–1 次）：a 報了新線 / 新伏筆、名字又對不上已有的 → 判是不是已有的那一條換了個說法
```

- **a 認事件**每次定稿都跑，線是空的也跑：正文裡長出來的線只能在這裡認出來。所以**定稿最少 2 次**（⚑，從前最少 1 次）。
  - 輸入：本章正文（放不下截尾，證據仍對整章校驗）；沒收束的線（名字、種類、意圖、當前進度、最近兩條實際事件）；沒收的伏筆（名字、是什麼、掛在哪條線、計劃第幾章收）；本章的計劃事件（讓模型知道這一章本來要幹什麼）。線與伏筆的條數按上下文詳細度封頂（沿用 `threadJudge`，伏筆另給一組），沒送去的寫日誌。
  - 輸出：`{"events":[{"line","type","foreshadowing","what","evidence"}],"newThreads":[{"title","kind","intent","evidence"}],"newForeshadowing":[{"title","what","line","evidence"}]}`。
  - 校驗沿用七期的 `verifyThreadEvents`：線認得出（或者就在 `newThreads` 裡）、型別認得出、證據歸一後至少 4 個字且在正文裡找得到；一章最多 8 個事件、2 條新線、5 條新伏筆。
  - **新線要有證據、種類是四種之一，主線已有就不收新主線**；新伏筆掛不上線的進「未歸屬的伏筆」。
  - 關係變動就是一個 `關係` 事件，掛在相關的那條線上（感情線、人物線最常見）；掛不上的丟掉。
- **b 當前進度**只給本章有實際事件的線寫，一次寫完幾條。輸入是這幾條線的意圖、舊的當前進度、本章的事件；每條 ≤150 字。作者改過的（指紋對不上）不送去，掛黃 ❗。
- **c 歸併**只在 a 報了新東西、名字又和已有的對不上時才調：把新的和已有的名字、意圖交給模型，問它是不是同一條。是的就並進已有的那條（事件掛過去，不建新的）。沒有新東西就是 0 次。
- **失敗各算各的**（第 16 條）：a 失敗，b、c 不走，黃 ❗ 掛在章節上；b、c 失敗，a 記下的照樣算數。
- **用哪個模型**：單章入口用對話頁選定的那個；批次（立即同步、寫完即定稿、補記）走「定稿」檔（`plotSummary`），同七期。
- `FINALIZE_CALLS` 改成 `{ low: 2, high: 5, max: 5 }`，主按鈕、右鍵、批次確認框都用它；批次寫章「寫完即定稿」、「立即同步」的上限跟著變。
- **完成提示一定說敘事線**：「敘事線：林昭與沈青推進；埋〈玉佩的來歷〉；新認出 1 條線〈沈家舊案〉（支線）」；什麼都沒認出就說「敘事線沒有新進展」。「立即同步」的提示按實際結果說，不再一律說「跟到了這幾章」。

## 四、寫正文、寫前檢查、審稿

### 寫正文：`threads` 層改造

仍是正文配方 P1、緊跟大綱那一節；續寫、修稿不帶。挑法：本章有計劃事件的線 → 主線 → 計劃收束章就在附近的 → 最近推進過的；伏筆裡**計劃在本章收的、已經逾期的**排最前。一條線一行：

```
- 林昭與沈青（感情線 · 進行中）現在：兩人已結盟，沈青仍瞞著身份；本章計劃：推進——沈青第一次替林昭擋刀；沒收的伏筆：玉佩的來歷（第 18 章前不要揭開）
```

- 「現在」按寫到第 N 章時算：`progressThrough ≥ N`（重寫前面的章）時不用當前進度，改用第 N 章之前的最近兩條實際事件，免得把後面的劇情透給前面。
- 沒到回收章的伏筆一律寫「第 b 章前不要揭開」，這是這一層存在的另一半理由（同七期）。
- 條數、字數按上下文詳細度，放不下的寫進明細。

### 寫前檢查：兩類提醒，不調模型、不攔人

照「設定還只有一句話」（`thinLoreFor`）那套做，**不進 `risks`**（那是要攔人的），`PreflightResult` 另加一個提醒欄位：

- **伏筆逾期**：計劃第 b 章前收、寫第 N 章時（N > b）還沒收，本章計劃裡也沒收它。
- **線斷了**：進行中的線已經 K 章沒有實際事件，本章計劃裡也沒推進它。⚑ K：主線 5 章，其餘 15 章，先寫死。

顯示在對話頁寫正文前的卡片、批次寫章的確認框、章節工作臺、前端批次彈窗這四處。

### 審稿：這一期先帶「沒收的伏筆」

審稿提示詞裡兩條伏筆檢查（`prompts.ts:532-533`「是否存在應回收而未提及的前置伏筆」）現在的材料只有角色卡的「未收伏筆」和本章細綱的「新增伏筆」，這兩樣都並走以後它就沒材料了。⚑ 所以**這一期審稿配方先帶敘事線層的伏筆部分**（沒收的伏筆、本章計劃的埋與收），整條線「計劃推進的寫到沒有」的檢查照作者定的放到下一期。

4. ⚑ **線的格子只放線自己的事件**（推進 / 關係 / 收束 / 放棄），伏筆的事件在伏筆那幾行；沒寫伏筆名的伏筆事件沒別的行可放，放線上這一行。
   **偏差** = 這一章有計劃、那一章定稿了，卻一條實際的線事件都沒有；計劃了推進與關係、只發生了推進的算 ◉（懸停看得到兩邊各是什麼）。
   比的是「那一章定稿了沒有」，不是「現在」：前面有沒定稿的章時，它們上的計劃不算偏差。
5. ⚑ **伏筆的偏差**：計劃在第 N 章埋的，第 N 章定稿了、到第 N 章為止還沒埋（也沒收、沒棄）；計劃在第 N 章收的，到第 N 章為止還沒收（或棄）。
   提前埋了、提前收了的不算。
6. ⚑ **推遲迴收怎麼畫**（二期留的問題）：沒收的伏筆，虛線從埋的那一章延到**伏筆那一行寫的回收章與計劃裡收它的那一章取晚的**；回收章那一格
   另畫一道豎線（`.tov-due`），計劃的收畫空心 ◇——虛線越過豎線，一眼看得出推遲了。逾期的延到「現在」、整條標紅；埋了卻一樣都沒寫的也延到
   「現在」（它還掛著）。還沒埋的按計劃畫一條淡點線（伏筆那一行寫的埋章，沒寫取計劃裡埋它的那一章 → 回收章），缺一頭不畫。收了、棄了的從
   埋的那一章實線連到收（棄）的那一章，沒埋過就不連。
7. ⚑ **一格伏筆畫哪個記號**：實際的先（棄 ✕ → 收 ◆ → 埋 ●），沒有實際的畫計劃的（收 ◇ → 埋 ○）；偏差的記號標紅。
8. ⚑ **線的計劃區間畫一條淡底**（設計稿沒寫）：還沒推進過的線在總覽上也看得出它該在哪一段。只寫了開頭的延到最後一列，只寫了收束章的從第 1 章起。
9. ⚑ **編輯區的特殊標籤是一個通用介面**（`editor/store.ts` 的 `SpecialTab`：`label` / `show` / `hide` / `menu`），`pane.ts` 只認它，不知道
   裡面畫的是什麼。**顯示它時這一塊沒有當前檔案**（`activePath` 是 null）：儲存、查詢、體檢、歷史版本、章節條都當這一塊沒開檔案，不會對著
   藏在後面的那一份動手。標籤排在檔案標籤**前面**（它是一張總表，不隨開開關關的檔案挪位置）；同一時刻只在一塊裡，預設開在主區；×、中鍵、
   Ctrl+W、「檔案 → 關閉編輯器」關掉它，回到切過去之前的那一份；檔案都關了、它還開著就顯示它；「▾」列表裡有它；右鍵只有「關閉」「重新整理」，
   不給「移到另一側」「關閉其它」。
10. ⚑ **重新整理恢復**：快照多 `specials` / `special`，`active` 記切過去之前的那一份。`restore()` 先開特殊標籤（不寫 localStorage：檔案還沒回來，
    這時寫下去會把它們從待恢復的清單裡沖掉），陸續回來的檔案不把正顯示著的它換下去（`upsertFile` 認得出是重新整理恢復的：有 `pendingDrafts`、
    不是搬家），作者此刻從別處開啟的照常切過去；沒在顯示的恢復成背景標籤、不畫、不要資料；認不出的 id、形狀不對的一律不認、不崩。
11. ⚑ **點格子發 `openChapter`**（與工程頁點章節行、「轉到…」同一條：正文進主區、細綱並排；還沒寫的只開細綱），總覽的標籤被換到後面（標籤
    還在，點一下回來）；**點列頭也開啟那一章**（設計稿沒寫）。細綱、正文都沒有的章說一句、不發。點線名、伏筆名、「未歸屬的伏筆」開啟那份
    檔案，開在總覽所在的這一塊（正常標籤，作者明說要看它）。
