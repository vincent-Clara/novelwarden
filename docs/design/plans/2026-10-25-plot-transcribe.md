# 按格式寫、轉寫模型照抄成 JSON（2026-10-25：細綱試點，同日推到全部結構化產物）

## 為什麼

作者實測：同一份上下文，要模型直接按 JSON 合同輸出細綱，與放開寫相比內容明顯不同、質量更差。JSON 只是程式要的運輸格式（細綱落盤還是 Markdown），不該讓寫細綱的模型去背。

作者定的：先拿細綱試；轉寫用**固定的轉寫模型**（不跟對話頁選的、也不跟確認框上為這一次挑的模型）；轉寫模型沒配就按預設走。

## 做法

1. **寫**：細綱（寫第 N 章細綱、落定細綱、對話頁拆細綱、工程頁批次拆細綱、邊寫邊拆）的提示詞不再要 JSON，改成按小標題寫自然語言（`context/prompts.ts` 的 `blueprintFormat`）：一章一個「## 第N章：標題」，下面九個小標題——細綱七節（連續性事實除外）加「敘事線」「新角色」「設定」。各節寫什麼照原來的 JSON 合同搬過來，只把欄位名換成小標題。
2. **轉寫**：新任務 `transcribe`（「轉寫 · 細綱整理成 JSON」，預設快速檔）把原文照抄成原來那份 `{"blueprints":[…]}`（`blueprintJsonContract` / `blueprintTranscribeMessages`）。只帶合同與原文，不經裝配器、不帶書的上下文；溫度 0、不帶思考。
3. **查**：解碼、章號對賬照舊（`decodeBlueprints` / `checkCoverage`），另加一道「每段文字都出自原文」（`features/structuredJson.ts` 的 `unfaithfulStrings`）。
4. 後面的落盤、敘事線計劃、建角色卡與設定空條目一行沒改——它們吃的還是同一份 JSON。

## 定下的幾處（⚑ 我按推薦定的，待作者看）

- ⚑1 **格式**：九個小標題、一章一個「## 第N章：標題」；敘事線 / 新角色 / 設定只說每條要寫清哪幾樣，怎麼寫隨它。
- ⚑2 **「出自原文」怎麼比**：兩邊去掉空白、標點與符號後看是不是原文的一段（去掉行首「-」、兩行並一條、拆成兩條、換引號都不算改）。章號、推進 / 埋……、主角 / 反派……、男 / 女、新不新、第幾章前收、分類按對應關係填，不比。
- ⚑3 **批次重試**：轉寫不合格（截斷、解不開、漏了原文寫了的章、改了字）**全程只重轉一次**，說清上次哪幾處不對；還不行走原來的降級鏈（多章對半拆、單章緊湊重建，各自重寫重轉）。原文就沒寫的章（連「第 N 章」都沒有）是偷懶，直接報漏寫、不重轉。
- ⚑4 **單章寬鬆**：轉寫兩次都不合格不報錯，把原文交回去按小節讀（七節讀得出來，敘事線計劃、新角色、「設定」一節讀不出來），卡片說明裡寫清。同從前單章的全文兜底：作者當場過目。
- ⚑5 **不轉的兩種**：模型自己給了合格 JSON（沒照格式寫、老會話）不轉；連「梗概」「關鍵事件」都沒有的輸出（「我不太確定」）不轉，按解不出來走降級，省一次轉寫。
- ⚑6 **呼叫次數**（第 4 條）：單章 2 次、最多 3 次（`PLOT_CALLS`）；一批 n 章 2 次、最多 6n − 1 次（5 章最多 29 次，原來 15 次）。寫細綱最多 3n − 1 次（拆半 2n − 1 + 重建 n），轉寫每次寫完一次再加全程一次重轉。
- ⚑7 **轉寫那一檔一個可用模型都沒有**（連預設模型都建不出來）：退回幹活那個模型轉寫，日誌裡說一聲。
- ⚑8 **對話頁氣泡**：轉寫的輸出不流進氣泡，只加一行「——第 6–7 章轉寫成 JSON（快速檔：xxx）——」；鏈結束後氣泡照舊換成規範化 JSON。
- ⚑9 **確認框**：批次拆細綱、批次寫章（邊寫邊拆）的確認框單列一行「轉寫 · 細綱整理成 JSON → 快速檔：xxx（不跟這一次挑的模型）」，挑了具體模型也照樣顯示。AGENTS 第 12 條加了這一條例外。

## 試跑（gemini-3-flash-lite，2026-10-25）

寫細綱與轉寫同一個模型，同一本書拆第 11–15 章兩遍、單章第 16 章一遍：新版 3/3 成，轉寫都一次過、逐字一致；舊版（直接出 JSON）有 1 次漏一個引號、語法修復又改了內容被拒，整批沒寫進去。細綱質量在這個小模型上看不出高下。報告：`project-reports/2026-10-25-novelforge-plot-transcribe-trial.md`。

## 二期：推到全部結構化產物（同日，作者：「把全部需要 json 的步驟都改成這種模式」）

公用骨架 `features/transcribe.ts` 的 `transcribeJson`（原文是 JSON 不轉、不像這一步的不轉；照抄 → 「無」換空 → 每段文字出自原文 → 這一步原來的解碼，不合格重轉一次；轉寫呼叫失敗不往外拋，照這一步原來解析失敗的走法）。每一步只給合同、解碼與按對應關係填的鍵；解碼函式基本沒動。工程頁任務經 `poolIO.ts` 的 `poolTranscriber` 拿轉寫呼叫，生成鏈經 `Tally.transcribeJson`。從前的「語法修復一次、只許改標點」整套刪了（轉寫順帶理順語法）。

| 步驟 | 幹活的模型現在怎麼寫 | 呼叫次數（原來 → 現在，預計 / 最多） |
|---|---|---|
| 小說配置 | 一個欄位一個「## 小標題」，故事結構、視角寫中文詞 | 1 / 3 → 2 / 5 |
| 角色圖譜（身份清單 + 詳情） | 一人一個「## 名字」，定位 / 性別 / 敘事職責 / 關係；詳情七個小標題 | 2–4 / 16 → 4–8 / 31 |
| 設定清單（清單 + 詳情） | 「## 分類」「## 清單」一條一行；詳情三節 | 3–6 / 封頂 12 → 6–12 / 封頂 24 |
| 展開一條設定 / 落定設定 | 八個小標題 / 一條一個「## 名字」加「還沒定的問題」 | 1 / 2 → 2 / 3（批次展開每條最多 4） |
| 審稿 | 「總評」「問題」「目標核對」三節，引文用「」 | 1 / 3 → 2 / 7 |
| 寫前衝突檢查 | 「無矛盾」或一處一段，兩句原句用「」 | 0–1 / 2 → 0–2 / 3 |
| 同步一章（細綱 + 角色狀態 + 敘事線 + 故事時間） | 細綱八個小標題；狀態一人一節；敘事線見下；時間一章一節九項 | 3–6 / 6 → 6–12 / 18 |
| 排敘事線 | 一條線一段「## 線名」+ 種類 / 章節 / 意圖 / 伏筆 | 1 → 2 / 3 |
| 敘事線判一章（認事件 / 歸併 / 當前進度） | 「## 事件」「## 新線」「## 新伏筆」一條一行，證據用「」；歸併「新 → 已有：理由」；進度「【線】」一段 | 1–3 / 3 → 2–6 / 9 |
| 故事時間（補推一批） | 一章一節「## 第N章」九項 | 1 → 2 / 3 |
| 角色卡更新、提取角色、記設定、按目錄整理 | 十個小標題 / 一人一個「## 姓名」/「- 名字（分類）：說明」/「## 新目錄」「## 搬家」 | 1 → 2 / 3（每批 / 每章） |
| 建條目 / 整合 | 「一句話」「關鍵詞」兩行加三節 | 1 / 2 → 2 / 6 |

各步的內容要求（字數、條數、照抄名字、證據逐字、暗設只做減法、統稱第 5 條……）一條沒丟，只改了說法；證據與引文轉寫之後照舊由原來的校驗對正文逐字核。確認框上凡是會轉寫的都單列一行「轉寫 → …（不跟這一次挑的模型）」。

### 二期定下的幾處（⚑ 按推薦定的，待作者看）

- ⚑10 各步的格式就是上表那樣；名字、證據之外按對應關係填的（定位、種類、嚴重程度、結論、天數、時段……）寫中文詞，轉寫時對到程式碼，不比原文。
- ⚑11 角色圖譜的編號就是名字，關係指向名字；轉寫模型照抄了中文定位（「主角」）的先對回英文程式碼再解碼。
- ⚑12 角色詳情、設定清單詳情全程只重轉一次（同從前的語法修復）；設定清單的封頂 12 → 24，轉寫也算，一批要放得下「寫 + 轉寫」才開。
- ⚑13 失敗走法照各步原來解析失敗的走法：配置、單章細綱、同步的細綱轉不成按小節讀原文（說明裡寫清讀不出的幾項）；設定清單、展開、落定轉不成不給寫入；審稿轉不成按格式重寫 1 次再轉（最多 7 次）；寫前比對轉不成當沒做成、照寫；敘事線認事件轉不成停在這一章掛 ❗；角色卡這一批跳過掛 ❗；記設定「設定」一節不動掛黃 ❗；建條目 / 整合這一條重寫一次再轉（最多 6 次）。
- ⚑14 原文明說沒有的不轉：寫前比對只寫「無矛盾」、角色狀態只寫「無」、敘事線三節都「無」 / 不歸併——實際只調 1 次，預計裡的下限仍按 2 報。反過來，原文寫了條目、轉寫一條都沒有的算不合格、重轉一次（敘事線、提取角色）。
- ⚑15 同步的「設定」一節與單獨記設定共用 `LORE_FIELD_RULES`（欄位名換成中文：名字、分類、說明），一行一條的格式各自說（同步「- 名字〔分類〕：說明」，記設定「- 名字（分類）：說明」）。
- ⚑16 故事時間的 date、season 不放進按對應關係填的鍵：裡面的月日、節令本來就是從原文抄的，要比。
- ⚑17 批次寫章「寫完即審稿」轉不成時，寫好的報告不留進「批次審稿」會話，只記一句報錯（同從前）。

## 沒做的

- 全文大綱、文風、故事前提、世界觀、情節大綱、正文、修稿、刪修飾本來就不是 JSON，沒動。
- **二期沒調真實模型**：測試全是假模型。各步的格式模型守不守、轉寫會不會動名字與引文、長段（角色卡的節、設定條目的正文）會不會被轉寫截掉一截（「出自原文」只查有沒有改字，不查漏沒漏），都要拿真實模型試過才知道。
- 試跑：一期用 gemini-3-flash-lite 跑過細綱（見上）；二期各步待跑。
