## 1. 三期首跑的五處

### 1.1 續寫越過章末鉤子（⚑）

**現象**：三章都是第一次呼叫正常收尾、只寫到 55–77%（1960 / 1665 / 2323 字，目標 3000）。第一次呼叫已經按執行卡收在鉤子上了，於是不到八成的續寫只能接在鉤子**後面**：第 3 章在「守門人家族的標誌」之後又寫了 869 字，最後讓第 4 章才登場的沈秋出現在巷口（即 1.2）。

**根因**：`shouldContinue` 對「正常收尾但不到八成」和「被截斷」一視同仁，都往末尾追加。截斷時結尾停在半句，追加沒問題；正常收尾時結尾就是鉤子，追加必然越過它。

**改法**（⚑ 上游沒有這一步）：**收尾過早時，第一次續寫先回退到結尾那一場之前**。
- 只在這種情況觸發：上一輪正常收尾（不是截斷、也不是 `other`），不到八成，上一輪新寫的那一段至少有兩段。
- 從哪兒切（`rewindPoint`）：在最後 40% 的段落裡，三段一窗，用 bigram 覆蓋率找跟章末鉤子最像的那一窗（≥ 0.35），從視窗第一段開始切；找不到就切掉最後約 25%（最多 600 字）。至少留一半、至少切一段。三段一窗是真實正文定的：一章四五十段、一段六十來字，鉤子那一幕拆在兩三段裡，單段的覆蓋率最高也只有 0.3 上下。
- 切掉的那一截丟棄，氣泡退回到切點（`io.reset`），續寫那一輪的契約換成「收尾那一段已經拿掉了：把本章還沒寫足的事件寫足，最後重新落到章末鉤子上；不要越過鉤子」，「還差多少字」按切完之後算。
- 可以回退幾次（試跑實測：這個模型一次只寫一千字上下，一章要走兩三輪），但**每次只在上一輪新寫的那一段裡切**，前幾輪接受了的不再動。回退那一輪淨多的不到 300 字，或者上一輪那一段短得沒法切：**不再往鉤子後面續**，停下說明原因，按未寫夠處理。被截斷照舊追加。
- Responses 協議的 `response.completed` 從前不報收尾原因，這條路上 `stop` 永遠是缺席，回退一次都不會觸發：改成報 `end`（試跑時發現）。
- 「接著寫」（`continue`）只在**這一次新寫的**那部分裡切，磁碟上已有的一個字不動。
- 說明裡寫清切了幾段、多少字（第 2 條）。

### 1.2 結尾提前寫進後面幾章的人（⚑）

**現象**：第 3 章續寫的結尾讓沈秋出場，他按細綱第 4 章才登場。後五章細綱（`plotAhead`）一直在裝配裡，契約裡也有「不提前寫後續章節」，但這一條太籠統。

**改法**：
- **執行卡點名**：後五章細綱裡排了、本章與前面各章細綱都沒排的人，執行卡裡列一行「本章不出場：沈秋（第 4 章才登場）」。模型對點名的清單比對一句原則聽話得多。純函式 `notYetOnStage`（`model/manuscriptCheck.ts`）。
- **本章細綱自己提到了的人不算**（試跑時發現）：第 3 章的鉤子就是「老客提醒他祠堂裡的陳老爺正在搜尋」，陳老爺是第 4 章才登場的「鎮守人（陳道源）」的別名——點名「本章不出場」只會和細綱打架。名單由 `planWriting` 算一份（帶別名、名字括號裡外各一截），執行卡與寫完查共用。
- **寫完查一遍**：上面那份名單裡的人（名字與角色卡別名）在新寫的正文裡出現了，就記一條說明（「沈秋按細綱第 4 章才登場，本章已經寫到了他：『……』」），落盤卡片上看得見。⚑ **批次寫章遇到這種情況也停下**（黃 ❗），口徑同重演：批次沒人看著，下一章要從這個人「第一次露面」寫起，接不上。
- `model/manuscriptCheck.ts` 要用 continuity.ts 的 bigram，所以不是零 import 的；它不進前端打包。

### 1.3 「彷彿」超標

**現象**：規則是「『彷彿』『猶如』『宛如』全章合計不超過 3 次」，三章正文裡光「彷彿」就有 9 處，第 3 章一章 4 處。這條規則只寫在系統提示中間；續寫那一輪也不知道前面已經用了幾次。

**改法**：
- 執行卡末尾重列一條「比喻詞上限」（模型對末尾最敏感，GD:657 同一個道理）。
- 續寫那一輪的契約寫明已經用了幾次、還能用幾次，用滿了就是「一次也不許再用」。
- 寫完數一遍，超了記一條說明。不攔、不自動改：這是文筆問題，作者手改或修稿。

### 1.4 已落盤的產物隨歷史再灌一遍

**現象**：同一個會話跟著主按鈕一路走，配置 JSON、前提、角色圖譜、大綱、細綱批次、前幾章正文都還留在歷史對話裡，寫第 3 章時又整份裝進去一遍。可它們早就落盤了，有專門的層按磁碟帶（設定、大綱切片、本章細綱、上一章結尾、前文全文、證據），作者落盤之後要是手改過，歷史裡的還是改之前那一版。

**改法**：`history` 層跳過已經寫入的那一輪（`acceptedTo`）**以及發起它的那條使用者訊息**，明細裡記「已寫入 xxx，以磁碟上那一份為準」（第 2 條：跳過要看得見）。沒寫入的（作者點了不採納）照舊帶，那份只在歷史裡有。agent 那條路本來就傳空歷史（第 24 條），不受影響。

### 1.5 和年代不符的現代術語

**現象**：民國背景的書，角色圖譜裡模型寫了「嚴重的 PTSD」，接著進了第 2 章細綱和第 3 章正文。

**改法**：
- 架構、大綱、細綱三個階段的系統提示「通用要求」，加上正文的硬性要求，都加一條：用詞要貼合故事的年代和世界觀；古代、民國、架空世界不用現代醫學、心理學、網路和科技術語（舉 PTSD、抑鬱症、多巴胺、CPU 為例），換成那個年代的人會說的話。
- 正文寫完查一遍有沒有連續兩個及以上大寫拉丁字母的縮寫，有就記一條說明（「正文裡有英文縮寫：PTSD」）。只提示：都市、科幻題材裡 CEO、AI 是正常的。

## 2. 預檢永久豁免（⚑ 與上游不同）

上游（`shared/consistency-preflight.ts`）的豁免按「事實」記在庫裡、全書生效，還能撤銷。這裡：
- **按章記，記在這一章細綱的 frontmatter 裡**：`preflightOk: ["沈秋：回憶裡的一場"]`，一行是「名字：理由」。第 17 條要求作者的決定只能存在 Markdown 裡，所以不進 SQLite。按章而不是全書：第 8 章是回憶，不代表第 12 章再排他也是回憶；寧可多問一次（五期 §8 的口徑）。
- 細綱 frontmatter 不進內容指紋（`plotContentHash` 只雜湊三個小節），所以記下豁免不會讓正文變成「細綱改過」。**重新生成這一章的細綱會丟掉它**：重排過的出場是新的安排，要再問一次（`renderPlotFile` 本來就只寫認識的欄位，這裡寫明這是刻意的）。作者要撤銷，刪掉那一行就行。
- `findPreflightRisks` 收 `exempt`：豁免過的人不算風險，單獨返回（`exempted`），寫章卡片的說明裡列出「按你記下的安排放行：沈秋（回憶裡的一場）」。
- **對話頁的預檢卡**加一個理由輸入框和第三顆按鈕「記為刻意安排，照寫」（填了理由才能點）。閘門協議加 `remember { label, placeholder }`，`gateResult` 加 `remember` 帶回理由。點了就把這幾個人連同理由寫進細綱，然後照寫。
- **批次**：開跑前與中途的預檢都認豁免。確認框是宿主的模態框，放不了輸入框，所以批次這邊只有「僅本次忽略」，說明裡告訴作者怎麼永久放行。

## 3. 報告卡新增 / 編輯條目（⚑ 取捨）

移植上游 `ReviewReport.tsx` 的編輯模式，有幾處不同：
- 報告卡加一顆「編輯」：問題條目可以改分類、嚴重度（嚴重 / 建議）、說明、引文；「新增問題」加一條作者自己寫的（`origin: 'author'`，分類預設「作者補充」，預設勾上）。作者加的可以刪；**模型給的不能刪**，不想修就不勾（上游同樣只給「忽略」）。目標核對那幾項來自細綱，不能編輯。
- 引文對作者加的條目是可選的；給了就按歸一化在正文裡找，找不到就清掉並說明。作者改過引文的模型條目同樣處理。修稿清單裡沒有引文的那一條不寫「相關原文」。
- 「儲存」時把整張問題表發給後端（`editReview { turnId, issues }`）。後端用純函式 `applyReviewEdits` 校驗、截斷，再寫回那一輪的報告與氣泡正文（`renderReport`），落盤並推回。說明為空的條目丟棄，並告訴作者。
- 編輯過的模型條目標「已改」；修稿清單裡作者加的標「作者補充」。

## 4. 批次「寫完即審稿」（⚑ 報告放哪、順序、停不停）

- W9 批次寫章彈窗加一項「寫完即審稿」（開 / 關），跟「只寫正文 / 寫完即定稿」分開選。`planWriteBatch` 收 `review`，每章多算一份 `REVIEW_CALLS`。
- **順序：寫 → 審 → 定稿**（⚑）。審稿對照的是「截至上一章」的角色狀態與連續性事實；先定稿的話，本章剛寫下的事會被當成「前文」拿來對照它自己。
- **報告放進一個新會話**（⚑）：「批次審稿 · 第 a–b 章」，一章一輪（使用者輪是 `/审稿`，助手輪是報告卡）。每審完一章就落盤一次，取消了也留著審過的那幾章。作者開啟這個會話，在報告卡上逐章勾選、修稿，走的是對話頁同一條路（修稿用對話頁選定的模型、當場問、覆蓋前對比）。完成提示的按鈕換成「開啟審稿報告」（`TaskNotice.open` 加 `sessionId`）。
- **審出問題不停**（⚑）：審稿只是意見，要人勾了才會修稿；批次停下來也沒人勾。完成提示裡說清「第 4 章 2 嚴重，第 5 章 1 建議」。**審稿失敗也不停**：後面幾章不靠這份報告往下寫。失敗記成那個會話裡的一輪報錯，完成提示裡提一句。
- 模型：新增分檔任務 `review`（審稿，預設均衡檔），不帶思考深度（第 26 條）。

## 5. 真實模型試跑

`~/workspace/project-scripts/novelforge-phase5-live/run.js`：沿用三期指令碼的做法，用同一個腦洞、同一個模型（`gemini-3-flash-lite`），從空工程跟著主按鈕走到寫完前 3 章（單步，各章定稿），然後審第 2 章、按預設勾選修稿，修稿走合併檢視交回新版。匯出到 `~/workspace/project-reports/novelForge-五期补遗真实模型试跑-<日期>.md`。

報告要對照三期首跑逐項寫清：
- 每章字數、續寫了幾輪、有沒有回退、結尾是不是落在鉤子上；
- 有沒有後面幾章的人提前登場；
- 每章「彷彿 / 猶如 / 宛如」各幾次；
- 歷史層跳過了哪幾輪；
- 設定和正文裡還有沒有 PTSD 這類詞；
- 審稿報告（丟了幾條、目標核對）、修稿前後的 diff 處數。

預計 20–25 次呼叫。
